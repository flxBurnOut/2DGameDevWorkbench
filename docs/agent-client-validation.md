# Agent 客户端验收

本页列出改动 MCP、指导文档或预览跟随后的回归场景（日常制作无需执行）。除明确说明的本地导出示例外，自然语言对话场景默认以“只讨论方案，不生成”为前提，使用隔离目录和模拟提供方。

## 对话与任务范围

| 输入场景 | 预期行为 |
| --- | --- |
| “只讨论方案：做个角色动画。” | 只问角色来源、动作等真实缺项（优先用宿主提问工具），不建空任务 |
| “只讨论方案：用已有赛博战士做行走，你决定其他设置。” | 查真实对象 ID，沿用默认 preset 与 1 个候选，不重复追问常规参数 |
| “只讨论方案：做一个可开关的箱子，目前没有任何素材。” | 说明物品原图（PixelLab 生成/导入/PixelProp 转换）、静态状态槽、交互物动画状态链与写回流程；只讨论不生成 |
| “箱子只有 GPT Image 图，做成开关动画。”（未委托确认） | 本地执行 `convert-prop`（不计费），用 `workbench_present` 展示 `compare.png`，等用户确认后再移送与规划 |
| “……你帮我检查，合适就继续。”（已委托确认） | 看图核对视角、初态、部件与透明背景后带确认说明移送；后续规划与生成仍在原授权额度内进行 |
| “只讨论方案：把已有动画接到这个物件上。” | 说明从资产库导入动画并保留帧序、FPS 与来源，不重复追问已有目标 |
| “只讨论方案：做个宝箱。” | 区分静态外观图与可交互物件，必要时澄清，不默认等同拾取物 |
| “做一个按键开关的门，只要逻辑包，通用 Godot。” | 选 `toggle` 与 `generic` 直接本地导出，不要求 PixelLab Key |
| 提问卡片取消或不作答 | 不提交依赖答案的任务，不将推荐项当成用户已选 |
| 连续回答“已有角色”“做行走” | 记住已答内容，只补其余缺项，不重发整套问卷 |
| 委托 Agent 检查并选用动画 | Agent 查看完整有序序列后继续采用或导出，不凭首帧或纯报告替代 |
| 已有目标 Godot 工程接入单个动作 | 保留目标工程的其他动画、控制器行为与既有用户改动 |
| 用户明确要求在网页中操作 | 使用宿主实际可用能力与现有页面流程，不虚构不存在的 MCP 工具 |

## WorkBuddy 首次连接与开页

协议细则见[预览协议](agent-preview-follow.md)，验收步骤：

1. 在 WorkBuddy 重连 `2d-game-workbench`，确认工具挂载完成（含 `workbench_start_frontend` 与文档工具），新建对话。
2. 仅连上 MCP 不发消息时，确认不会自动开页。
3. 发送“看看工作台现在有哪些功能”：预期自动打开工作台首页并正常回答；若先停掉本地开发服务做冷启动，应自动拉起前端与 Bridge（超 60 秒则报告仍在启动与日志路径）。
4. 再发送“列出已有角色”：复用同一预览页，不重复开页；手动关闭后再发消息不强行重开。
5. 未确认本会话预览前直接 `run`：返回 `preview_required` 且任务目录不新增记录；连接页面后以相同参数成功提交。另验证双会话隔离及 `previewPolicy` 例外行为。

## 页面跟随与内容一致性

1. 首页打开状态下发送“展示我已有的一个交互物，不要生成”：在同一标签跳转该作品详情。
2. 发送“把它的提示文字改成指定内容并保存，让我看到过程”：保存后定位到新版本，保留工程与物件 ID，界面提示“已保存”而非“已导出”。
3. 查看 3 候选动画的第 2 个：URL 与播放器均锁定候选 2；连续查询状态不刷新、不跳回首页。
4. 点击“暂停跟随”后请求查看另一作品：保持原页并提示已暂停；点击“继续”后再跳转。
5. 修改草稿期间切换作品：先保存草稿；模拟保存失败时停留在原页并提示，恢复后继续。
6. 关闭预览后让 Agent 查进度：不自行重开窗口。同时核对页面显示的实际名称、图片与内容是否与保存版本一致。

## 自动化回归命令

- **指导与接入**：`npm run test:mcp`、`npm run test:http`、文档链接核查；
- **预览与跟随**：`npm run test:preview-follow`、`npm run test:presentation`；
- **生产调用链（fixture）**：`npm run test:agent-acceptance`。

真实 WorkBuddy 宿主的工具挂载与 `present_files` 调用需在 WorkBuddy 实际客户端内执行验证并记录环境。
