# 共享图片局部调整

Web 可按 `mediaProtocol: 1` 先取版本元数据，再从 `GET /api/workbench/image-edit/media` 读取绑定会话、版本与编码 SHA-256 的预览和 RGBA8 数据。客户端校验尺寸、原图哈希和像素哈希后缓存。旧服务可继续用 `includePixels` 返回内嵌像素。

本分支支持交互物静态槽、独立图片任务与动画帧的局部调整。共用工作区提供本地编辑、按源尺寸开放的显式 AI 候选、冻结请求、精确会话深链与宿主保存协调。静态图片可采用并单图恢复；动画帧先保存备选，再完整播放决定采用。真实模型品质和引擎验收按具体素材分别记录。

## 共用本地工作区（7B）

新增「部件与属性计划 · 试验」：支持可修正的属性策略、授权／目标／影响／保护区、干净局部参考，以及确定性简单换色。操作与保证边界见 [属性计划与换色试验](../workbench/guides/image-attribute-editing.md)。这是实验入口，尚未完成正式画质评测。

| 从哪里进入 | 修改范围 |
| --- | --- |
| 交互物编辑器点“局部调整默认图片” | 当前定义的默认静态图片；状态和序列条目也有独立静态图片入口 |
| 独立图片任务预览或资产库 `image:` 素材详情，点“局部调整图片” | 保存新图片变体，原任务和原素材不覆盖；之后仍需明确采用到工程 |
| 动画检查页点“局部调整当前帧” | 确定性修改当前可编辑帧，保存为动画备选后返回完整播放对比；锁定边界和状态图保持保护 |

交互物入口先等待当前工程持久保存到 Bridge；保存期间又有修改时继续保存，直到取得确切源版本。失败或冲突会保留本机草稿，不打开旧版本图片。工作区打开后，宿主暂停交叉编辑和离页，并使用源版本和当前槽位绑定检查写入。

左栏按用途分组：选区（矩形、涂选、连通，新建／添加／减去，选整图、清空、可见像素、可见包围框）、绘制（画笔、橡皮、填充、移动、取色，仅本地精修显示）和视图（平移），下方只显示当前工具的参数。填充直接在画布上点击起点，用画笔颜色填充相连同色区域；移动在矩形选区内拖动，松开后移动其中像素，选区随之移动。右栏按“修改范围 → 对范围执行（换色、清理透明噪点、擦除、从旧版本恢复）”排列。滚轮缩放、空格或中键拖动只改变视图。撤销与重做是一条顺序：Ctrl/Cmd+Z 撤销最近一次笔划或选区变化，Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y 重做；Ctrl/Cmd+A 选整图，Ctrl/Cmd+D 清空选区，Esc 关闭窗口（有未保存内容时先确认）。笔划只写入蓝色修改范围；落在范围外的笔划不写入，并在状态栏说明原因。执行任何其他操作或应用时，未保存笔划会先自动存为一个新版本；也可点“保存为新版本”。各版本和本地操作使用本地 `process-image` 任务，不调用模型、不需要 Key；静态图片处理不需要 Python，动画帧读取、锁检查与备选保存需要 SpritePipeline 服务。

底部是版本时间线：“打开时的图片”和“版本 N · 操作”，每项注明“基于”哪个版本，并标出“工作中”（下一步修改的基准）和“已应用”（最近应用到目标的版本）。点缩略图只切换查看，不更换工作版本，不清空未保存笔划或选区；查看其他版本时画布上方显示“正在查看版本 N（只读）”，配“回到工作版本”和“从这里继续改”，右栏顶部说明为何暂停编辑。“从这里继续改”才更换工作版本；未保存笔划须先保存或舍弃，选区及其撤销历史保留，包括空选区。上方“修改前／修改后／差异高亮”相对所看版本的本步基准比较四个 RGBA 通道，包含不可见 RGB 变化；对比只是视图，在对比视图里开始编辑会自动回到“修改后”。所有被暂停的操作都在原位置写明原因。应用按钮作用于当前查看的版本，名称随目标变化：交互物为“应用到交互物”，独立图片任务为“另存为新素材”，动画帧为“保存为动画备选”；在工作版本上有未保存笔划时，应用会先把笔划存为新版本再应用它。已应用的版本不能重复应用。采用成功后宿主读取回执中的准确服务端版本，并更新本机工程和自动保存基线；遇到本机变化、较新远端版本或读取失败时不以旧草稿覆盖已采用结果。应答不明时重试原命令，不能据此另建提交。

采用后旧会话保留候选与“恢复打开时的图片”入口；继续精修须点“基于当前图片继续精修”，使用最新图片建立新会话。历史会话需在标题栏“更多”菜单中显式选择，不把同名旧源自动当成当前源；“刷新目标状态”也在该菜单里。历史来源不满足当前写入 guard 时只能查看；锁定、来源变化或宿主保存冲突不授权重绑图片。

未保存笔划另有当前浏览器 origin 的 IndexedDB 恢复副本，约 600 ms 后保存；只保存补丁和基准身份，不是服务端候选，也不跨浏览器同步。单份草稿上限 2 MiB、最多 12 份，笔划提交仍受 512 KiB 补丁限制；存储不可用、超过限制或来不及落盘时不能承诺恢复。恢复前核对基准像素哈希。“舍弃笔划并关闭”删除当前笔划副本，已保存候选和采用记录仍保留。重要修改应先保存为候选，不能用本机草稿代替持久保存。

## AI 局部修改（7C）

在同一工作区切换到“AI 局部修改”。打开时按目标决定模式：图片满足 AI 尺寸要求时打开 AI 局部修改，初始为空选区和矩形工具；动画帧和不满足要求的图片（如 128×128 像素图）打开本地精修，初始选中整图，AI 标签注明“此图不可用”，右栏给出原因和“改用本地精修”。从 AI 切到本地精修且尚未选择范围时自动选整图。矩形和涂选共用“新建／添加／减去”，Shift 临时添加，Alt 临时减去；只修改可编辑蒙版，不改变图片像素。矩形可拖动内部移动、拖动角点缩放；空格或中键平移画布。选区工具和平移在两种模式下都可用；画笔、橡皮、填充、移动和取色只在本地精修显示，不会因为点工具而悄悄切换模式。切换模式保留选区、未保存笔划和 AI 描述。命名区域收在“修改范围”下单独管理。选区使用淡蓝色和边界显示，原图不再被黑色保护遮罩覆盖；AI 结果返回后默认隐藏修改范围，便于检查画面，画布左上角保留“修改范围已隐藏”提示，可一键显示。本地操作完成后范围保持可见。空范围不能提交；整图范围会明确显示。增减笔刷通过 `mask-runs` 的有序、不重叠 `{startPixel,length}` spans 保存硬边界，最多 65,536 段，不是软边蒙版或自动语义分割。

填写最多 12,000 字修改描述，可选最多 8 张 PNG/JPEG/WebP 参考图；网页单张上限 30 MiB、参考合计上限 32 MiB，服务端仍检查源图、蒙版与参考总计 80 MiB。只上传明确选择的参考。“生成 AI 候选（调用模型）”直接显示在描述下方；有未保存像素笔划时，提交前会先把它们存为新版本，AI 再基于该版本生成。部件与属性计划、独立成品复核、逐项检查记录和“修正合成区”收进 AI 模式下默认关闭的“试验工具”，部件计划不再随描述自动展开。本地模式不需要 Key；AI 使用既有 GPT Image 2.6 设置并可能消耗外部额度，不会因本地操作失败自动启动。

请求固定所选 `baseCandidateVersion`、描述、参考真实字节、源版本与区域；参考与配方写入不可变快照，原文件之后修改不改变在途请求。任务身份在 adapter 发出请求前持久保存。返回 running 后只查询原 task / editId；断连、Bridge 重启、超时或未知提交都不会自动重发模型。重试同一动作须保留 commandId 和原载荷；配置补齐也不会续发旧任务。关闭窗口不保证撤销已送出的请求。尚未提交的 AI 描述、参考选择与未保存选区仅属当前页面，关闭前提示不等于已经持久保存。

AI 不改变源尺寸：当前要求宽高均为 16 的倍数、655,360–8,294,400 像素、最长边不超过 3840、宽高比在 1:3–3:1 内。不符合尺寸的小像素图仍可本地精修，不会自动放大。`inspect` 的 `aiEdit` 与 `operationConstraints` 返回实际可用性和原因。AI 可选择保留原图透明度：网页默认开启；API 使用 `constraints.preserveAlpha=true`，未提供时保持原有默认 false。这里的“原图”指本次 `baseCandidateVersion` 的基准图片，连续编辑不会强行恢复会话最初的 Alpha。结果返回后从基准逐像素复制全部 Alpha，跳过低 Alpha 清理，并对最终 PNG 校验 Alpha 哈希；不会改变尺寸或额外调用模型。关闭选项才允许模型改变选区内透明度。该选项不保证颜色、纹理、内部结构或接缝。

候选先经过本地合成：选区外从本步基准逐字节复制解码 sRGB/RGBA8，包含隐藏 RGB，再核对编码后结果；选区内轮廓、接缝、颜色和碰撞适配仍需查看。证据分别报告本步相对基准的变化、保护区变化和累计相对会话原图的变化；累计区域外变化可能来自此前已完成的编辑，不能混为本步越界。原始服务响应、可采用图片、哈希、模型与处理证据分别保留。完成候选不会自动采用或通过真实画质验收。

任务与 `presentation` 保留精确 editId / candidateVersion；`workbench_present({editId,candidateVersion})` 及 `?imageEdit=...&imageCandidate=...` 打开原会话与所选候选，不以最新候选替代指定版本。在途候选完成时可继续读取它，已有未保存笔划不会被轮询覆盖。来源或宿主 guard 不可写时只读历史，不隐式建立新会话、改绑默认图或采用。状态槽也使用同一精确会话 / 候选入口；外部绑定变化导致当前 guard 失效时只读历史。本会话已知采用绑定的恢复仍按下文规则校验。

## 精确选择与主流程

默认使用四个高层工具，另有会话读取、部件计划与候选复核工具。完整字段由 [共享契约](../lib/workbench/image-edit-contract.mjs) 定义；[manifest](../workbench/manifest.json) 登记工具、目录和阶段范围。

| 工具 | 用途 |
| --- | --- |
| `workbench_inspect_image_target` | 按范围发现已保存目标，或读取精确源图、版本、PNG/源编码哈希、RGBA 哈希和可用操作 |
| `workbench_resolve_image_region` | 对精确源版本解析几何、Alpha、连通颜色或已有命名区域；`saveAs` 配合 `commandId` 显式保存名称 |
| `workbench_edit_image_region` | 以解析后的区域创建候选；本地操作使用 `image-assets/process-image`，显式 `ai-edit` 使用 `image-assets/edit-image`，保留冻结配方与来源 |
| `workbench_apply_image_candidate` | 重新检查版本、源哈希、锁和槽位身份，采用静态图片或保存动画备选 |
| `workbench_get_image_edit` | 读取候选历史、任务状态和采用记录；不重新提交生成 |

目标是 `interactable`（文档、物件及静态外观槽）、`image-task`（已完成图片任务）或 `motion-frame`（workId、workRevision、candidateIndex、可选 stageIndex、frameIndex）。动画帧发现必须限定作品、版本与候选；省略 stageIndex 表示完整候选。浏览器中尚未保存的草稿不在发现范围内。多个匹配项需要选择具体目标，不自动采用第一项。

修改调用必须提供 `expectedRevision`、`expectedSha256` 和稳定的 `commandId`。同 ID、同载荷返回原任务或采用回执；同 ID、不同载荷返回冲突。已有编辑会话还要求 `expectedEditRevision` 与 `baseCandidateVersion`；原图基准使用 `source`。产生候选和采用候选是两个独立步骤。

CLI 使用同一服务，例如：

```text
npm run workbench -- agent image-inspect --input work/inspect-image.json --json
npm run workbench -- agent image-resolve --input work/resolve-image.json --json
npm run workbench -- agent image-edit --input work/edit-image.json --json
npm run workbench -- agent image-apply --input work/apply-image.json --json
npm run workbench -- agent image-session-get --input work/read-edit.json --json
```

Bridge 接口为 `POST /v1/agent/image-inspect|image-resolve|image-edit|image-apply|image-session-create|image-session-get`；网页代理使用 `/api/workbench/image-edit/<后缀>`。MCP、CLI、网页连到同一个 canonical Bridge。会刷新候选的读取也在 Bridge 中执行；不可用时不退回客户端文件直写。和共享文档一样，不支持多个独立 Bridge 同时写同一数据目录。

## 像素、区域与操作

保留实际 PNG/JPEG/WebP 源文件。`sha256` 表示源编码字节，`rgbaSha256` 表示解码后的 straight-alpha、sRGB、RGBA8；两者不能互换。`includePixels` 显式返回 `rgbaBase64`、字节长度和尺寸。前端显示可经过 Canvas，权威像素由服务返回的 RGBA 缓冲提供，避免浏览器重编码丢掉 Alpha=0 像素中的 RGB。历史列表不附带每张图的像素。

区域支持整图、整数矩形、像素中心判定的多边形、`mask-runs` 硬边蒙版、Alpha 包围矩形、真实 Alpha 选择和四邻接连通颜色。Alpha 包围矩形不是语义分割或主体精确轮廓。连通颜色以种子 RGBA 为基准逐通道比较，包括透明像素中的 RGB。空区域、越界或不支持的参数会拒绝。命名区域绑定目标、源版本及哈希；源改变后需要重新检查并解析。

本地操作包括 Alpha 噪点清理、精确 RGB 替色、连通填充、擦除、矩形移动、从同会话原图/旧候选取样恢复，以及手工像素补丁。首版移动只支持完整矩形且不能越界；有效区域是移动前后矩形的并集。输出尺寸保持不变，保护区的四个通道逐字节一致。`preserveAlpha` 为真时，任何 Alpha 变化均拒绝。

像素补丁使用排序、无重叠的 `spans`：`startPixel`、`beforeRgbaBase64`、`afterRgbaBase64`，并携带基准 `baseRgbaSha256`。先检查全部 before、边界和区域，再原子应用。before+after 解码总量最多 512 KiB；大面积操作用填充、移动等声明式操作。大配方存不可变文件，候选历史只保留摘要和引用，命令账本只保留任务/候选身份。

核心通过[薄适配器](../features/image-edit/core.mjs)直接复用角色画布的 `pixel_editor_core.js`，不依赖 DOM、Python 或 Key。大图填充使用有界 typed-array 队列，不构建每像素 JavaScript 历史对象。最长边 3840、最多 8,294,400 像素；局部编辑不会为了模型尺寸自动放大素材。

本地 `process-image` 允许现有不透明物件以及明确擦除后得到的空图。AI 编辑沿用现有源的透明 / 不透明策略，不强迫已有不透明外观变成透明物品；新透明物品生成仍检查真实透明通道与可见内容。本地候选默认关闭额外 Alpha 清理；AI 开启透明度保持时跳过清理，包括原有 Alpha=1 像素；关闭时沿用原透明处理策略。保护区始终保持全部 RGBA。

## 定点采用与恢复边界

以下单图采用与恢复规则适用于静态图片目标。`motion-frame` 采用会把真实选区与 PNG 保存为 `local_pixels_v1` 动画备选，回执为 `saved_variant`，动画此时尚未变更。须检查完整播放和相邻衔接，再通过动画备选的裁决操作采用；锁定帧与来源版本继续校验。多帧替色、完整候选派生与历史保护见[确定性帧编辑](motion-adjustments.md#确定性帧编辑)。

交互物采用保留工程和物件身份、旧素材、行为及其他槽位。默认图采用清空默认 idle/focus 动画选择；状态图采用只修改该槽位。状态槽绑定源文档版本及 fingerprint，序列重排不能把旧结果写到新条目。默认图另外用定义、assetId 和图片哈希识别绑定；采用 / 恢复时仍校验当前文档版本，位置、尺寸等无关变更不会被旧外观快照覆盖。配置了状态动画或默认 idle 动画的状态槽只读，不以预览此刻是否播放为依据。

`restore-region` 从同源版本会话的原图或完成候选取样，只恢复选区并生成待采用候选。“恢复会话原图”则把会话原始像素经本地处理保存为新 PNG 候选，再采用到同一目标；不是回滚整份工程，也不保证恢复原 JPEG/WebP 的编码字节。API 使用 `image-apply` / `workbench_apply_image_candidate` 的 `candidateVersion="source"`，或指定历史完成候选；均须当前目标 revision、源哈希和新 commandId。服务端只接受会话原绑定或本会话曾采用的已知图片绑定；外部替换图片、锁定或槽位变化时拒绝，保留历史供检查。

交互物恢复保留行为、范围、碰撞、其他槽位及当前无关外观参数，默认静态图采用仍会停用默认 idle/focus 动画选择。独立任务源始终不可变，采用或恢复只得到新素材变体。图片采用不更新已经交付到游戏的资源。

## 状态与证据

会话、命名区域、配方、命令账本和不可变快照在 `workspace.imageEditDirectory`（默认 `work/image-edits`）；候选仍使用标准任务和输出目录。`running`、`awaiting_configuration`、`attention_required` 都不是可采用的完成结果。任务身份在 adapter 执行前写入持久账本；中断且身份未知时报告需要检查，不另建任务重试。临时租约失效的派生诊断仍允许刷新迟到的完成结果。

## 静态状态槽

交互物状态和序列入口传入完整 `documentId + definitionId + slot + index`。状态继承默认图时，采用只创建该状态自己的图片绑定；默认图和其他条目保留。序列重排、槽位变动、锁变化或版本冲突会拒绝旧写入，候选和未保存笔划留在原会话。

采用在同一文档版本事务中新增图片并更新指定槽位，保留其他源素材。原图恢复仍是新版本，只有原绑定或本会话已采用的绑定可以恢复；相同像素不意味着来源绑定相同。

## 透明度保持与界面回归（2026-10-24 修订）

透明度保持在本地处理阶段执行，保留源 PNG、模型原始输出和派生 PNG 的独立身份。`processing-report.json` 中的 `alphaPreservation` 给出 `expectedAlphaSha256`、`actualAlphaSha256` 和 `changedAlphaPixels`；最后一项必须为 0。`alphaCleanup.threshold=0` 与 `skippedReason=preserve-alpha` 表明本次没有清理原有低 Alpha 边缘。透明度开关也属于冻结请求，同 commandId 改变开关会被拒绝，不会重发模型。

已保存候选与恢复原图的上下文预览直接使用经过哈希校验的编码图片，避免等待 Canvas.toBlob；未保存笔划的预览按控制器、版本和显示模式失效，迟到回调不能覆盖当前画面。建立新会话后地址栏写入新 editId 与 source；切换候选或跟随在途候选时写入确切版本。更新保留宿主 document/asset 参数、页面锚点和路由状态，不新增浏览历史；关闭工作区清除图片参数。

回归命令：`npm run test:image-assets`、`npm run test:image-edit`、`npm run test:editor-documents`。浏览器回归先运行 `node tests/image-edit/ui-server.mjs`，再在它打印的独立 origin 打开 `/tests/image-edit/workspace-regression.html`。页面使用真实 React 工作区和本地 API 桩，故意不完成 Canvas 编码，验证恢复画面、新会话链接、重开同会话、透明度默认值及关闭后的请求。结果页区分 fixture 请求和真实请求；全部请求均在本机拦截。该维护验证不需要新增付费调用，也不替代模型品质或 Godot 验收。

## 版本切换与结果检查（2026-10-28）

工作区使用有界的已验证版本缓存（96 MiB），重复查看不重新请求整张 RGBA；首次解码分块让出主线程。快速切换以最后一次选择为准，可取消纯读取等待，旧响应不能覆盖当前版本。取消查看不会取消模型任务。图片、选区及版本浏览状态分离；会话切换和关闭会取消尚未完成的预览读取。

窗口通过 Portal 挂到独立层级，避免宿主编辑器的表单样式改变工具栏、选框和画布布局。小图仍可选择本地精修；工具本身没有自动放大或改变源尺寸。

候选“已生成 · 待确认效果”仅表示任务完成，保护检查不代表视觉效果合格。前端对比本步基准提示大面积新增近黑像素；此提示不阻止用户有意改黑、不改变像素、不自动重试。请求仍发送独立 Alpha 蒙版和未绘入遮罩的基准图，并附加从蒙版解析出的像素边界与蒙版语义说明；模型品质需真实验证，不能仅以保护区变化为零判断成功。历史错误候选完整保留，不会在浏览时自动修复或重新计费。

浏览器回归另运行同一隔离服务器下的 `/tests/image-edit/workspace-interaction.html`：使用 1024×1024 图片检查连续切换、延迟响应、取消等待、只读查看的原因说明、按模式显示的工具、矩形移动缩放、加减选区、统一撤销、未保存笔划和纯净结果对比；请求全部由本地 fixture 拦截，不调用真实服务。

## 批量配色与摆放尺寸对照

局部修改描述可以逐行写明确的 `#RRGGBB → #RRGGBB` 配色，支持“将 #112233 替换为 #445566”。另支持明确的“擦除选区像素”和“移动选区(2,0)”；移动仍需完整矩形和合法目的地。整段为配色表且没有参考图时，提交按钮显示本地候选。其他外观描述保留为明确的 AI 提交。可在本地精修中添加颜色对；单色复用 replace-color，多色使用 palette-map 的 pairs 数组（1–64 个 {from,to}，原色不分大小写且不能重复）。每次从本步基准一次映射，保留每个 Alpha 字节。Agent 可在单目标 image-inspect 的 metadata 请求中传 intent 预览建议操作，再显式提交。已明确指定的 ai-edit 沿用其原有调用语义。

完成候选可打开“按摆放尺寸比较”。面板按所选预览宽度比较单图原色，并明确显示比较尺度。单幅超过 320 像素的部分取编辑区附近的同位置窗口，不缩小比例。游戏中的遮挡、着色及相机效果另外查看实际游戏。

workbench_get_image_edit 传 editId、确切的已完成 candidateVersion 和 comparison:{}；独立素材可传 comparison:{previewWidth:128}。MCP 返回本步基准、所选候选两张 PNG，HTTP/CLI 的 edit.comparison 含 beforePng/afterPng、同一采样窗口、目标版本和两张输入的哈希。普通历史读取不生成对照图。小目标裁图参考仅作为独立实验输入，没有默认启用。
