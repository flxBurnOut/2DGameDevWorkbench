# 内部素材导入与联用

各编辑器复用资产库中的真实素材，不需要先下载再上传。导入不会生成图片、导出新引擎包或创建生产任务；采用后按目标编辑器保存草稿。场景与交互物增加了共享版本，网页和 Agent 可继续同一工程；Agent 只能使用已声明的文档命令。地图生成、拼接和扩图仍在地图前端完成。

## 已接通的入口

| 来源 | 入口 | 结果 |
| --- | --- | --- |
| 资产库地图 | 导入地图编辑器 / 用于制作场景 | 优先恢复已有源包；只有原图时作为中心图，不虚构碰撞 |
| 资产库交互物 | 编辑交互物项目 / 加入场景 | 读取完整源项目，默认选中所选物件，保留行为、图片、声音、范围 |
| 资产库物品原图、角色原图、地图图片 | 用于交互物外观 | 绑定当前物件默认图片，保留其他状态图片和行为 |
| 资产库动画 | 用于交互物动画 | 导入选定候选的有序帧、FPS 和循环设置，作为当前物件默认动画 |
| 资产库完整场景 | 继续组装此场景 | 打开已保存的场景源包，保留地图、碰撞、物件和排列 |
| 场景组装：添加交互物 / 替换选中物件 | 从资产库导入 | 与本机项目、文件导入并列；替换仍需预览确认 |
| 场景组装：选择或替换地图 / 打开场景 | 从资产库导入 | 地图替换保留物件坐标，场景同身份冲突沿用原有确认流程 |
| 交互物编辑器 | 从资产库打开项目 / 从资产库导入原图或动画 | 打开完整项目，或把外观导入当前物件；不同版本保留独立项目 |
| 交互物编辑器 | 用于制作场景 | 保存并移送当前物件或勾选的物件，进入场景素材选择，不自动摆放 |
| 场景选中交互物 | 编辑此交互物 | 将当前素材副本交给交互物编辑器，保留原场景；修改后手动替换 |
| 场景地图信息 | 编辑地图源文件 | 把嵌入的地图源包送回地图编辑器；修改后回场景选择替换 |
| 地图编辑器 | 从资产库导入 / 用于制作场景 | 接收已有地图，再沿用直接制作场景入口 |
| 已完成 Image 2.6 图片任务 | 明确采用，或 `workbench_adopt_document_image` | 背景成为场景地图层并保留源 ZIP；透明 prop 绑定指定交互物默认图片 |
| 共享场景 / 交互物工程 | `?document=<id>` / 文档工具 | 打开同一稳定身份与服务端版本，保留来源快照 |
| 已保存地图源图 / 交互物静态槽 / 独立图片任务 | 高层图像 API / 7B 共用本地工作区 | 读取真实源图、生成本地候选，再明确采用到绑定目标；UI 已接地图单层、交互物默认图及独立图片 |

角色原图到序列帧的“用于制作序列帧”继续沿用既有 transfer 流程。原图只代表外观，不自动形成拾取、开关或剧情行为；动画导入也不会生成角色控制器。

## 默认辅助显示

新场景的网格、物件名称、碰撞与交互范围、玩家参考来源全部默认打开。旧场景第一次经过当前模型读取时迁移为全开；随后手动关闭会保存在场景中，刷新或重新打开不会强制再开。地图碰撞仍是辅助轮廓，开关不改变 Godot 碰撞导出。

## 物品原图分类与旧记录

资产分类依据生成任务的 subject=prop，而不是图片相似度或名称关键词。旧版本产物 result.json 可能不含 subject；仅当任务明确为 prop 且 PNG 尺寸、SHA-256 均验证通过时兼容读取。明确标为 character 的冲突记录仍拒绝。分类或导入不重写原始生成记录，不需重新生成。

更新后 Runtime Bridge 与 MCP 都需要加载新代码；旧 MCP 进程即使读取了新版 manifest，也可能仍使用旧分类模块。重启后台、重连 MCP 并刷新前端后生效。

## 保留与一致性

- 选择器支持名称搜索、分页、部分来源离线提示；只有可用的适用素材能导入。
- 内部读取校验所选资产身份、版本指纹和文件 SHA-256，发生变化或缺文件时失败，保留原编辑内容。
- 项目替换前保存现有草稿；同身份但不同内容的交互物项目作为独立导入版本，不覆盖原项目。场景替换沿用既有的另存与确认逻辑。
- 图片替换保留旧素材和各状态配置；默认静态外观采用后停止原默认动画。动画导入保留原片段，新增默认播放片段。
- 同一原图重复导入复用其素材身份；不同来源即使像素相同也不混淆来源。物品原图保留生成任务与内容哈希。
- 导入期间暂停跨页导航，避免异步结果写入另一物件。源工具与场景不会自动双向覆盖；采用或替换都由用户明确触发。
- 只有原图的地图没有碰撞区域。选择带完整源数据的地图/场景才可恢复已有碰撞；导入不会从像素猜测区域。

## 共享版本与明确采用

共享场景使用 scene.id，交互物使用 projectId；材料引用、定义、实例和资产 ID 继续沿用现有契约。保存会把图片、音效与地图源内嵌为不可变快照，来源之后修改不会自动影响已采用的版本。打开来源并编辑仍需在目标场景明确替换，不会双向同步内容。

`workbench_get_document` 返回可审阅内容和 revision。后续 apply/save/restore/adopt 必须带 expectedRevision 与 commandId；不同页面并发修改时只接受匹配当前版本的一次提交。相同命令重试返回原提交版本，currentRevision 另报告服务端当前版本；如两者不同，应重新读取当前工程。冲突不会丢弃前端本机草稿，加载共享版前可保存本机恢复副本。

图片生成结果与采用分开。`workbench_adopt_document_image` 只消费已完成 image-assets 任务，使用 sourceTaskId + sha256 重新读取原 PNG。背景采用建立地图源 ZIP 与单层图片，碰撞为空；透明 prop 采用需要指定已有 definitionId，保留行为与状态图片。采用是一条版本事务，不产生新的模型调用、导出或图片任务。不要用下载链接、预览图或缩略图替代原图证据。

场景后续可通过 `workbench_observe_document` 获得确切保存版本的 PNG 与几何标注；通过 validate/simulate 检查结构、媒体和交互事件。这些结果包含文档 revision / contentHash，不能代表浏览器未保存内容或 Godot 运行效果。`workbench_export_document` 则为明确 revision 生成新的场景源包和 Godot 包，并把该独立导出加入资产库；它不改变原共享工程。交互物仍沿用既有 export-godot 接口导出。

## 单张源图的局部调整（7A–7D）

高层图像 API 已支持目标发现、真实源图读取、区域解析、版本化本地候选和明确采用。地图目标定位到工程、图块和图片层；交互物目标定位到共享文档、定义和默认 / 切换状态 / 序列静态槽；独立 `image-assets` 任务以 taskId 定位。PNG、JPEG、WebP 保留真实源文件校验，同时以解码 sRGB/RGBA8 的 `rgbaSha256` 校验像素；预览图、Blob URL 和浏览器未同步草稿不作为来源。详见[图像局部编辑](image-editing.md)。

采用校验源 revision、文件哈希、目标锁与持久命令身份。地图从真实源 ZIP 只替换选中图片，其他源图字节、几何、区域和标记保持；图片类型锁继续覆盖所有图块。来源任务 / 候选哈希与原子采用 receipt 一起保存，应答丢失后的同命令重试返回原结果。旧预览失效，黑白参考修改不会自动重新提取物件。

交互物采用新增素材并只绑定明确静态槽，状态目标还绑定原共享 revision 与槽位指纹，不能因 index 重排而写到另一状态。只有默认图片采用停止默认待机 / 聚焦动画，状态专用采用保留默认与其他状态配置；行为、范围与碰撞不变。独立图片任务不覆盖原产物，采用得到新的 `image:<候选任务ID>` 变体。两条路径均不自动改写已有场景引用或引擎导出。

7A 的高层本地 API 已接入 7B 共用工作区：地图选中真实源图后点“局部调整本层”，交互物点“局部调整默认图片”，独立任务预览或 `image:` 资产详情点“局部调整图片”。地图与交互物打开前等待持久保存，采用后读取准确版本并协调自动保存基线。“恢复会话原图”只恢复这一张图片为新版本，不回滚工程的其他编辑；本机未保存笔划不等于服务端候选。

7C 已接显式 AI 局部候选，冻结基准、硬边蒙版、描述与参考字节。增减笔刷只改选区；精确会话 / 候选深链不选择同名新源，失效写入 guard 的历史只读。断连或重启后检查原任务，不自动重新提交。本批真实模型请求为 0，实际 UI 与真实模型品质验收分别记录；7D 已接指定状态槽及场景引用：选中实例使用独立派生素材，其他共享实例保留；地图快照仅在验证单源像素映射后开放，图层 PNG 与嵌入源 ZIP 同一事务保存。不能确认映射的派生或合成层只读，使用源地图入口继续。

场景层通过源包像素映射检查后可定点采用，并同步嵌入源包；无法映射时保持只读。修改上游源工程仍须在场景明确替换。既有 Image 2.6 独立编辑与整图采用继续沿用原流程；地图原图生产、拼接、区域绘制和扩图保持人工地图边界。完整限制见[图像局部编辑](image-editing.md)。

## 实现与验证

manifest.assetImports 声明导入用途、类型和目标编辑器。只读源文件接口 POST /api/workbench/assets/import 代理 /v1/assets/import，返回带身份清单与校验值的内部 ZIP；不调用生产 adapter。源文件总量上限 256 MB，导入控制复用各编辑器现有恢复、保存与替换流程。临时内部移送保存在当前浏览器的 IndexedDB，不属于后台任务。共享工程另保存在 workspace.documentDirectory，通过 `/api/workbench/documents` 代理至同一个 Bridge 写入；MCP / CLI 也转发给该 Bridge，不跨进程直接改文档文件。

运行 npm run test:asset-import、test:scene-composer、test:prop-art、test:editor-documents，再按开发矩阵运行地图、交互物、MCP、HTTP、资产、壳层和构建回归。使用隔离 fixture，不消耗真实模型额度。真实 WorkBuddy 行为及 Godot 游戏效果需单独验收。

交互物编辑器另有“保存到资产库”：使用现有 save-project 保存完整可编辑源项目，无需先导出 Godot。此按钮是明确的保存操作，会创建一次保存记录；单纯浏览、选择和导入仍不会创建任务。

## 与游戏项目交付的区别

内部导入继续在工作台编辑器之间复用可编辑源；[Godot 交付](godot-delivery.md)消费已导出的引擎包，写入用户选择的游戏并由外部 Agent 接入脚本。新 forge_maps 包可回导地图和场景编辑器，保持图层与碰撞。交付不解除地图制作的手动边界。

地图完整工程包（map-source.zip）可从资产库直接导入地图编辑器或场景组装器，保留图层与碰撞。点击“继续编辑地图”恢复原工程；“导入地图编辑器”创建副本。缩略图不作为交互物外观素材。地图图片与历史素材仍可作为中心图或外观使用。Godot 交付只使用已有导出包；完整工程尚未导出时，提供返回编辑器导出入口。

### 指定引用的局部调整（7D）

选择单个场景物件后可指定默认、切换状态或序列静态槽，采用只改变该实例；共享原素材的其他实例保留原图。选择地图图层时，只有能与嵌入源包建立单源像素映射的层可写，采用同步 PNG 和源 ZIP。多图块或派生层使用“编辑地图源文件”。状态或来源变化后旧会话只供检查，不能强制覆盖。完整范围和恢复规则见[图片局部编辑](image-editing.md)。
