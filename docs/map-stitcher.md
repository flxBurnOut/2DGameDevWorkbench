# 地图拼接编辑器

> 状态：当前维护。机器契约以 `workbench/manifest.json` 中的 `map-stitcher` 为准。

主入口为 `/tools/map-stitcher`，使用 FrameRonin / Pixelwork v2 数据模型。旧版保留在 `/tools/map-stitcher-legacy` 供回归和迁移。Unity 功能不在本工具范围内。

| 需求 | 使用路径 | 外部 API |
| --- | --- | --- |
| 在可视画布中布图、画区域、修图和导出 | Web 地图编辑器 | 仅原图生成和整体层扩图需要 |
| 从提示词生成地图中心原图 | Web `generate-origin` | 沿用地图生成设置 |
| 确定性拼接已有图片并生成状态/引擎包 | 本地适配器 `compose` | 不需要 |
| 填充透明模板的整体图层 | Web `generate-layer` | 需要已配置 Gemini、OpenAI Images 或混元 |

地图为人工编辑流程，不向 MCP Agent 开放自动执行。

## 开始编辑

完整工作台运行 `npm run dev`。只开发地图/交互物而不启动序列帧服务时，可运行名称沿用现状的 `npm run dev:interactable`；两者都会启动网页和 Runtime Bridge。访问 `http://localhost:3000/tools/map-stitcher`。

1. 点击“生成原图”，输入环境提示词并选择方形 / 横向 / 竖向画幅，生成后先预览，再点“用作中心图”。也可用“新建 / 导入”将第一张图片作为中心地图，按顺序填入首圈卡片。PNG、JPEG、JFIF、WebP 单张上限 30 MB。新建前先保存当前地图。
2. 单击地图块标签选择卡片。“地图块”页签的上传替换当前图片；多张图片继续填入同视图的空卡片。拖入画布时会提示目标卡片和视图。
3. 使用 4 / 8 / 12 分扩展卡片，设置横纵重叠比例，从所选卡片继续向外扩展。参数只影响之后建立的卡片。
4. 项目栏显示完整地图工程保存状态，点击可立即保存；“更多 → 下载编辑源文件”下载完整 Forge 地图源包。点击“导出”选择地图资源格式。

编辑中的解码图片与 Blob URL 保存在页面内存中，完整草稿先写入当前 origin 的 IndexedDB 作为备份，再保存到本机服务并进入资产库。源包保留全部图片图层、卡片位置、区域、编辑设置及暂停的未完成队列；Mask 仍由现有图层派生。只有主动发起原图生成或整体层扩图时，提示词（扩图还包含重叠模板）才通过 Runtime Bridge 发送给已选服务。保存工程不创建任务或调用图片服务。同一本机服务上的浏览器可从资产库恢复工程；旧浏览器独有草稿仅在原浏览器打开并保存后迁移。版本冲突会保留本页草稿并报错，先下载本页源文件，再重新打开最新工程。

## 原图生成

场景首页的“生成地图原图”直接打开生成面板。编辑器常驻工具栏和空白画布均有“生成原图”入口，专注模式下也可使用，沿用当前地图设置中的 Nano Banana 2 / GPT Image 2 / 混元 Image 3.0 和服务端 API Key。必须启用图片 API，每次点击只生成一张，不自动重试。原图请求只发送提示词及画幅，不上传当前地图。支持 1:1、3:2、2:3；保留模型实际输出尺寸与像素，不裁切或强制缩放。

生成成功后图片保存在 `outputs/<task-id>/generated-origin.png`，预览可以下载。只有点击“用作中心图”才会替换编辑地图，并先保存旧草稿；失败、关闭预览或重新生成失败均不会替换当前地图。采用后创建中心卡片和首圈扩展卡片，图片来源标记为 API 生成。浏览器草稿和服务端生成记录分别保存；未采用的结果仍可从制作记录的产物中找回、下载再导入。

OpenAI 原图使用 `/v1/images/generations`，扩图继续使用 `/v1/images/edits`。自定义 edits 地址以 `/edits` 结尾时会沿用同一服务的 `/generations`；其他自定义地址需设置 `MAP_STITCHER_OPENAI_GENERATION_API_URL`，不会自动把密钥发送到另一个服务。Gemini 使用当前 `generateContent` 接口的文本输入。

手动验收：先保留一份有内容的地图，打开生成面板并检查模型设置；生成一张后确认旧图未变，下载预览，再点“用作中心图”，检查首圈卡片并生成一块扩图。最后从“打开”找回旧地图、刷新后重新打开新地图，确认两份草稿都在。真实图片生成会使用你配置的 API 额度；自动回归使用隔离模拟服务。

## 图片视图与分层素材

顶部一次选择一个图片视图：整体、地表、物件，或图片视图下拉菜单中的黑底参考、白底参考、Mask。窄屏的全部视图统一收纳在此菜单。Mask 由整体和物件 Alpha 派生，不能上传、删除或像素精修。底部的当前视图数量表示已有素材的卡片数。

“显示”菜单中的“底图”“区域标注”“干净预览”仅控制编辑辅助显示，也可在此切换“导出效果”。“此卡片参与地图输出”才决定卡片图片和区域是否进入 PNG、PSD 与 Godot；被排除的内容仍保存在编辑状态里。选择或悬停不会改变图片叠放顺序。

## 画布布局与属性栏

地图页使用 44px 项目栏、40px 编辑工具栏和 28px 底部状态栏。左上角 Forge F 图标菜单提供工作台导航、场景流程、制作记录、高级工具与新手引导；其他编辑器仍使用工作台原有布局。窄屏的新建、打开入口收纳在“更多”菜单。

- 拖动属性栏左侧的 8px 分隔线调整宽度，默认 320px，范围 280–520px。分隔线可用方向键调整，双击恢复默认。
- 桌面画布至少保留 480px。工作区宽度小于 768px 时属性栏变为抽屉，可通过关闭按钮、遮罩或抽屉内的 Esc 关闭，从工具栏重新打开。
- 宽度和展开状态保存在当前浏览器的 `workbench.map-layout.v1`。临时缩小窗口不会覆盖用户选定的宽度；这些偏好不进入地图文件或撤销历史。浏览器禁止存储或偏好损坏时仍可编辑。
- “专注”隐藏项目栏和底栏，保留编辑工具、属性栏开关、“退出专注”与制作记录摘要。退出时恢复布局；刷新后回到普通模式。
- 拖拽分栏、切换专注和抽屉不会重新创建画布或自动适配。缩放、平移与画布中心对应的地图位置保持稳定；按 0 或点击“适配画布”才重新适配。
- 底栏合并地图操作提示和制作任务摘要。点击摘要打开完整制作记录，待处理与断连状态仍会显示；点击操作提示可展开完整文本。


可靠的分层流程是：

- 上传独立地表和透明物件；或者上传同一物件的真实黑白底参考，再提取透明物件。
- “复制为地表草稿”只复制整图。草稿标记随状态保存；上传独立地表，或精修并点击“确认为独立地表”后，才参与分层合成。
- “由透明物件生成黑白参考”需要物件图片存在透明像素。不透明整图和完全相同的黑白参考不能冒充透明物件。
- 图片状态会标明上传、草稿、API 生成、参考派生、提取或精修来源；旧文件中的本地补全图片仍可读取。

图片锁定作用于当前图片类型的全部卡片，涵盖上传、删除、精修和生成。异步任务提交时再次验证锁、原图片和文档版本；中途锁定再解锁，也会使旧结果失效。四边羽化影响卡片全部图片，因此相关图片被锁定时不能修改羽化。

## 区域绘制

区域是独立的矢量数据，分为遮挡扣除、碰撞、调整和顶层区域。每个区域记录所属卡片和创建时的图片视图。

- 默认列表与清空操作只针对当前卡片、当前图片视图、当前区域类别。
- “当前卡片的全部视图”会显示其他视图的参考区域。点击列表中的参考区域，跳到它所属的视图后编辑。
- 眼睛只隐藏辅助标注。遮挡扣除仍影响物件与 Mask；碰撞仍导出到 Godot；顶层仍从整体图裁出前景。
- 区域类别锁定作用于该类别的全部卡片。可以查看、选中锁定区域，不能创建、删除或清空它。
- 矩形点击两次；多边形点击添加顶点，Enter / C 完成；自由套索按住左键绘制，松开闭合。无效坐标、零面积和自交会给出提示。
- 区域在 SVG、命中检测、Alpha 扣除和 Godot 碰撞中共用闭合几何。

像素精修通过独立弹窗修改图片：保留画笔、橡皮、吸色、超级橡皮擦、框选移动、透明背景、撤销和恢复原图。弹窗内的快捷键不会操作地图区域。

## 导航与历史

| 操作 | 行为 |
| --- | --- |
| 中键 / 右键 / 空格 + 左键 | 临时平移，不添加区域顶点 |
| 平移按钮 | 切换持续平移；关闭后继续原绘制工具 |
| 画布滚轮 | 围绕鼠标缩放；属性面板滚轮只滚动面板 |
| 0、+ / -、H | 适配画布、缩放、切换卡片标签 |
| Esc | 依次取消草稿、取消区域选择、退出区域编辑 |
| Backspace / Delete | 有草稿时撤回顶点，否则删除可编辑的选中区域 |
| Ctrl / Cmd + Z | 先撤回草稿顶点，再撤销文档修改 |
| Shift + Ctrl / Cmd + Z | 重做文档修改 |

历史覆盖区域、图片替换与精修、羽化、卡片扩展和输出排除，最多保留 80 步；新操作会清空重做分支。切换卡片、视图、类别、工具、打开弹窗或失焦会取消草稿。历史不是保存文件的一部分。

## 生成队列

“生成队列”支持空整体卡片补全、批量物件提取，以及最多 64 块的自动向外扩展。并发为 1–4；可暂停、继续、取消、重试失败项和清除记录。

整体扩图仅调用图片 API。未启用或未配置时禁用生成，并提供 API 设置入口；请求失败不会回退到本地补全。物件提取在本地处理真实黑白参考。暂停让进行中的任务完成，取消则停止调度并丢弃未提交结果；已发出的外部请求可能继续在服务端完成。

内存保护按图片和历史的 RGBA 解码占用，加上生成临时画布预留估算，并非浏览器实际总内存读数。超过上限会在新任务启动前暂停；可调整阈值或在队列停止后释放历史。合成输出另有单边 30000 像素、总计 6400 万像素的限制。

## 保存、导出与恢复

| 格式 | 内容 |
| --- | --- |
| 当前图片视图 PNG | 当前图片类型的拼接结果，含羽化和适用的遮挡扣除 |
| 导出效果 PNG | 与 Godot 默认可见层一致的合成 |
| 全部图片层 PNG · ZIP | 所有已有图片视图、顶层、合成图和尺寸 / 原点清单 |
| 顶层区域 PNG | 顶层区域裁出的透明前景 |
| 分层 PSD | 按图片类型分层保存，参考和派生层也可检查 |
| Pixelwork 编辑状态 | 原始卡片素材、几何、区域、羽化、锁与显示偏好 |
| Godot 包 | PNG、`map_scene.tscn`、碰撞多边形、`regions.json`、读取脚本及 `source_state.zip`，按独立目录组织，不含项目配置 |

“导出效果”使用实际导出合成算法：全部参与输出且有图片的卡片都具备独立地表和物件时，使用“地表 + 物件 + 顶层”；否则保留“整体 + 顶层”。单纯隐藏标注不会改变输出。

“打开状态 / Godot”支持 Pixelwork v1/v2、SceneMaker v5、新 Godot ZIP，以及旧 Godot 合成包。新包优先恢复完整编辑源；旧合成包只能恢复为一个地图块，并明确提示原卡片布局和羽化前素材无法恢复。帮助窗口也能打开带 JSON 清单和图片的完整资源文件夹。

底层 compose 适配器生成的 Godot 包也嵌入同批次 Pixelwork 源状态；该接口不开放 Agent 地图自动制作。更早的 Agent 包只有合成图片和场景时，加载器恢复图片并提示区域数据不足；要继续完整编辑，应打开同批次的 `pixelwork-state.zip`。

SceneMaker 的 ground 映射到 surface，整体图由旧视觉层合成，矩形碰撞转换为像素坐标；旧 foreground 烘焙入整体图，不猜测顶层区域。编辑器不会反向解析用户任意修改过的 Godot 场景脚本。

## API 与 Agent

默认整体层提示词面向纯 2D 横版过关背景：正交侧视立面，左右 / 上下为空间轴，禁止俯视、等距、纵深地面和 3D 渲染；保持原图笔触、配色及细节密度。横向扩图以参考中的主可行走地面为高度基准，保持街面等高、地基厚度一致，不得在重叠区或建筑结束后擅自抬高街面、加台阶、高台或挡土墙；原有斜坡沿其方向延续，用户明确要求的地形变化除外。向上 / 下扩图或参考中没有地面时，不自行添加地面条带，也不按固定画面比例安排地板。生成设置可“恢复横版侧视默认词”。旧状态中完全匹配旧版俯视或首版侧视默认词的文本自动迁移并提示，用户自定义文本保留。已入队任务仍使用原提示词快照；要使用新词，应取消旧任务后重新加入。提示词不能代替实际地面线检测或保证模型精确对齐。

外部生成后，服务端按模板尺寸回收结果，并逐像素保留模板中 Alpha 大于 0 的内容（含半透明边缘）；只填充完全透明处。明显不匹配的返回宽高比会报错，避免拉伸。此保护不保证新生成内容在视觉上完全无缝。

生成设置只保留已有连接器实际支持的参数：服务选择、密钥、是否激活，以及唯一整体层提示词。Host 和 Model 由 Manifest 定义。密钥保存在本机受保护的持久配置或服务端环境变量中，页面只接收“已配置”状态，状态包和日志不包含密钥。

地图属于手动前端工作流，不向 MCP / Agent CLI 开放发现或执行。前端通过 `workbench/manifest.json` 和共享 Runtime 调用本地 `compose`、原图 `generate-origin` 和整体层 `generate-layer` 适配器；生产产物写入 `outputs/<task-id>/`。具体输入见 [连接器契约](connector-contract.md)。

页面 WebMCP 另提供七个操作入口，但不能用于绕过 Agent 手动地图边界：读取摘要、切换视图、导入图片、生成图片、创建区域、导出、管理队列。它们与按钮、快捷键共用控制器，遵循相同锁与版本检查。普通页面编辑不产生仓库级生产任务 ID；通过服务端执行的外部 `generate-layer` 会进入工作台共享的 runtime task ledger。

### 地图块额外提示词

整体图片视图在生成按钮上方提供“额外提示词（可选）”，支持多行输入、清空、2000 字限制和完整提示词预览。每张地图块独立保存；浏览器草稿、源文件 ZIP 和 Godot 包内的源文件均携带该字段。旧文件默认空文本，新扩展卡片不会继承其他卡片的额外要求。

发送给 API 的 `prompt` 是基础提示词与当前卡片额外要求的组合，空白额外要求不改变基础提示词。不会增加第二次模型调用。单张、批量任务在入队时保存服务商和完整提示词；自动扩图还会在启动时固定基础提示词与服务商。之后修改设置只影响新任务，失败重试和草稿恢复沿用原快照。旧草稿中没有快照的任务需要取消后重新入队。关闭 API 会阻止后续调度，已发送的任务仍可能完成。

额外提示词不改变服务端的像素保护：模板中非透明像素（含半透明边缘）保持原值，返回图片比例不匹配时报错。历史 `local-fill` 来源仅用于兼容旧图片，生成入口和镜像补全算法已删除。

API 格式核对依据：[OpenAI 图片生成与编辑](https://developers.openai.com/api/docs/guides/image-generation)、[Gemini 图片生成](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)。OpenAI 使用 `images/edits` 的 multipart `image[]`、`prompt`、`model` 和 `b64_json`；Gemini 使用 `generateContent` 的文本及内联图片，并忽略带 `thought` 标记的中间图片。连接器测试使用本机模拟服务验证请求和返回处理，不代表真实账号的付费调用已验证。

### GPT Image 2 输出尺寸适配

整体扩图显式发送 `size` 和 `output_format=png`。服务端从实际 PNG 尺寸选择 16 像素网格上的合法输出，优先精确保持比例；只容许既有接缝检查允许的一个输出像素舍入误差。目标像素数不超过 2048 × 1152，并以接近目标的合法尺寸为准，候选均不超过 2560 × 1440 总像素，避开官方标记的更高分辨率实验范围。输出长边不超过 3840，比例不超过 3:1，至少 655360 像素。不能匹配时在外部调用前报错。

例如 5504 × 3072 模板明确请求 2064 × 1152；返回结果等比例恢复至原模板尺寸，再覆盖保留全部原有非透明像素。还原提高的是画布分辨率，不会凭空增加生成部分的细节。服务端会把内置提示词中的旧“返回原图尺寸”句子换为保持比例和构图，并追加实际输出尺寸；不会修改用户保存的提示词或队列快照。

每次任务写入 `generation-diagnostics.json`，包含模板、请求、返回尺寸、实际发送的提示词和处理阶段。API 返回图片后立即保存原始字节为 `provider-response.png`（其他格式按实际扩展名；无法解码为 `.bin`）。合成失败时这两个文件仍列入失败任务产物；不会产生或冒充 `generated-layer.png`。上游未返回图片时只保留诊断文件。尺寸异常不自动发起额外付费重试。

更新服务端适配器后，已经运行的 Runtime Bridge 需重启才能加载新代码；界面保存的密钥会从本机受保护配置恢复，无需重新填写。

## 新建空白项目

顶部提供“新建项目”和“打开”，窄屏从“更多地图操作”进入；导入中心图片仅保留在空白项目画布上的“导入地图图片”按钮。已有地图的图片更新通过卡片上传完成。新建经确认后先保存当前本机草稿，再清空地图块、区域、编辑历史、选择、整体及卡片提示词、视图和扩展参数；保留 API 配置和设备面板布局。保存失败时保留当前项目并显示错误。

新建会取消本页队列及自动扩展，旧任务的晚到结果不能写入新项目。已提交到图片服务的请求可能仍在服务端执行。旧项目可从制作记录恢复，新建不删除源文件或历史产物。

空白项目地址使用 `?map=new`，刷新不会自动加载最近草稿；导入图片或打开项目后地址更新为新草稿 ID。

验证：地图测试 30 项、工作台外壳测试 11 项及 lint、typecheck、build 通过。浏览器中导入测试 PNG、修改缩放后新建，确认 0 块、100% 缩放、撤销/重做禁用，刷新仍为空白；旧草稿通过原地址恢复成功。队列回归覆盖取消中的旧任务晚返回与新任务并行完成。

## 混元 Image 3.0（地图）

“地图生成设置 → 图片 API 模式”选择“混元 Image 3.0”。本次接入地图原图和整体层参考扩图；角色原图与动画仍使用原有 PixelLab 链路，地图不开放 MCP 自动制作。

### 账号和密钥

1. 注册 / 登录[腾讯云账号](https://cloud.tencent.com/document/product/378/125818)，按控制台要求完成实名认证。
2. 在 [TokenHub 控制台](https://console.cloud.tencent.com/tokenhub)开通服务，在“在线推理”中启用 Hy-Image-3.0，并确认可用额度 / 后付费。
3. 前往 [API Key 管理](https://console.cloud.tencent.com/tokenhub/apikey)创建在线推理密钥，授权访问混元生图模型。此接口使用 TokenHub 在线推理 Key；Token Plan 编程套餐密钥不适用于这个生图入口。
4. 在工作台“地图生成设置”选择混元、填写 Key、勾选“激活图片 API”，保存后即可生成。页面不显示已保存的密钥，也不把密钥放入生成记录或浏览器存储。

在地图生成设置中点击保存后，各服务的 Key、所选服务和启用状态会保存在本机 `work/config/map-generation.json`，重启后自动恢复。Windows 使用当前账户加密；macOS 使用钥匙串保护加密配置；其他系统使用权限受限的本地文件。网页不回显 Key，留空保持已保存值，停用不会删除 Key。也可通过本地 `.env` 设置 `TOKENHUB_API_KEY` 和 `MAP_STITCHER_IMAGE_PROVIDER=hunyuan-image-3`；网页保存的设置优先。使用 `npm run dev` 启动时读取 `.env`，独立启动 runtime 时用 `node --env-file=.env scripts/workbench-http.mjs`。

### 接口及限制

- 模型 ID：`hy-image-v3`。采用当前 TokenHub 新接口，避免使用计划于 2026-09-15 下线的旧 ID `hy-image-v3.0`。
- 默认中国大陆广州接口：`POST https://tokenhub.tencentmaas.com/v1/wand/hunyuan-image/v3-generation`。若账号服务开通在其他地域，使用对应地域完整接口配置 `MAP_STITCHER_HUNYUAN_API_URL`，不会自动跨地域重试。
- 完整提示词上限 8192 字符，参考图片使用 PNG / JPEG，最多 10 MB；本工作台每次发送一张扩图模板。
- 根据地图比例选择单边 512–2048、面积不超过 1024² 的输出尺寸。原图保留实际返回尺寸；扩图校验尺寸后用最近邻恢复原模板尺寸，并逐像素保留模板已有的非透明像素，只填充透明区域。无法匹配的画幅会在调用 API 前阻止。
- 这是参考图生图适配，接缝和内容衔接仍须人工检查，不宣称混元具备专用像素级扩图能力。关闭自动提示词改写，尽量保持用户约束。
- API 返回临时图片地址，服务端立即下载转存到任务产物。下载不携带 API Key，不允许重定向；只接受腾讯云图片域名（测试环境可使用显式配置的本机服务）。API 或下载失败不会自动再次生成。

官方资料：[生图调用指南](https://cloud.tencent.com/document/product/1823/135745)、[API 与地域](https://cloud.tencent.com/document/product/1823/130078)、[旧版迁移](https://cloud.tencent.com/document/product/1823/135600)、[模型价格](https://cloud.tencent.com/document/product/1823/130055)。计费以控制台当前额度和账单为准，不把历史价格作为长期操作规则。

手动验收：生成一张方形原图，预览后“用作中心图”；选择一个相邻空卡片生成整体层，检查已有区域像素保持、过渡自然；导出并重新打开草稿。换回原有模型后也应能继续使用。自动回归使用隔离模拟服务，不消耗真实额度。

## 完整工程持久化

前端 `PUT /api/workbench/map-stitcher/projects/<id>` 代理 Bridge 同路径的 `/v1/` 接口，以 `application/zip` 和 `X-Map-Revision` 提交完整工程。GET 返回已保存源包和版本；过期版本返回 409。记录在 manifest 的 `workspace.mapProjectDirectory`，不可变源包版本在 `outputs/map-project-<hash>/<revision>-<uuid>/map-source.zip`，成功写完源包才原子切换记录。256 MB 上限包含解压后的字节。此接口只供人工编辑器持久化，不新增 MCP/CLI 地图生产能力。

资产库新增这些工程，同时保留已保存地图图片与历史素材；通过“地图工程”或“地图原图 / 历史素材”筛选。工程下载只读取编辑源文件，不自动生成 PNG、PSD 或 Godot。打开下载包中的 `map-source.zip` 会导入为新工程；从资产详情进入则继续保存到原工程。恢复的未完成队列始终暂停。历史 Pixelwork / SceneMaker / Godot 导入继续保留。

### 地图工程卡预览

地图工程预览由浏览器随保存本地合成，最长边不超过 640 像素；仅展示参与输出的卡片，按现有分层与顶层规则合成，不显示网格、选中框或区域辅助线。预览以透明 PNG 作为工程附件，与当前源包版本一同持久保存，不新增图片资产；下载仍提供完整源工程。卡片按 16:9 等比显示并使用棋盘底，附地图块数与保存时间，点击预览继续编辑，详情可放大。视图切换、选择、缩放和平移不触发重绘。预览失败、缺失或旧工程无图时显示占位，源工程保存与下载不受影响，也不复用过期预览。旧工程在下次打开并保存时补齐。
