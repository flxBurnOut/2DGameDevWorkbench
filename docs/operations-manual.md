# Forge 使用与操作手册

新建角色动画使用修正后的规划与可见性核对：规划会给策略和协调环节预留额度，
最终绘图说明在提交前校验；原来的确认按钮和五阶段界面不变。检查会区分
“看不清”“可能遮挡/透视缩短”和“具体外观矛盾”。看不清不自动判错或通过，
相反专家意见没有解决时仍需看实际帧确认，不会自动重画。旧任务和失败记录保留
原版本；新修改继承原工作的复核规则。模型仍可能误判，检查报告不是作品自动采用。

查看角色动作方案时，“段末姿势”会直接说明有几段绑定了真实图片；未绑定的段使用
文字要求。原图结构辅助不会自动提供目标姿势图。有合适的图片时，展开原有的
“用已有图片约束段末姿势”，检查后绑定即可。最终仍需看实际动画；旧作品和
选帧修改流程保持原样。

选帧修改的试做次数按帧计算：改过 13–14 帧后，可以继续选择 15–16 帧。每帧最多参与两次绘图，页面显示当前选区剩余次数。尚未绘图的理解失败不占绘图次数，历史费用不会删除；已提交但失败或未知的绘图仍计数。不同窗口互不占用，重叠帧沿用已经使用的次数。

选帧修改默认只需“选帧 → 填写要求 → 生成一个备选”。“精确限定修改区域”是默认关闭的可选画笔；勾选后每帧涂选，区域外像素才有硬保护。修改细节时以原姿势为基础，未要求的内容应保持。128 像素原帧编辑一次支持 2 帧，限制选中数量而非帧号；未锁定段尾可选，例如 15–16。奇数、单帧、反向范围和保护锚点分别提示，不自动凑帧或拆分收费。理解失败且绘图为零时没有新版，不显示“保留原版”。真实备选出现后同步播放、填写结论，再采用或保留原版。

角色准备页新增可选“结构解析与纠正”：一次解析识别原图部件和锚点；点击“查看结构”
叠加检查，按需展开纠正、保存与恢复旧版本。查看、刷新和手动纠正不再次调用语义模型，
不改变原图；模型设置可单独选择“角色结构解析”模型。核对并确认后，可勾选
“使用已核对的结构辅助本次制作”；仅确认结构不会自动启用。实际效果仍需看生成动画，
其中未知部位仍保留为未知，不会因为点击确认就自动变成确定的控制位置。
详见 [角色视觉结构](visual-structures.md)。

分段检查页从“高级工具”进入“结构观察”：默认本地追踪，不调用外部模型；勾选关键帧核对才
增加最多一次语义请求。查看部件叠加、按当前帧纠正观察或恢复旧版，不修改动画。
未知部位不会显示成确定坐标。另行开启结构辅助复核前会显示最多三次视觉请求，
旧作品缺少基础检查时不会自动补收费调用；报告只是建议，不代替你的采用决定。

如果参考区域一开始就圈错了，可先在实际动画第 1 帧纠正该部件。新观察版本会优先使用
这次明确纠正，避免旧区域继续把后面的追踪带偏。仍要检查后续帧；这是免费的观察纠正，
不会重画角色、采用动画或更新已有复核结论，旧观察版本可以恢复。

开放动作补充：方案页可按需展开“用已有图片约束段末姿势”，先检查并绑定同尺寸透明 PNG，再开始制作。无需目标图时直接用原流程；目标图片本地保存，不额外调用模型。分段检查页可展开“只修复这一段的局部问题”，选择窗口与实际缺陷，明确允许一次修复后生成前后对比预览。128 像素的外观编辑一次修 2 帧；运动修复一次选 4–16 个内部偶数帧。须播放整段并核对两侧接缝；可以保留原片段，失败结果不会删除。采用修复后重新复核，仍需确认本段才继续。调用次数受原任务预算限制，不能静默追加。

2D game dev workbench

2026-10-24 角色动作主流程更新：进入“角色美术 → 制作玩家”，按“准备与描述、查看制作方案、自动制作、检查与调整、导出与使用”操作。点击“制定方案”才调用规划专家；确认方案后才绘制并调用视觉验收。查看方案时关注动作事件、装备归属、结束姿态和节奏，不只看阶段名称。三类调用分别计费，预算展开后可调整；模型报告不会自动重做或采用素材。

规划进度以每位专家的最近一次调用为准：“已提出建议”“已提交方案”只表示收到了对应意见，不代表可以绘图。本机校验拒绝显示“校验未通过”；无效回复、请求失败或中断显示明确状态并停止转圈。只有规划仍在运行且当前调用尚未返回时才转圈。终止后可直接点“重新制定方案”，沿用当前要求并保存新版本；无需先修改提示词。按钮旁明确显示本次规划调用上限，重新规划会再次调用模型，旧版本与费用记录保留，成功后仍要另行确认开始制作。也可先点“返回准备与描述”修改要求。刷新只读状态，不重新收费；网络回复未确认时再次提交沿用同一个请求，不重复创建。带关键问题的方案仍需补充，不算通过执行校验。

“模型设置”可分别选择默认规划模型、视觉复核模型和单个专家。API Key 与服务状态默认展开：TokenHub、OpenAI、PixelLab 分别输入，已保存的 Key 不回填，留空保存保留原值。新增模型时展开“新增或编辑可选模型”，选择 API 服务、填写服务商准确模型 ID，设定输出上限与请求等待上限，点击“加入可选模型”；分配给对应专家后再“保存配置”。同一服务共用 Key；账号需具备对应型号权限。配置修改只用于新规划，已有任务保留原模型记录。Kimi K3 系列的参数自动适配，较慢的推理模型可提高等待上限；超时不会自动重发。

视觉复核可直接选择 TokenHub 的 `glm-5.3-flash`，与 Kimi 规划共用已保存的 TokenHub Key。请区分 `glm-5.3-flash`（支持看图）和 `glm-5.3`（纯文本）；设置界面会拒绝把已知纯文本型号用于看图专家。模型切换只影响新规划，旧候选的 HY 报告不会被改名或自动重跑。

带质量合同的新任务在生成后提供完整性、装备一致性、节奏三项报告及帧证据。模型的通过/失败/不确定都需结合实际播放判断；修改帧后旧报告失效。未通过的结果可以继续调整；若人工检查后决定接受，必须写明结论并确认提醒。旧版任务没有视觉报告时不会自动收费补做。导出使用已确认的播放帧序，原始返回仍完整保存。

新规划会在每段完成后显示“确认第 N 段”：先播放当前完整片段，再拖动逐帧条核对目标末姿势、装备和节奏；勾选检查确认、填写结论，必要时核对模型提醒，点击“确认此段，继续制作”。实际末帧会锁定为后段起点。模型说通过也不能替你确认；WorkBuddy 可以取得同一组实际帧并代为检查。片段不合格时展开“本段未达到要求”停止后续制作，已完成内容保留；不会自动付费重画。最后一段确认后仍须检查完整动作与片段衔接。刷新保留当前检查点，普通继续按钮不能绕过检查。

若目标姿势出现在较早帧、最后几帧已越过目标，展开“目标姿势提前到达时，选择实际锚点”，选择准确帧并勾选采用范围。记录截取原因后再确认；尾帧完整保留，不进入本段播放快照。下一段会从选中的真实图片继续。没有明确选择和范围确认时，系统不会自动截取。

制作中可以暂停后续请求、刷新或稍后回来；已经提交的片段继续取回，不自动重发。结束后播放完整动作、逐帧查看并核对提醒，勾选播放确认、写下至少 4 个字的检查结论，并明确接受已核对的技术提醒后采用。按钮不可用时，底部会说明尚缺哪一步；有阻断或待修补帧时先处理，不能强行采用。已采用的候选能反复进入导出；点击“导出到 Godot 项目”打开原有路径选择和 WorkBuddy 交接提示。修改需求会建立新版本，历史版本和素材保留。从“需要调整时”进入逐帧编辑后，顶部“返回当前作品”会回到相同版本与候选；请先保存修改，再返回重新检查。旧任务、旧预设仍可从制作记录的“旧版工作区”进入。当前技术 QA 不等于自动视觉验收，详见 [序列帧主流程](sprite-generator.md)。

## 1 先认识工作台

### 谁负责什么

Forge 的网页负责编辑、预览、制作记录和导出。WorkBuddy、Codex 等外部客户端中的 Agent 负责理解需求、选择工具和编写获授权的游戏代码。网页没有另一个通用聊天 Agent。

MCP 是客户端调用工作台工具的接口；Skill 是告诉 Agent 怎样完成某类工作的项目说明。连接 MCP 可以获得工具，但不能代替宿主读取 Skill、操作内部浏览器或修改目标游戏的权限。

| 入口 | 用途 | 谁来操作 |
| --- | --- | --- |
| 角色美术 | 角色原图、动画候选、检查、修补与导出 | Agent 可调用已开放的 MCP；精细修补在界面完成 |
| 场景中的地图工具 | 生成中心图、扩图、拼接、分层与碰撞 | 用户在前端操作 |
| 场景中的交互物 | 门、开关、查看物件、拾取物与序列行为 | 用户编辑，或 Agent 用 MCP 制作 |
| 场景组装 | 摆放已有地图与交互物、调整遮挡、导出场景 | 前端操作或 Agent 共享文档命令 |
| Image 2.6 | 生成背景、透明物品与编辑图片 | 前端或 Agent；采用后进入工程 |
| 资产库 | 查找已有素材、区分候选、下载真实文件 | 用户或 Agent 查询 |
| 游戏工程 Skill | 把已就绪资产接入 Godot，设计架构与编写脚本 | 外部 Agent 在指定目标工程中执行 |

旧地图拼接与扩图不开放 Agent 自动制作。路线 A 单独开放背景/物品生成、采用和共享场景编辑；工程 Skill 消费已经导出的文件并接入游戏。

已保存的地图单张源图、交互物静态外观和独立图片可通过 Agent 做局部调整：先选定目标和区域，生成候选，检查后再采用。7B 共用工作区已接地图单层、交互物默认图及独立图片入口；7C 增加明确提交的 AI 局部候选，实际 UI 验收另记。替色、透明噪点清理、填充、擦除与移动仍是无需 Python 或 Key 的本地操作；AI 使用图片服务并可能消耗额度，不自动从本地失败升级。本批真实模型请求为 0，真实模型品质尚未验收。7D 已接指定状态槽及场景引用：选中实例使用独立派生素材，其他共享实例保留；地图快照仅在验证单源像素映射后开放，图层 PNG 与嵌入源 ZIP 同一事务保存。不能确认映射的派生或合成层只读，使用源地图入口继续。地图拼接与扩展边界不变。详见[图片局部调整](image-editing.md)。

### 四个容易混淆的概念

“任务”记录一次执行，例如生成、检查、保存或导出；同一作品可能有多条任务。“作品”指实际素材，同一动画作业的不同候选是不同版本。“草稿”是可恢复的编辑状态；地图完整草稿同时保存到本机服务。“导出包”是能够下载、备份或导入其他工具的真实文件。

因此，任务数量不等于作品数量；查询到记录不代表文件仍存在；检查完成也不等于已采用或已导出。资产库显示的是它能够读取的持久素材，浏览器草稿另在原工具中恢复。

## 2 安装与启动

### 首次准备

使用 Node.js 22.13 或更高版本。需要角色原图或序列帧时，还需要 Python 3.11 或更高版本；项目 CI 使用 Python 3.12。仅地图、交互物和场景组装不需要 Python。导出 Godot 包无需安装 Godot；实际导入和播放验收使用 Godot 4.7.x。

先把仓库放到稳定目录。Windows 可在该目录打开 PowerShell；macOS 可使用终端。以下命令都从仓库根目录执行：

```sh
npm ci
npm run sprite-pipeline:setup
npm run dev
```

npm ci 安装锁定的前端与 Node 依赖。setup 查找 Python，在 Tools/SpritePipeline/.venv 创建独立环境并安装锁定依赖。它用于准备 Python 工具运行条件，不会生成图片。不同操作系统之间不要直接复制 .venv；在新机器上重新 setup。

如果只需要地图、交互物和场景，首次运行 npm ci 后，使用 npm run dev:interactable 即可。这个命令名称虽然包含 interactable，启动的前端仍包含其他页面，只是不启动 SpritePipeline。

### 日常打开与关闭

完成首次安装后，通常只需 npm run dev，再打开 http://localhost:3000。保持启动终端运行。正常结束时在启动终端按 Ctrl+C；由启动器管理的子服务随之退出，启动前已经运行的外部服务不会被它关闭。

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| 前端 | http://localhost:3000 | 导航、专业编辑器、作品预览 |
| Runtime Bridge | http://127.0.0.1:8790 | 任务、文件、地图生成与本地导出 |
| SpritePipeline | http://127.0.0.1:7860 | 角色原图、动画服务和原生操作界面 |

默认 localhost 可能使用 IPv6。应先检查清单指定的地址，不要仅凭另一个回环地址连接失败就判断服务离线。前端、Bridge、Sprite API 与 Sprite UI 是不同检查对象；其中一个在线不能代表全部就绪。

### 拆分启动和重启

开发时可以分别运行 npm run dev:web、npm run workbench:http 和 npm run sprite-pipeline。最后一个提供 UI 与 API；npm run sprite-pipeline:api 仅提供 API，其根页面返回 Not Found 时不能作为嵌入工作区使用。

修改服务端代码后，旧进程可能仍在运行旧代码。先保存编辑内容，查看是否有尚在生成的任务，确认要重启的是本项目进程，再重启受影响服务。不要对占用端口的未知程序直接强制结束。项目没有闲置自动关闭计时器；终端关闭、进程异常退出或旧模块缓存都需要分别排查。

## 3 模型与密钥配置

### 角色原图和动画

在角色原图页面或序列帧工具“设置”中保存 PixelLab Key。两处连接同一 SpritePipeline 服务时共用凭据，输入一次即可。保存后输入框留空是正常行为，应看“已配置”状态。

默认凭据文件位于 work/sprite-pipeline/config/credentials.json。Windows 使用当前用户 DPAPI 保护，重启服务后会读取。PIXELLAB_API_KEY 环境变量可以覆盖已存值；启用覆盖时，界面不能修改该值。换机器或 Windows 用户后，不应假定旧加密文件仍可解密。

原图、动画生成以及启用的模型视觉检查或 AI 修补可能使用外部额度。普通浏览、模板、资产清单、下载已有文件和本地 Godot 打包不会调用生图模型。具体制作范围由用户当前请求决定；结果不明时先查旧任务，不重复提交。

| 设置中的名称 | 提供方 ID | 当前模型 ID | 服务端变量 |

| GPT Image 2 | gpt-image-2 | gpt-image-2 | OPENAI_API_KEY |
| GPT Image 2.6 | gpt-image-2.6 | gpt-image-2.6-sunburst | OPENAI_API_KEY |
| 混元 Image 3.0 | hunyuan-image-3 | hy-image-v3 | TOKENHUB_API_KEY |

在地图设置中选择提供方，填写 Key 并启用图片 API。页面保存的地图 Key 会持久保存在本机，Windows 使用当前账户加密，macOS 使用钥匙串保护；重启 Bridge 后自动恢复。也可把对应变量保存在本机未提交的 .env，并由项目启动器读取。

首次创建 .env 时参考仓库的 .env.example；已有 .env 时只修改必要字段，不覆盖整份配置。以混元为例，设置 MAP_STITCHER_IMAGE_PROVIDER=hunyuan-image-3，并在 TOKENHUB_API_KEY 填入自己的密钥。不要把实际 Key 发给 Agent 对话或写进任务 JSON。

混元接入使用 TokenHub 在线推理 Key，入口为 https://console.cloud.tencent.com/tokenhub/apikey。不要把 Token Plan 的其他凭据类型直接当作在线生图 Key。账号开通、模型权限与费用以当前控制台提示为准；项目中的模型与端点以 manifest 为准。账号说明可从地图设置提供的入口及仓库地图手册继续查看。

### 视觉检查凭据

序列帧攻击视觉检查可以使用单独配置的服务。当前默认 TokenHub 混元视觉检查可读取 TOKENHUB_API_KEY，也支持其设置内声明的 OpenAI 选项。地图界面里临时填写的 Key 不会自动写进另一个进程的设置；若需要共享环境变量，应通过统一启动配置提供。

视觉模型检查和 AI 修补不是免费本地 QA。启用时按设置和请求范围使用；新修补结果须预览并明确采用，不能把自动建议当作已替换原帧。

## 4 导航与保存

### 从哪里进入

开始页使用 Forge 的 F 标识。“角色美术”进入 /player，可选择制作角色原图或进入序列帧；“场景”进入 /scene，提供地图原图、地图拼接、交互物和场景组装。“资产库”位于 /assets，“高级工具”位于 /advanced。

工具上方上下文显示当前位置和已有作品，制作记录可恢复正在做的内容。序列帧的生成、检查、修补与导出使用其内部标签；外层上下文栏不再承担一条不可点击的进度条。

进入页面、查看作品、向 Agent 问方案都不应创建新的制作任务。确实保存、生成、检查或导出时才会产生相应记录。不要把高级工具中的多次执行尝试当成重复作品。

### 保存和下载的区别

地图自动保存会将完整工程保存到本机服务并收录进资产库，同一工程反复保存只更新一件资产。资产详情中的“继续编辑地图”恢复图层、布局、区域和设置，未完成队列保持暂停。旧地图草稿仍需在原浏览器打开并保存后收录。交互物和场景的浏览器草稿仍依赖原浏览器、原网站地址的 IndexedDB。地图单张生成、扩展、拼接或导入图片不单独收录，但原文件与制作记录保留。地图下载提供完整 map-source.zip，不自动生成 PNG、PSD 或 Godot 包。

离开工具前确认保存完成。保存失败时保留当前页，重试保存或下载源文件。地图生成、交互物导入导出等繁忙操作期间，导航可能被阻止，以免丢失编辑内容。源文件导出才是便于换机器的备份。

序列帧作业由 Python 服务保存，原图的生成任务由 Runtime 保存。它们不是浏览器草稿。原图尚未提交的表单内容不等于已保存任务，刷新前应先记录必要描述。

### 已有图片的本地局部调整

地图中选择卡片和真实图片视图后点“局部调整本层”；交互物中点“局部调整默认图片”；独立图片任务预览或资产库 `image:` 详情中点“局部调整图片”。地图和交互物打开前等待工程保存到服务端，冲突时保留本机草稿。工作区打开期间暂停宿主交叉编辑与离页，采用后读取准确服务端版本并刷新自动保存基线。

画笔、橡皮和本地操作先形成候选。“原始图片”是会话冻结源图，“当前候选”可能含未保存笔划；“保存笔划为候选”后仍需明确采用。“恢复会话原图”只恢复所选图片为一个新版本，其他图片、几何、区域和行为保留；默认静态图采用仍会停用默认待机 / 聚焦动画。采用后继续精修需基于当前图片新建会话。地图锁仍覆盖同类型的全部图块，场景引用不会随源图自动更新。

未保存笔划仅有本浏览器的延迟 IndexedDB 恢复副本，受存储、容量和基准校验限制；不跨浏览器同步，也不是共享候选。保存失败时保留页面，先检查原会话与任务，再重试相同命令；若提示服务端已采用但本页未同步，不能当作未采用而另建提交。详见[图片局部调整](image-editing.md)。

需要 AI 时切换“AI 局部修改”。“添加选区 / 减去选区”只改变硬边蒙版，不修改图片像素；先检查范围，若要画局部范围可先清空整图选区。填写描述并选择参考后，明确点“生成 AI 候选（调用模型）”。基准、区域、描述和参考字节在提交时冻结；窗口关闭不保证取消请求，断连、刷新和重启不会自动重发。任务链接带准确会话和候选，历史只读不会暗改当前来源。“保留原图透明度”默认开启，会保留本次基准图的每个透明度值，包括半透明边缘；连续精修以所选候选为准。要新增或删除轮廓时关闭。选区外始终保持原 RGBA；颜色、内部细节、接缝仍需检查。未提交的 AI 表单不属于服务端候选。恢复成功时预览直接使用已核验的原图；建立新会话或切换候选后，地址栏同步到当前身份，可复制该链接继续查看。

## 5 制作角色原图

### 从描述到参考图

进入“角色美术 → 制作角色原图”，确认 SpritePipeline 与 PixelLab 已就绪。输入角色描述，可指定名称和朝向。描述宜包含职业、服装、武器、主要颜色和侧视要求，例如：森林游侠，绿色短披风，皮甲，手持短弓，面向右侧，轮廓清楚。

点击“生成一张原图”。当前输出固定为 128×128 透明背景像素角色，不额外调用付费提示词改写。等待任务完成后，在预览中检查人物是否完整、透明边缘是否正确、手持物与朝向是否符合要求。每次主动重新生成都是新的请求。

需要继续动画时，点击“用于制作序列帧”。工作台会把完成的原图导入为可复用角色预设，并在序列帧页预选它。移送保留原图字节，不缩放、不重画，也不自动创建动画任务。随后选择动作才开始动画制作。

同一原图重复移送会复用相同角色身份；内容发生冲突时会拒绝覆盖。仅需要原图的任务，到下载 PNG 即可结束。

### 用 WorkBuddy 制作

可以说：“制作一个面向右侧的森林游侠像素角色原图，只做一张，完成后让我预览。”若还没决定外观，先说“只讨论方案，不生成”。Agent 应保留你已经给出的选择，只询问影响成品的缺失信息。

已有附件不需要再次付费重画。当前 MCP 没有把任意附件直接注册成角色预设的独立操作；需要通过已开放的页面上传等入口导入，不能编造角色 ID，也不能把任意图片冒充已完成的原图任务。

完成的原图位于该任务目录的 reference.png。接口超时或结果不明时，先查询原任务及上游记录；不要把“再点一次生成”作为默认恢复方法。

## 6 制作和审查动画

### 选角色和动作

进入序列帧工具，默认从作品库选择已有作品，或从“开始”“1 · 生成”选择真实角色和动作。已有原图移送的角色会预选。首次试做通常使用一个候选，帧数、速度和循环沿用当前动作预设；用户明确要求的参数优先。

候选是同一批生成的不同版本。需要三份候选时明确说明三份；不要把三个候选误认为一个最终合成动作。历史素材可能有不同帧数和尺寸，不能假定全部都是 16 帧或规则 4×4 表。

### 播放检查与修补

生成结束后进入“2 · 播放检查”。先正常播放，再慢放和查看问题帧，检查轮廓、衣物、武器、肢体、脚底高度、透明边缘和动作衔接。循环动作还要看尾帧到首帧；攻击动作要看准备、出招与收势是否连贯。

本地 QA 与视觉观察各有作用。文件存在、QA 报告生成或 GIF 首帧可读，都不足以证明整段动画好用。需要修补时进入“3 · 逐帧修补”，保留原始版本。保存会校验当前帧版本并使旧审核失效，随后重新检查。

像素编辑支持手工修补；外部整帧替换需要按当前流程标记待修补。AI 修补必须检查阶段和上下文，新结果先预览，再明确采用。不要为通过导出而跳过硬错误、覆盖较新的帧或随意接受警告。

### 采用和导出

确认选中的候选满足要求后采用，再进入“4 · 导出”。Agent 执行 approve 时必须给出实际看过画面的 reviewNote；acknowledgeWarnings 只能用于明确接受已经检查的警告。当前门禁会检查候选状态、QA 与源文件一致性。

点击“导出 PNG + Godot 包”，可以获得精灵表 PNG、预览、配方与 QA，以及 Godot SpriteFrames ZIP。已经导出的作品可以重新选择并下载已有文件，无需再生成。旧导出没有 Godot 包时仍能读原文件；需要新包时按当前审批规则重新导出，不在浏览时偷偷补做。

### 继续已有候选

可以说：“打开最新一次连续三个候选动画的第 2 个候选，只看，不生成。”Agent 应按批次和候选条件查询并进入那一版的详情页，不能只停在作品库首页。多个合理结果时显示名称或预览让用户选择；不存在指定候选时明确说明。

## 7 把动画直接导入 Godot

### 导入资源包

在序列帧导出页下载“Godot SpriteFrames 包（ZIP）”。解压后，把其中整个 forge_sprites 文件夹放到 Godot 4.7.x 项目根目录，保持目录结构。

| 包内文件 | 使用方式 |
| --- | --- |
| sprite-sheet.png | 已审核候选的精灵表纹理 |
| sprite_frames.tres | 已装配帧、动作名、FPS 与循环的 SpriteFrames 资源 |
| animated_sprite.tscn | 可拖入场景的 AnimatedSprite2D 视觉节点，运行可播放 |
| export.json | 来源、候选、帧序与导出参数 |
| IMPORT.md | 本包的导入说明 |

目录按角色、作业和候选隔离。包不包含 project.godot，不覆盖项目设置。需要移动资源时优先在 Godot 编辑器内移动并核对引用，不只把 .tres 单独拷走。

给已有 AnimatedSprite2D 使用时，将 sprite_frames.tres 赋给 Inspector 中的 Sprite Frames 属性；无需手动切图和逐帧添加。需要快速独立预览时，把 animated_sprite.tscn 拖进场景运行。

### 更新已有多动作角色

当前导出包包含所选的一个动作。直接用单动作 SpriteFrames 替换整个角色资源，会让原先其他动作不再属于该资源。应由工程 Skill 把这次动作合并进原资源副本，再更新目标引用，保留未选中的 idle、walk、jump 等动画。

导出保留准确帧区域、顺序、动作别名、运行 FPS 和 loop。示例场景按角色锚点配置脚底原点并使用 nearest 过滤。只替换 SpriteFrames 不会自动调整旧角色的偏移、缩放或碰撞，必须结合实际角色检查。

### 最小人工验收

在 Godot 中选中该资源，核对帧数、顺序、动作名和速度。运行场景，循环动作应连续；非循环动作应正常结束。再检查左右朝向、脚底位置和重复触发。导出成功只证明包已生成；以上操作才是引擎里的实际验收。

## 8 制作地图原图与拼接地图

### 没有中心图时

从场景首页点击“生成地图原图”，或在地图编辑器工具栏点击“生成原图”。选择地图模型并启用 API，输入环境描述，选择方形、横向或竖向画幅。原图请求只发送提示词和画幅，不上传当前地图。

生成后先看预览，可以下载图片。只有点击“用作中心图”才把它放入地图，采用前会保存旧草稿。关闭预览或生成失败不会替换当前地图。输出保留模型实际尺寸，不以固定拉伸冒充更多细节。

混元 Image 3.0 支持原图与参考扩图，接缝仍需人工检查。它是参考图生图适配，不承诺专用像素级扩图效果。服务端只填充模板中完全透明的区域，已有非透明像素包含半透明边缘会被保留。

### 已有图片时

在新建空白项目中导入中心图片。选中地图块后可上传替换其当前视图图片；按照需要建立 4、8 或 12 分扩展卡片，设置横纵重叠比例，再选择空卡片继续扩图。

扩展参数影响之后创建的卡片。为某一块补充内容时使用该卡片的“额外提示词”；它与整体提示词组合，一起存入队列快照。后来修改全局设置只影响新任务；要让旧任务使用新要求，应取消后重新加入。

生成队列支持暂停、继续、取消和失败项处理。取消会停止后续调度，已发送给提供方的请求可能继续完成，不能把取消当作撤销费用。出错后先看任务诊断与已有返回图片，不自动发起第二次付费请求。

### 画布操作

| 操作 | 方法 |
| --- | --- |
| 平移画布 | 中键、右键或空格加左键拖动 |
| 缩放 | 画布滚轮；属性面板内滚轮仅滚动面板 |
| 适配画布 | 按 0 或点击适配按钮 |
| 撤销与重做 | Ctrl 或 Cmd 加 Z；加 Shift 重做 |
| 完成多边形 | 点击添加顶点，Enter 或 C 完成 |
| 取消当前绘制 | Esc |

右侧属性栏可以拖动分隔线调整宽度；窄屏时使用抽屉。“专注”隐藏部分外层栏位，保留编辑工具和退出入口；不会自动改变地图缩放。新建项目先保存当前地图，再清空编辑内容，旧地图仍可从记录恢复。

## 9 地图分层 碰撞与导出

### 图片视图和区域

地图可查看整体、地表、物件、黑底参考、白底参考和 Mask。上传独立地表和透明物件可以形成可靠分层；“复制为地表草稿”只是复制整图，需要修改并确认后才算独立地表。

遮挡扣除、碰撞、调整和顶层区域是独立矢量数据。选好卡片、图片视图和区域类别，再绘制矩形、多边形或套索。隐藏区域标注只影响编辑辅助显示，碰撞仍会导出；“此卡片参与地图输出”决定该卡片是否进入成品。

顶层区域形成前景遮挡，碰撞区域决定 Godot 中的物理边界。图片看起来像地面并不自动生成可行走碰撞。对锁定图片或区域不能强行写入；异步生成时改变锁、原图或项目版本，晚到结果可能被拒绝，这是避免覆盖新内容的保护。

### 按目的选择导出

| 想做什么 | 导出格式 |
| --- | --- |
| 发给别人看整图 | 当前视图 PNG 或导出效果 PNG |
| 保留各层图片 | 全部图片层 PNG ZIP |
| 继续在绘图软件处理 | 分层 PSD |
| 以后回来编辑或换机器 | Pixelwork 编辑源文件 |
| 接入 Godot | Godot 包，包含场景、图片、碰撞及完整编辑源 |

当前地图 Godot 包包含独立 forge_maps 目录下的 map_scene.tscn、regions.json、图片、读取脚本与 source_state.zip，不再包含示例 project.godot。导出窗口选择已有游戏后，由 WorkBuddy 安装资源并完成场景与脚本连接；旧包交付时会自动转换。

新包能从内嵌源状态恢复原卡片、区域和素材。旧包只有合成图时，最多恢复其实际包含的内容，不能推断出完整编辑历史或原始分层。工作台也不会反向解析任意手改的 Godot 脚本。

可点击“用于制作场景”，把当前地图完整快照交给场景组装；不必先下载再上传。地图自动保存与下载源文件是不同动作，重要项目应两者都保留。

## 10 制作交互物

### 没有物品图片时

选择物件后，展开右侧“生成物品原图”。输入电池、宝箱或开关等单个物品的描述，确认 PixelLab 已配置，点击生成。它与角色原图和序列帧共用已保存的 Key；输出为 128×128 侧视透明 PNG，每次生成使用账户额度。

先检查预览，再下载 PNG 或点击“采用到当前物件”。采用会替换默认图片，停用默认待机 / 聚焦动画选择，但保留已有动画帧、状态专用图片、其他素材和行为。草稿自动保存；重新进入可从最近物品原图或资产库的“物品原图”恢复。生成不会自动采用或生成动画，切换物件后以采用按钮上的目标名称为准。

通过 WorkBuddy 可说：“为当前电池物件生成一张侧视像素原图，先预览，不要改行为。”对应 reference-art 的 subject=prop；只要求图片时不会创建角色预设。采用后再配置行为或导出。详见[物品原图](prop-art.md)。

### 先选行为

进入场景中的交互物编辑器。没有外观图也可以先制作逻辑草稿，但这不能称为完整美术成品。导入图片或序列帧后，分别调整外观、感知范围、点击区域和自身碰撞。

| 行为 | 常见用途 | 成功后的结果 |
| --- | --- | --- |
| 查看 inspect | 告示牌、说明物件 | 展示内容，可重复或一次完成 |
| 切换 toggle | 门、开关 | 在两种状态间切换，可改变外观和碰撞 |
| 拾取 pickup | 收藏物、道具 | 发出一次拾取事件，可保留、隐藏或释放 |
| 序列 sequence | 多阶段提示或装置 | 每次成功推进一步，到末项按配置处理 |

“只能开一次的宝箱”未必等于“拾取整个宝箱”。先决定打开后是否保留箱体、是否给奖励，再选择对应行为。背包奖励由游戏代码接事件实现，编辑器不会自动替目标游戏创建背包系统。

### 设置和预览

触发可以是靠近按键、点击、自动进入或外部调用。通用默认按键为 E。需要播完再结束的动画或音效，应设置等待；要求等待的动画不能无限循环。

在预览中模拟靠近、离开、按键、点击与两个物件重叠。预览能检查反馈、最近物件选择和状态变化，但不模拟正式人物移动物理。完成状态属于每个实例，复制出来的物件不共享拾取进度。

通过 WorkBuddy 可说：“制作一扇靠近按 E 可开关的门，先保存逻辑草稿，不生成美术。”Agent 应取模板、保持对象 ID 并 save-project，随后给编辑链接。再说“把按键改为 F 并导出 Godot”，应继续修改同一对象而非建立同名新物件。

### 导出和接入

通用导出使用 generic；只有目标是 CopyWorms 时选择 copyworms 兼容版。导出不要求 PixelLab、SpritePipeline 或已安装 Godot。保存源文件可继续编辑，导出 Godot 才提供运行资源包。

通用包整体放入目标项目的 addons/workbench_interaction 目录结构。每个关卡放置一个 interaction_runtime_2d.tscn，再放置所需 object.tscn。靠近交互的实际物理节点加入 interaction_actor group，并让物件感知 mask 包含人物 collision layer；只给普通 Node2D 加 group 不会产生物理重叠。

游戏代码连接 picked_up、toggled、interaction_finished 等信号处理奖励、剧情和输入。CopyWorms 兼容版已有对应角色、输入锁和事件接线约定，仍需在实际目标关卡验证。多包导入保持 runtime/v1 一致，不盲目覆盖旧版运行时。

## 11 组装场景

### 摆放地图和物件

进入 /tools/scene-composer，新建并命名场景。从本机地图记录或源文件导入地图，再从交互物项目或文件中选择素材。把素材拖到画布成为实例；移动、缩放、翻转与碰撞范围一起作用于该实例。

地图默认锁定。需要移动地图时解锁并移动整个地图，使视觉和地图碰撞保持一致。复制交互物实例会获得独立游戏状态。节点眼睛只控制编辑显示；“参与导出”才决定成品中是否出现。

右键可以调整前后顺序，或相对某个物件、玩家参考层摆放。已烘焙在地图图片里的物件不能单独排序，应回地图工具分层，再手动替换场景地图。

### 修改来源后的替换

回原工具改好地图或交互物后，在场景中使用替换并预览差异。交互物替换保留选中实例的身份、位置、缩放、翻转与遮挡；新外观、碰撞和行为来自新素材。未选中的实例保持原样。

地图替换保留物件世界坐标。更换不同原点的地图时按界面选对应点，确认新旧对齐关系再应用。素材没有自动同步，场景操作不回写来源项目。

### 保存和交付

自动保存写当前浏览器草稿；“下载源文件”生成 .scene.zip；“导出 Godot”生成带地图、独立物件、交互运行时和源包的场景包。该包不含正式角色和 project.godot。

在 Godot 中使用 scenes/<scene-id>/scene.tscn，将人物挂到 ActorSlot 下并保持相对 Z 为 0，再按交互物要求配置物理层与 group。剧情、背包及人物控制由目标工程接入。源包用于回工作台继续编辑，手改 Godot 节点不会反向同步。

### 让专家协作制作场景候选

场景工具栏的「场景协作」会先保存当前场景，空场景也可使用。配置支持图片与结构化输出的专家模型后，描述需求、选择已有物件素材、保护内容与总调用额度，即可启动专家规划。默认生成与 AI 局部改图次数为零；要生成新物件或地图，设置新素材生成次数，选择物件／地图图像服务；创建或扩展地图还要选择地图范围和新增图块上限。

协作历史可通过「加载更早任务」继续查看，不限于第一页。列表发生变化时用「刷新列表」重新读取。WorkBuddy 制作会先连接本会话的前端，并进入对应场景任务详情；已暂停跟随或正在编辑时不会强制切换。历史任务的专用链接同样可直接打开。

任务在独立候选中生成与摆放物件、创建／扩展地图、配置联动和改图，并保存专家讨论、实际画面、接缝证据与事件回放。检查后点击「采用到原场景」，原场景有新修改时会报告版本冲突。关闭窗口不会停止后台任务；用暂停按钮停止后续步骤，网络中断用「恢复原请求」核对同一个任务；生成结果未知时核对原制作请求，缺少 Key 时配置完成后继续同一步骤。范围、模型配置和完整操作见[场景专家协作](scene-collaboration.md)。

## 12 找到旧资产并交付真实素材

### 正确查找

资产库按角色原图、动画、地图、交互物和完整场景展示持久素材。完整场景在成功导出 Godot 后收录，每次导出保留独立版本；浏览器草稿和只下载到电脑的源文件不自动收录。使用名称关键词和类型过滤，需要查全时翻页；Agent 应带回 nextOffset 和 snapshot 完成分页。制作历史用于执行追踪，不能代替资产盘点。

同一动画候选的创建、检查与导出会关联到同一资产；不同候选分别保留。时间未知时保持未知，不能把最近打开时间当作生成时间。出现服务离线或部分覆盖提示时，先恢复来源，再判断是否缺项。

清空制作历史仅归档执行记录，不删除或隐藏作品、素材和场景导出。资产详情中的“来源文件与版本”保留首次创建时间和制作/导出记录，点击可追溯已归档的任务。制作历史支持超过 200 条的读取与搜索，不必为了找到较早作品重新制作。

### 下载和交接

勾选已有资产后点击“下载所选素材”，应得到真实 ZIP。原图和地图提供图片，动画包含有序 PNG 帧及已有 GIF、精灵图和 Godot 包，交互物包含源工程及已有引擎包。完整场景包含 scene-source.zip 和 scene-godot.zip；将源包导入场景组装器可继续编辑。未导出的作品可以下载当前素材，但审核状态不会因下载而改变。

每次最多选 100 件，普通素材源文件总量最多 128 MB；包含完整场景时总量上限为 768 MB，场景单文件上限为 512 MB。超过时分批下载。缺文件或打包期间内容改变会报错，不应收到假完成或残缺文件。

Agent 的 get_asset_manifest 返回可读说明和结构清单，适合交接来源、尺寸、帧率与哈希。它不会复制素材，也不能把两个描述 JSON 当作可用资产。需要工程接入时，应同时提供已选文件或真实包。

### 看起来丢失时

先核对是否使用了原来的浏览器和 http://localhost:3000 地址，再检查 SpritePipeline 数据目录及服务是否在线。独立版可能曾把作业保存在系统用户目录，而工作台默认使用 work/sprite-pipeline。启动器有受控的一次性旧资产导入机制，同名冲突保留在 recovery，不会双向同步。

不要清空 work、outputs 或浏览器数据来修复列表问题。读取来源范围、目录和导入记录后再处理；未被当前目录索引不等于资产已删除。

## 13 让 WorkBuddy 正确使用 MCP

### 接入步骤

在 WorkBuddy 打开本仓库，配置名为 2d-game-workbench 的 STDIO MCP。命令为 node，参数为 scripts/workbench-mcp.mjs，工作目录必须是仓库根目录。已有 .mcp.json 和 .codex/config.toml 分别供支持相应配置的客户端使用；文件存在不证明宿主已加载。

连接后通过工具发现确认实际工具面；完整名单以 manifest 和 MCP discovery 为准。新增共享文档工具后需重新连接 MCP；只新开聊天不一定重启旧 server。

WorkBuddy 在首次用户消息后检查前端，离线时启动一次并等待就绪，再调用宿主自己的 present_files 打开内部预览。握手后还没有用户消息时不开网页是正常行为。已有作品优先进入精确详情；之后复用现有预览，用户关闭后不强行重开。

### 对话范例

“盘点已经保存的素材，按类型统计，指出还缺哪些文件；不要生成。”用于资产核查。Agent 应查全请求范围，并说明浏览器草稿不在目录内。

“用这份已选角色制作向右行走，一个候选，其余沿用预设，检查后交付。”用于明确制作。Agent 使用真实角色与动作 ID，不再问已给出的选择；实际审查通过后才导出。

“只设计一个能跑跳、开门的小关卡，按 CopyWorms 方法，先不改文件。”用于工程规划。Agent 先查资产与工程，提供方案，不建生产任务或写入游戏。

Agent 需要澄清时，优先使用当前宿主暴露的 AskUserQuestion 或等价工具，先读取其 schema。没有工具就简短提问；取消或未答复不能当作推荐选项已获批准。正常回复应说明结果、给准确预览或链接，再提供一个有用的下一步。

## 14 从资产到游戏工程

### 工程 Skill 的前提

使用 forge-game-engineering 时，提供目标游戏目录和需要完成的可玩范围，例如把已选行走与攻击动画接到现有角色，或把已导出地图装配进指定关卡。参考 CopyWorms 工程与待修改工程必须分清；参考工程默认只读。

Agent 应读取目标 project.godot、架构文档、场景、配置与相关脚本，以实际 CopyWorms 契约为起点。方法包括正式角色基类、Resource 配置、关卡和 UI Builder、明确事件与输入锁所有权、关卡生命周期。不能因为素材已经齐全就自动引入另一套通用框架。

### 角色帧和动作

优先使用已存在的 Godot SpriteFrames 包。旧资源需要重新整理时，工程 helper 从显式有序 PNG 或 atlas 区域生成资源，记录候选和源哈希；不能按目录字典序猜帧顺序，也不能把精灵表空格当有效帧。

正式角色场景的 Sprite 节点、控制器、视觉偏移和碰撞应保留。部分动作更新使用 sprite_frames_merge.gd 合并到原资源副本。动作别名必须对应实际工程，例如源动作与场景中的 hurt/hit、death/defeated 命名可能不同，需要明确映射。

状态改变时切换动画；同一次更新不能每帧重置到第 0 帧。重复攻击需要一次新的动作触发，即使逻辑状态名未变。攻击前摇、持续时间与命中由原控制器负责，不能把 QA 重点帧或动画播放结束自动当成伤害事件。

Cyber 的蓄力、突进或技能可能暂时接管动画。替换时保留这些控制权与固定帧引用，检查新资源是否有相应帧，不能只看普通行走播放通过。

### 地图实例化

先识别包格式。当前 Frame Ronin 导出有 map_export.json 和 map_scene.tscn；旧 Pixelwork 地图有生成运行时、清单与图块，可能依赖原插件和运行门控；场景组装包则有 scenes/<id> 和共享交互运行时。三者不能混作同一种包。

当前静态地图的图片和碰撞坐标已有原点信息，移动时变换整个地图根节点，不能再次减去导出原点。由关卡 Builder 实例化和持有地图，离开关卡时释放其生命周期。旧流式地图重挂载需保留 request_ready 与 reparent 的顺序及插件依赖，静态测试不能代替该回归。

### Helper 的用途

项目提供 inspect_source.py 只读整理参考源文件；stage_assets.py 在新的输出目录暂存角色或当前 Frame Ronin 地图；character_visual.gd 提供表现层播放；sprite_frames_merge.gd 合并指定动作；map_mount.gd 辅助地图实例化和重挂载。

Helper 不自动合并到游戏，不生成美术，不需要 API Key。Agent 应先检查暂存结果，再执行用户授权的目标项目改动。自定义控制脚本放在生成资源目录之外，以免再次导出覆盖。

### 验收层级

“已写代码”“已暂存资源”“引擎导入通过”“实际播放通过”“画面人工检查通过”“全游戏通过”是不同结论。设置 GODOT_47_BIN 后运行 npm run test:engineering 可以执行隔离的 4.7.x 契约检查；未配置时引擎部分会跳过，不能报告为通过。

目标工程最终仍需测试输入到状态再到动画、重复攻击、暂停、朝向、碰撞、关卡离开重进及实际依赖。fixture 或资产播放器成功不能替代真实游戏验收。

## 15 备份 更新与故障处理

### 备份清单

| 数据 | 默认位置或导出方式 | 迁移注意 |
| --- | --- | --- |
| 共享任务 | work/tasks | 与关联 outputs 一起保留 |
| 原生动画与角色 | work/sprite-pipeline | 保留作业、角色与导入记录 |
| 真实产物 | outputs | 保留原图、帧、包与元数据 |
| 地图草稿 | 工具中下载编辑源或带源 Godot 包 | IndexedDB 不随 Git 迁移 |
| 交互物草稿 | 保存源文件或导出 ZIP | 保持项目与对象 ID |
| 场景草稿 | 下载 .scene.zip | 保留完整素材和实例 |
| 凭据 | 本机 .env 或受保护服务设置 | 私下保管；跨机器可能需要重新输入 |

重要项目在更新前先完成草稿保存与源文件备份，再记录仓库提交及数据目录。安装依赖只恢复程序，不恢复浏览器草稿；Git 同步也不包含被忽略的用户资产。

### 更新序列帧组件

维护者先检查 git status 和本地集成补丁，再核对上游版本。Tools/SpritePipeline 内包含工作台特有的链接、下载、资产目录和 Godot 导出接线，不能整目录覆盖丢弃。更新后运行对应组件及接口回归，再重启旧服务加载新代码。

更新本地工作台、提交主仓库、推送远程主仓库和更新独立序列帧仓库是四件事，应分别报告证据。不要因本地按钮出现就称远程也已更新。

### 常见故障

| 现象 | 先检查什么 | 处理方向 |
| --- | --- | --- |
| 页面出现 Not Found JSON | Sprite 是否以 API-only 启动 | 保存工作后启动 UI 模式，检查根页面 |
| 提示接口不兼容 | 是否仍运行旧 Python 服务 | 确认进程归属后重启，不靠重复 start 修复 |
| 动态模块无法加载 | 前端模块 HTTP、依赖与 Vite 缓存 | 修复对应依赖或缓存，重启前端并刷新 |
| 前端连不上 | 清单地址、进程、端口与启动日志 | offline 才尝试启动；冲突或 unreachable 先诊断 |
| PixelLab 输入框空白 | 查看已配置状态及数据目录 | 不先认定丢 Key，检查环境覆盖和原存储 |
| 地图重启后要输 Key | 是否只在页面临时填写 | 使用本机 .env 持久配置对应提供方 |
| 旧素材列表缺项 | 数据目录、来源服务、浏览器和分页 | 恢复正确范围，不先清空或重新生成 |
| 任务多于作品 | 是否含查询、检查、导出记录 | 用资产库按真实候选盘点 |
| 旧作品没有 Godot ZIP | 原导出是否早于新增格式 | 保留旧文件；需要时按门禁重新导出 |
| Godot 动画缺失或卡首帧 | 单动作覆盖、别名或每帧重启 | 合并动作并检查控制器触发逻辑 |
| 交互物靠近无响应 | 人物物理节点、group、layer/mask | 按通用包或 CopyWorms 接入约定核对 |

动态模块错误可能来自前端进程中断，也可能来自测试和开发服务共用依赖缓存造成旧引用；不能仅凭该错误判断“放久了后端自动关闭”。项目测试已使用独立缓存目录，维护时继续保留隔离规则。修复前端缓存不需要删除用户草稿和资产目录。

提供问题反馈时，说明从哪个页面进入、做了哪一步、实际与预期差异、是否能稳定复现。任务 ID、错误和日志按需补充并去除凭据；无需先整理整份 JSON。

## 随 Agent 执行展示当前步骤

升级后重启本机后台与 WorkBuddy MCP 连接，刷新已有工作台。执行时右下角显示当前作品与步骤，页面随原图、动画、交互物保存和导出切换；无需逐步说“打开”。暂停跟随或通过工作台导航手动离开时停止切换，继续跟随可恢复当前步骤。正在输入、工具忙碌或保存失败时保留原页面。关闭预览不会自动重开。页面到达不等于作品通过审核。

看不到当前地图时，先让 Agent 用 workbench_get_frontend_context 确认页面摘要；该摘要只提供名称/身份和编辑状态，完整地图仍需源包或 Godot 包。详见 [步骤跟随与验收](agent-preview-follow.md)。

## 内部素材联用

当前支持从资产库直接选择可复用源文件，及地图、交互物与场景之间的内部移送；无需下载后再上传。导入不生成、不增加后台任务，保留版本和源文件；具体入口、默认辅助显示和升级方式见 [内部素材导入](internal-imports.md)。

## 直接导出到游戏项目

地图、交互物和场景组装的“导出 Godot”会打开统一窗口。首次“选择项目…”在页面内浏览包含 project.godot 的游戏文件夹，点“使用这个项目”，或直接粘贴游戏根目录；导出后记住选择。点击“导出到此项目”，再在 WorkBuddy 说“接入刚导出的资源”。Agent 负责资源安装、场景挂载、动画合并和交互脚本连接，不需手动解压或改 res 路径。角色工作区和资产详情也有交付入口，只读取已导出的包。

“仅下载 ZIP”保留；新地图包无 project.godot，可直接解压到现有游戏根目录。等待 Agent、资源已安装、代码已接入及引擎已验收分别展示。网页不会自行启动一个关闭的 WorkBuddy 会话。详见 [完整交付流程](godot-delivery.md)。

### 角色像素颗粒

角色原图可选择 64×64（粗像素）或 128×128（精细像素，默认）。小角色优先检查原生 64 像素在游戏实际显示尺寸下的轮廓；移送保留原生尺寸。物品原图保持 128×128。角色 transfer 可用简短 identityDescription 锁定外观，源提示词完整保留。

### 地图工程卡预览

地图工程预览由浏览器随保存本地合成，最长边不超过 640 像素；仅展示参与输出的卡片，按现有分层与顶层规则合成，不显示网格、选中框或区域辅助线。预览以透明 PNG 作为工程附件，与当前源包版本一同持久保存，不新增图片资产；下载仍提供完整源工程。卡片按 16:9 等比显示并使用棋盘底，附地图块数与保存时间，点击预览继续编辑，详情可放大。视图切换、选择、缩放和平移不触发重绘。预览失败、缺失或旧工程无图时显示占位，源工程保存与下载不受影响，也不复用过期预览。旧工程在下次打开并保存时补齐。

## 清理资产库与恢复

在资产库勾选不再需要显示的素材，点击“移入回收站”，核对列表后确认。动画每个候选可单独选择，详情页也能移入。进入“回收站”后勾选素材，点击“恢复所选”即可回到资产库。切换范围会清空选择；跨页选择会保留并在确认窗口完整列出。

回收站保留源文件、制作记录和场景引用，不释放磁盘空间，也不提供永久删除。同一地图保存后仍保持回收站状态，恢复会显示最新工程。原工具仍能访问素材；来源离线时可以恢复目录状态，但恢复不能修复另行删除的源文件。

## WorkBuddy 新会话预览（MCP 0.11）

更新后重新连接本项目 MCP。正常的新会话应先自动打开内部浏览器，再提交生成；旧会话或其他浏览器的页面不算本次开页。若看到 preview_required，代表尚未创建任务、没有调用生图 API，Agent 应先执行宿主开页动作。页面连接后会自动追踪制作；用户暂停或关闭预览时不强制切换。无需重输 Key。宿主缺少开页工具时，Agent 必须明确说明，不能只给链接就宣称已打开。

### 更新 MCP 配置后找不到原生工具

如果新增了 `FORGE_MCP_HOST` 等环境变量，WorkBuddy 会把它视作配置变更，旧的信任记录不再匹配。到连接器/MCP 管理找到 `2d-game-workbench`，检查命令和参数后重新信任，再重连并新建项目会话。仅重启、检查配置未禁用、CLI doctor 成功，都不能证明原生工具已挂载。具体诊断和验收见 [Agent 客户端接入](agent-clients.md#配置存在但原生工具未挂载)。

### 序列帧导出到游戏项目

在角色美术的内嵌序列帧工具进入“4 · 导出”，导出 PNG + Godot 包成功后会打开统一项目选择窗口。选择或输入游戏根目录并点“导出到此项目”，再点“复制给 WorkBuddy”获取精确交付及动作接入请求。已有导出可通过“选择游戏项目并交付给 WorkBuddy”再次交付；路径会记住，仍可仅下载 ZIP。保持当前作业与候选一致；接入时只合并本次动作，保留其他动作与控制器。窗口不会自行启动 WorkBuddy，导出成功不代表脚本接好或引擎通过。独立 SpritePipeline 的 ZIP 下载保持可用。

### 已导出动画再次使用

作品库“导出”会恢复所选候选的 PNG、Godot 包和附加文件。播放检查中的已采用结果显示“已采用：返回导出”，只导航、不重复审批；手动进入导出页会刷新已采用列表。历史 PNG 若没有可用 Godot 包，会提示以新的文件名导出完整包，保留旧文件；重新打包仍遵守原有检查门槛，不会自动生成或跳过审核。旧页面已经出现的控件错误需刷新页面清除。

### 导入已有角色原图

`reference-art` 的 `import` 操作接受仓库内的 `sourceImagePath`、`prompt`（补充展示描述），以及名称、朝向、size（64/128）。只复制经过校验的透明 PNG；不调用模型，也不要求 PixelLab 服务或 Key。任务和结果记录导入来源、原始哈希、`generatedHere:false` 与 `promptOrigin:description-added-on-import`。原图历史显示“导入素材”，点击后恢复提示词并预览，可通过原有校验流程移送序列帧。移送需要本地序列帧服务，但不生成动画。不能把导入记录说成真实生图调用；不改图片、不倒填生成日期。

### Image 2.6 路线 A

生成评测会保留逐次用量与耗时。默认自动质量可能对不同请求选择不同档位；比较成本时应同时看输出尺寸、参考图、返回质量和token。公开价格计算的是估算，只有账单确认实付。失败但没有用量记录时费用未知。带蒙版的编辑现在由本地合成保留外部像素；蒙版内的形状与接缝仍需逐步检查。

透明物品默认清理Alpha=1的极淡噪点。已有图片可在预览点击“清理透明噪点（本地，无需额度）”，得到独立待采用版本；无须Key、不调用图片服务。原图和当前物件保持原样，确认后再采用。Agent可用process-image为旧编辑候选恢复蒙版外像素：候选、保护源图和蒙版必须同尺寸，只有蒙版完全透明处可变。有蒙版时清理也不能改变保护区，整图清理须另建版本作为后续源图。清理不补画缺失部件，不自动校正宝石形状或背景地面位置。

在地图原图面板生成背景，在交互物编辑器的 Image 2.6 面板生成透明物品。填写提示词，可补充参考图片；先预览完成结果，再选择采用。背景采用进入地图工程；物品采用绑定当前对象的默认图片，保留对象身份、交互行为与状态专用图片。生成任务关闭页面后仍由本机服务处理，重新打开精确任务链接可继续查看；超时或结果未知时先检查原任务，不反复点击生成。

也可以让 Agent 按授权完成这条流程。新图片会保留来源与内容哈希，采用不覆盖原图。透明物品经过真实 Alpha 检查，但轮廓、风格和缺失部件仍需看图确认。它不会自动生成碰撞和交互行为。当前不提供 Qwen 分层。

### 共享场景与交互物

场景和交互物页面会同步到本机共享工程，地址中的 document 标识可供 Agent 打开同一文档。页面显示同步状态；没有本地修改时可接收 Agent 的新版本。有未同步内容、网络问题或冲突时保留本地草稿，加载服务端版本会先保留本地备份。关闭前确认同步完成；浏览器草稿和服务端文档应分别备份。

Agent 可以读取已保存版本，调整实例位置、大小、翻转、顺序、素材、地图碰撞及交互行为，并返回对应版本的场景图片。图片观察不包含页面未保存的修改。导出的源包与 Godot 包仍需要实际引擎导入与游戏测试。新增功能的代码验收、模拟图片测试与真实生成效果分别记录。

在场景右侧的“物件联动”中，可设置“开关切换后，石门跟随开关状态”。先在石门物件中把两种状态分别设为显示/有碰撞和隐藏/无碰撞，再在场景选定来源、事件、目标与动作。预览会列出开关状态、可见性、碰撞、成功次数和最近联动事件；重置预览恢复初态。只隐藏图片不会关闭碰撞，停用交互也不会隐藏物件。删除物件会一并移除相关联动，撤销可恢复；复制物件不会自动复制联动。

Agent 可以检查失效接线、循环、预期事件与预期状态，再返回相同事件回放后的场景图片。此类模拟不包含人物行走物理；实际引擎验收需核对同一导出包的 Godot 版本、资源导入、真实碰撞和运行画面。详见[场景组装](scene-composer.md)。

### 指定引用的局部调整（7D）

选择单个场景物件后可指定默认、切换状态或序列静态槽，采用只改变该实例；共享原素材的其他实例保留原图。选择地图图层时，只有能与嵌入源包建立单源像素映射的层可写，采用同步 PNG 和源 ZIP。多图块或派生层使用“编辑地图源文件”。状态或来源变化后旧会话只供检查，不能强制覆盖。完整范围和恢复规则见[图片局部编辑](image-editing.md)。
