# 场景组装

入口：`/tools/scene-composer`，也可从“场景”制作页进入。仅面向正交侧视的 2D 平台跳跃场景。

## 分工

地图工具制作图片、分层和地图碰撞；交互物工具制作图片、动画、声音、范围及行为；场景组装负责导入、摆放、遮挡、替换、预览和整套导出。共享场景也支持 Agent 通过已声明的命令修改实例和地图碰撞。来源素材不会自动同步，场景不编排剧情。

## 创建与摆放

1. 新建并命名场景，选择本机地图记录，或导入地图状态 / Godot ZIP。
2. 地图工具中的“用于制作场景”会保存当前内容的完整快照，再打开新场景，不需要先下载地图包。
3. 添加交互物：从资产库、本机交互物项目或 JSON / ZIP 选择素材，勾选要加入素材栏的物件。选择/替换地图、打开场景也支持资产库；详见 [内部素材导入](internal-imports.md)。
4. 拖动素材到画布创建实例，也可点“放入地图”放到地图中心。
5. 框选或 Shift 多选，拖动、复制和调整遮挡。复制实例不会共享游戏中的完成状态。

快捷键：方向键移动 1 像素，Shift + 方向键移动 10 像素；Ctrl/Cmd + D 复制，Alt 拖动复制；Delete 删除；Ctrl/Cmd + Z 撤销，Shift + Ctrl/Cmd + Z 重做；0 适配地图；滚轮缩放；中键或空格 + 拖动平移。

默认以底部中心为摆放锚点。位置采用世界像素坐标，缩放与水平翻转作用于整个实例，包括碰撞和范围。改变锚点保持视觉位置不变。地图默认锁定，各视觉层共用地图偏移；解锁后移动地图会同步移动地图碰撞。

## 遮挡

右键支持置顶、置底、向前/向后一层、放到指定物件前后，以及放到玩家参考层前后。“场景节点”列表可拖动排序，属性栏可输入层级序号，1 在最前。所有操作使用同一顺序数据，导出使用相同顺序；多选调整保持组内顺序。

“放到……前/后”后，点击画布物件或节点列表选择参照物，Esc 取消。重叠处可通过右键的“选择”列表选择被遮住的物件。地图中烘焙的物件可通过“一键地图粗分”拆出，采用后即可在场景内独立排序。

节点眼睛只控制编辑时的隐藏；“参与导出”决定是否出现在预览和导出场景。遮挡不改变碰撞；点击交互优先选择绘制在前的合格物件。“玩家所在层”仅为参考及 ActorSlot 挂接约定，不附带正式人物。

## 手动替换

回原工具修改素材后，在场景中选择物件并点击“替换选中物件”。可以从场景已有素材、本机项目或文件选择新版。预览新旧素材后应用，只更新选中的未锁定实例，未选中的物件保持不变。

替换保留实例身份、名称、位置、比例、翻转和遮挡；图片、声音、动画、行为、碰撞和范围采用新素材，并以新素材底部中心对齐原摆放点。可用“选择使用相同素材的物件”进行批量替换。素材修改不回写来源项目。

地图替换保留物件世界坐标与尺寸。同源地图扩图保留原点；更换不同地图时，可点击新旧预览图选对应点，或输入对应坐标。尺寸、原点、图层和碰撞在应用前列出。地图范围外物件不会删除；底图后物件不会自动前移。替换作为一个撤销步骤，校验失败时原场景不变。

## 预览

拖动白色测试来源模拟靠近、离开；按物件配置的键或用“按键交互”触发；点击物件执行点击行为。外部请求物件可通过预览按钮模拟。支持文本、音效、动画、切换、拾取、序列与重叠焦点。

辅助显示默认全开，包含地图碰撞、物件感知、点击范围、实体碰撞、网格和名称。旧场景首次升级会全开；之后手动关闭的选项会保存。测试来源使用碰撞层 1，必须与物件感知 mask 相交。预览不模拟人物行走、跳跃或物理碰撞；临时状态在重置、退出预览时丢弃，不写回初始状态。

预览、候选制作与采用由同一编辑会话控制器协调。预览期间暂停远端内容替换，保留正在进行的对话、音效和模拟状态；退出后继续按共享版本检查接收修改。分层、改图、协作和默认导出先保存并取得确切共享版本，候选窗口期间冻结该内容守卫。

## 跨物件联动

右侧“物件联动”选择来源实例、事件、目标实例与动作。当前支持 `toggled`、`picked_up`、`sequence_advanced`、`interaction_finished`、`interaction_completed`、`state_changed`；动作是 `set_toggle`、`set_enabled`、`set_visible`。值可以是布尔值，或使用 toggle 来源的 `source_toggle` 跟随其开关状态。典型用法是“拉杆 toggled → 石门 set_toggle / source_toggle”，再把石门 A/B 外观分别配置为显示且有碰撞、隐藏且无碰撞。仅隐藏外观不会自动关闭碰撞；启停交互也不改变显示或碰撞。

联动使用稳定实例 ID，存于 `scene.links` 并随源包往返。删除实例会清除关联联动，撤销一起恢复；复制实例不自动复制接线；替换素材保留接线，但行为类型不兼容会拒绝提交。禁用联动保留配置。启用的两端必须参与导出；失效端点、重复 ID、事件/动作类型不匹配及有向循环会阻止保存。最多 256 条联动，每轮分发最多 256 次动作，超限会产生诊断而非无限执行。

预览显示每个实例的 A/B 状态、成功次数、可见性、交互启用与实体碰撞状态，并按时间显示联动事件。设置状态是幂等的：相同值不再次发出状态变化，目标不会凭空增加成功次数。来源反馈结束后按 FIFO 执行联动；重置预览会清空临时状态。

## 保存与恢复

- 自动保存 / Ctrl/Cmd + S：保留当前浏览器的 IndexedDB 草稿与制作记录；开始编辑后，另通过 Runtime Bridge 同步共享工程，界面分别显示本机与共享状态。
- 下载源文件：生成自包含 `.scene.zip`，用于备份和换机器编辑。
- 导出 Godot：先同步共享工程，再由 Runtime Bridge 导出该确切保存版本。共享冲突或离线会阻止默认导出；「更多」中的「导出本机草稿为 Godot」显式导出当前本机快照。

状态栏区分本机保存与文件备份；本机保存不代表已写入下载文件。保存失败时保留当前内存内容并显示源文件备份入口。不同场景独立保存；打开同身份源包时选择替换本机版本或另存为新场景。

“打开工程”同时保留本机记录、源文件和资产库，并提供“浏览服务端共享场景”。共享列表属于当前连接的本机 Runtime 服务，不是云端账号空间；读取全部服务端分页摘要后，可按名称或工程 ID 搜索并翻页，刷新读取最新列表。读取失败会显示错误，不作为空列表。打开使用 `?document=<id>` 和现有保存保护；如果目标在当前浏览器有未同步草稿，仍先保留本机内容并按原共享冲突流程处理，不直接覆盖。浏览器独有且未同步的草稿不会出现在该列表。

共享工程使用场景原有 `id`，每次成功提交增加 `revision`。网页与 MCP / CLI 共用同一个 Bridge 写入端。提交必须携带读取时的 `expectedRevision` 和唯一 `commandId`；版本过旧返回 HTTP 409 / `REVISION_CONFLICT`，不会覆盖其他页面的提交。重复的相同命令返回原提交结果，复用命令 ID 提交不同内容会被拒绝。网页轮询轻量版本摘要；本地有未同步内容或出现冲突时保留草稿，不用远端内容覆盖。加载远端前可保留本机恢复副本。

相机平移、缩放、网格和辅助显示属于个人视图，保存在本机草稿和下载源包中。网页共享保存及候选保护指纹将 `view` 归一为默认值，单独浏览视图不会提交共享版本，也不会让分层、改图或协作候选失效；接收远端或采用结果时保留当前本机视图。旧源包和服务端 `set-view` 命令保持兼容，但不会覆盖已打开页面的个人视图。

服务端工程保存在 manifest 的 `workspace.documentDirectory`（默认 `work/editor-documents/`），每次提交先写不可变快照，再原子更新版本指针。新快照只保存媒体 SHA-256 引用；图片、声音和地图 ZIP 在该文档命名空间的 `media/` 中不可变存储、按内容复用。新媒体入库时核对哈希、类型、图像解码和尺寸；引用入库媒体时仍检查槽位尺寸与生成来源。文件发生变化后重新校验，不以已有文件名代替完整性检查。来源文件后续变化不影响历史。

浏览器场景草稿、撤销历史和共享保存使用同一轻量引用，媒体 Blob 独立保存在 IndexedDB；预览使用已核验 Blob 的临时 URL。导入和读取边界处理媒体，位置、遮挡等普通编辑不反复序列化二进制。保存共享版本前先同步新增媒体；离线时保留本机草稿和已缓存媒体。下载源包、移送原工具及本机草稿导出时才还原自包含文件。旧内嵌草稿可迁移；未知保存按原参数与命令 ID 重放，不把引用替换进已发送请求。

旧内嵌不可变历史保持原文件和原哈希；按需读取为媒体引用不会改写历史。`workbench_restore_document` 把指定旧版本恢复为新版本，原历史保留。浏览器独有的旧草稿仍需先在原浏览器打开并成功同步，Agent 才能读取。

共享保存、分层、协作和局部改图共用 IndexedDB 原请求日志。请求发送前保存操作、目标、版本、完整参数和 `commandId`，取得回执后先保存回执，再完成结果接收；关闭标签页和响应丢失都可恢复原请求。不同页面不能用另一个操作覆盖未确认记录。协作旧 `sessionStorage` 与分层旧草稿记录先迁移成功再移除。服务端付费作业的原请求、上游 ID 和用量账本仍独立保留。

候选采用进入本机撤销历史。撤销或重做采用结果都先确认当前共享基线，再通过同一版本检查提交；已有远端新编辑时不覆盖它。普通编辑撤销仍可离线操作。远端替换会清空旧本机历史，防止把过时内容写回。

源包保存地图源数据、全部场景素材（包括未摆放的素材）、实例与稳定 ID、遮挡顺序和显示设置。二进制数据去重，包内引用不依赖原文件路径。上限为 256 MB 解压数据、2000 个实例、1000 个场景素材。撤销最多保留 60 步，不写入源包。

## Agent 编辑与视觉检查

需要多位专家规划并制作候选时，使用工具栏「场景协作」或 `workbench_create_scene_workflow`。它从已保存场景开始，在独立候选中复用或生成物件、创建或扩展地图、配置联动及局部改图；新生成与地图制作需要单独授权额度和范围。系统结合实际图片、接缝放大图和事件回放复核，最后按原场景版本采用。空场景也可启动。角色、额度、恢复与工具契约见[场景专家协作](scene-collaboration.md)。单次精确编辑仍使用下面的共享文档命令。

`workbench_list_documents` 发现共享场景，`workbench_get_document` 读取当前内容或指定 `revision`；`viewPath` 使用 `?document=<id>` 打开同一工程。`metadataOnly=true` 只返回版本、名称和内容哈希，适合轮询。HTTP 对应 `/api/workbench/documents` 与 `/api/workbench/documents/<id>`；CLI 使用 `agent documents`、`agent document-get` 等同名操作。

HTTP 文档接口可通过查询参数 `media=references` 请求轻量媒体表示；默认仍返回内嵌媒体以兼容已有 Agent 和制作链。该表示参数不改变提交参数或命令身份。`contentHash` 始终标识保存版本的存储内容，不能用展开媒体后的响应 JSON 重新计算它。媒体引用形如 `/api/workbench/document-media/<sha256>.<ext>`，对应 Bridge `/v1/document-media/<key>` 的 GET / HEAD / PUT；上传按路径哈希与声明类型校验。候选文档媒体位于私有命名空间，普通媒体路由不读取该目录。

修改使用 `workbench_apply_document_commands`，输入为 `{documentId, expectedRevision, commandId, commands}`。一个事务最多 100 条命令，只影响一个文档，任何一条失败都不提交：

| 范围 | 已支持的 `type` |
| --- | --- |
| 名称与视图 | `rename`、`set-view` |
| 素材与实例 | `import-material`、`replace-material`、`add-instance`、`replace-instances`、`remove-instances` |
| 位置与遮挡 | `move-instances`、`scale-instances`、`flip-instances`、`set-anchor`、`reorder`、`set-node-flags` |
| 地图 | `replace-map`、`move-map`、`set-map-collisions` |
| 联动 | `set-links`、`add-link`、`update-link`、`remove-links` |

命令依据稳定 ID 选择节点，参数以 `lib/workbench/document-contract.mjs` 和 MCP 实际 schema 为准。移动只能选择 `dx/dy` 或 `x/y` 一种方式。变换、删除、替换实例及移动其排序前需显式解锁；命令与 AI 快照使用同一领域锁校验，也不能通过替换共享素材间接改写锁定实例。快照不得改变锁定实例、地图层或分层物件与仍存在节点的前后关系；需要让未锁定节点跨过锁定节点时，使用明确选中未锁定节点的排序命令。快照不能同时解锁并修改受保护内容；类型化事务可先显式解锁，再执行后续命令。前端人工保存仍支持其既有完整快照流程。场景素材替换不会修改来源项目；`replace-material` 保留实例锚点，`replace-instances` 按新素材重设锚点。

`workbench_adopt_document_image` 采用已完成的 `image-assets` 背景任务，必须提供原 `sourceTaskId`、PNG `sha256` 和版本检查字段。服务重新校验任务、文件与尺寸后，替换为一个背景层并保留可回导的地图源 ZIP；原任务不会变化。采用不会从画面猜测碰撞。`set-map-collisions` 可明确提交地图源世界坐标多边形，统一地图偏移在显示与导出时叠加；它不触发地图生成、拼接或扩图。

场景碰撞编辑保存为显式覆盖：`map.collisions` 是实际显示与导出的多边形，`map.collisionOverride.sourceCollisions` 保留内嵌地图源包的碰撞基线。命令、网页编辑和共享快照保存共用该规则；恢复到源碰撞时移除覆盖。局部改图和扩图校验源碰撞基线及实际像素、几何、来源身份，继续保留场景覆盖和原源包数据；修改碰撞本身不会使合法地图失去改图或扩图能力。

`workbench_observe_document` 渲染确切保存版本，可指定世界坐标 `region`、`time`、`mode` 和输出尺寸。默认 `mode=export` 按参与导出标记绘制；`mode=editor` 按编辑隐藏标记绘制。返回场景 PNG、可选标注 PNG、世界到图片的坐标变换、物件范围和资源哈希。MCP 直接附带图片块，结构化结果只保留图片元数据与实际产物路径。缺少本次渲染所需的图片时失败，不返回完整成功的观察证据。观察不读取浏览器未保存内容，也不证明 Godot 已运行。

`workbench_validate_document` 检查结构、媒体和场景诊断。`workbench_simulate_document` 复用交互模拟器，最多接收 200 个 `move-actor`、`tick`、`press`、`click`、`request`、`advance-text`、`finish-audio` 或 `cancel` 事件，返回按时间排列的事件、最终状态、联动诊断及 `expectEvents` / `expectStates` 检查。`expectStates` 按 instanceId 断言 toggleState、completed、enabled、visible、solidEnabled、sequenceIndex 或 successCount；回放截断或联动诊断会令 passed=false。未提供任何期望时的 passed=true 只表示该请求完成。检查不改变文档，不验证人物物理、可达性或实际游戏存档。

`workbench_observe_document` 可接收同一套 `events`，返回回放后的真实 PNG、状态与事件证据。`events` 与静态 `time` 不能同时提供；要推进回放时间，加入 `tick`。所有回放从指定保存版本的初始状态重新开始，`events: []` 明确观察初态。图片和辅助碰撞层使用同一模拟结果；回放不完整时拒绝生成完整观察证据。

## Godot 交付

导出目标为 Godot 4.7.x。包包含 `scenes/<scene-id>/scene.tscn`、地图图像与碰撞、独立物件资源、`scene-source.zip`、实例名称清单和接入说明。场景入口节点是 `Scene`，物件节点使用稳定 ID；名称在清单中保留。

所有场景共用 `addons/workbench_interaction/runtime/v1/`，避免重复注册 GDScript 类；每个场景有一个交互运行时。地图和物件资源按场景隔离，不因导入另一场景而替换已有定义。保持运行时版本一致。

有联动的场景附带 `scene_link_router.gd` 与稳定 ID 配置，连接现有交互运行时，不新增第二套交互系统。运行时提供幂等状态设置、state_changed 信号、按序分发与卸载断开连接；场景重入不会重复注册。自定义游戏逻辑仍在生成目录之外。

将人物放到 `ActorSlot` 下并保持其相对 Z 为 0，或者使用接入说明中的排序值；靠近交互的物理节点加入 `interaction_actor` group，碰撞层与物件 detection mask 对应。默认按 E，物件可以使用自身配置的按键。剧情、背包和复杂逻辑通过原有物件信号接入。

不输出 `project.godot`、正式人物、EditorPlugin 或 `.godot` 缓存。重新导出更新该场景生成目录，自定义脚本应放在外层场景或独立文件中。Godot 包可在工作台重新打开其嵌入源包，不反向解析手改的脚本和节点。

本机产物在 `outputs/scene-export-<id>/`，包含 `scene-godot.zip` 和 `scene-source.zip`；导出记录在 `work/scene-exports/`。它们是独立导出记录，不创建图片生产任务。`workbench_export_document` 需要明确的 `{documentId, revision}`，使用该保存版本的同一个导出器，并记录文档版本与 `documentContentHash`。每次调用建立新的导出记录，不修改共享场景。

网页默认与 Agent 导出使用相同共享身份。每份新导出记录的 `source.kind` 明确为 `shared-document` 或 `local-snapshot`；共享来源记录 `documentId / documentRevision / documentContentHash`，草稿来源记录 `localRevision`，两者都有展开后场景的 `snapshotHash`。源包内的 `scene-provenance.json` 和 Godot 包内的 `scene-manifest.json` 保留同一来源；导出记录与 Godot 清单还保存源 ZIP 的 `sourcePackageSha256`。导出成功仍标记 `engineValidated=false`，不会冒充目标游戏验收。

成功导出后会被资产库的“完整场景”分类收录。每次导出保留独立版本，可查看名称、版本和实例数量，下载原始源包及 Godot 包；旧导出记录也能读取。归档制作历史不会移除这些资产。共享工程另有继续编辑入口，与已导出的独立版本区分；下载源文件本身不创建导出记录。目录路径由 manifest 定义，测试使用隔离路径。

## 实现边界与验证

入口仍注册于 Manifest 的 `editorModules`，不作为图片生产任务能力。共享文档工具独立登记在 MCP；网页共享文档请求、MCP 与 CLI 均由 Bridge 统一写入。原有 `/api/workbench/scene-composer/export` 与源包流程继续可用，新增 `/documents/<id>/export` 导出指定保存版本。部署网页不能替代本机运行时。地图生成与拼接仍使用地图前端。

场景模型、包格式、坐标变换、排序与 Godot 装配位于 `features/scene-composer/`。交互行为复用既有 InteractionSimulation 和 Workbench Interaction Kit。

运行 `npm run test:scene-composer` 检查替换隔离、排序、坐标、源包、安全路径、预览状态及资源引用；`npm run test:editor-documents` 检查共享版本、事务、幂等、路径边界、模拟与 MCP 视觉产物，以及会话保护、采用撤销、持久请求恢复、媒体完整性与去重、旧历史兼容和导出来源。`node tests/scene-split/browser.mjs` 以隔离 Chromium 检查实际预览保护、采用撤销/重做及媒体缓存恢复。相关回归为 `test:workbench-shell`、`test:map-stitcher`、`test:interactable`、`test:http`、`lint`、`typecheck`、`build`。使用 `npm run test:scene-composer -- --write-engine-fixture` 可在 outputs 下生成隔离 Godot 检查项目。

`npm run test:scene-links` 检查接线、循环、幂等、事件顺序与前端配置；`test:scene-observation` 校验回放后的实际像素和碰撞辅助状态。设置 `GODOT_47_BIN` 后运行 `npm run test:scene-links-engine -- --input <scene-godot.zip> --source switch --target gate --rendered`，在工作区新建隔离项目验证真实 Godot 4.7 的导入、物理点查询、开关门、重入与渲染截图；省略 input 使用明确标记的 fixture。未配置引擎会报错，不算通过。此脚本针对恰好两个 toggle 实例的开关门验收场景，不是任意完整游戏的验收器。

## 导出到已建立的游戏

点击“导出 Godot”后选择游戏项目，包保存到其 forge_imports 收件目录；让 WorkBuddy 按 [Godot 交付流程](godot-delivery.md)继续检查、安装、挂载玩家并接好信号。用户无需再手动复制目录或调整 res 路径。“仅下载 ZIP”仍提供原有手动导入方式。编辑辅助开关不改变已导出的真实碰撞。

## 场景地图整图分层

在包含地图的场景中点击“一键地图粗分”。页面会先保存场景。单图和拼接图都使用该版本已合成的地图像素，保留世界原点和地图偏移。场景里另行摆放的角色和物件独立于分层输入。已有候选可从“分层候选 / 恢复”打开。

1. 一键粗分优先用本机 SAM 2.1 Tiny 扫描最长边 1024 像素的地图概览。宽阔、密集且接触上下边界的候选可建议为背景或地表。其余候选可能包括碎片和相邻物件。结果标注“未经核验”，可交给 Agent 在原图上检查。缺少本机运行环境或权重时，页面显示缺项并改用图层 Alpha 或颜色连通片。安装命令是 `npm run visual-structure:setup`。如需用已配置的视觉服务先辨认物件，可选择“视觉定位 + 本地 SAM（1 次视觉调用）”。
2. Agent 可以读取同一候选的整图、原比例裁片、独立物件及像素归属蒙版，调用修订接口补拆、合并、修边、划分背景与地表。跨卡片的同一对象用一个稳定 ID 管理多个绘制片。物件前后片分别相对玩家绘制。效果片可与物件一同移动并单独关闭。扣下可见物件的位置允许留透明洞，边缘可在深浅和彩色底上比较。
3. 采用后可移动、隐藏和锁定分层节点，编辑单张纹理、效果与碰撞。碰撞初始关闭。Agent 可以直接给出树干、桥面等阻挡轮廓。缺少这种标注时，本地工具按主体下缘的支撑范围给出可调整的建议。把归属明确的旧地图碰撞转给物件后，移动或删除物件会同时移动或删除这份阻挡。显式解除归属会把阻挡还给地图。核验记录绑定所检查的对象和候选版本。
4. 更换地图会保留旧分层与编辑基线，由新候选自动匹配并迁移兼容修改。相对位移叠加到新版位置。世界固定模式保留原世界坐标。匹配歧义和同一内容的冲突可分别查看、指定对应对象或裁决。采用时再次核对文档版本。回复丢失后使用原命令和原参数恢复。
5. 从场景组装导出，Godot 中每个完整物件拥有独立节点，携带绘制片和物理子节点。场景源包和 Godot 包内的场景源都保存分层身份、图像、碰撞及迁移基线，重开后仍可编辑。

SAM 修订在后台执行，页面保留原请求并查询完成状态；临时查询失败会退避重试，连续失败后可用“恢复上次请求”继续查询。视觉定位成功后会先保存物件框和提示点，本机分割失败时也可恢复原请求继续本地阶段。换图时保留当前碰撞轮廓不会自动接管新图的同号碰撞区域。未采用分层的旧场景继续导出原有 `InteractionRuntime` 节点和资源。

高层工具与 CLI/HTTP 操作见 [Agent 工具索引](agent-client-tools.md#场景地图分层)。纯视觉物件、背景与地表绘制片可使用共享图片编辑器。局部修改的目标类型为 `scene-split-part`，由 `documentId + elementId + partId` 定位。大层可加 `window:{x,y,width,height}` 指定绘制片内部的原像素窗口，采用只写这个窗口。地图工程的源层编辑和可逆映射检查仍使用其原有目标类型。

### 指定引用的局部调整（7D）

选择单个场景物件后可指定默认、切换状态或序列静态槽，采用只改变该实例；共享原素材的其他实例保留原图。选择地图图层时，须对场景中全部地图层验证嵌入源包的单源像素映射，包括隐藏或不参与导出的层；选中层和源图片类型锁均须解除。通过后采用同步 PNG 和源 ZIP。多图块、派生层、缺失或不一致来源保持只读，可从“编辑地图源文件”入口继续处理；缺失或损坏的源包不保证能够恢复。槽位或来源变化导致当前 guard 失效时，旧会话只供检查，不能强制覆盖；本会话已知采用绑定的单图恢复仍需当前版本校验。完整范围和恢复规则见[图片局部编辑](image-editing.md)。

AI 局部调整默认开启“保留原图透明度”，以当前选择的编辑基准保持 Alpha；要改变轮廓时关闭。恢复后上下文直接切换为已核验原图，继续精修建立的新会话及候选选择会同步到地址栏。链接保留场景身份，不把新会话留在旧候选地址。
