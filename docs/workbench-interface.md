# 工作台界面与制作流程

开放动作 v3 保持五阶段结构，在“自动制作”内显示当前分段检查卡：完整片段播放器、逐帧条、实际末姿势、目标与检查结论默认可见；模型细节和“不合格”操作按需展开。一次只有“确认此段，继续制作”这个主要推进按钮。完整播放、明确检查与结论完成后才可确认；模型意见未通过时还需明确裁决。刷新保留进度，确认锁定真实末帧，全部片段确认后进入完整动画检查。

角色动作的模型设置分别显示默认规划与视觉复核型号；服务状态和空白 Key 输入区默认展开，已保存凭据只显示来源与状态。新增型号、单专家覆盖与高级参数按需展开，保存按钮保持可达。方案页的动作约束与关键姿势默认收起；检查页默认显示视觉报告结论与帧证据，模型意见不能替代实际播放。播放确认绑定当前帧摘要，外部改帧后必须重新确认；视觉请求未结束时不能预先确认其提醒。

外层工作台通过并列的角色制作与交互物入口组织资产生产。角色动画采用五阶段 React 主流程，交互物保留原有编辑方式；交互物的状态动画目前借用角色动画页制作，独立面板见[交互物动画独立面板方案](交互物动画独立面板方案.md)。它是外部 Agent 的可视协作面：展示真实任务、进度和产物，并承载画布、图层、碰撞区等不适合纯对话操作的内容；页面不提供通用 Agent 对话框。

界面使用纯色背景（网格只出现在画布与预览区）和明确的角色美术/交互物色彩语义，不使用英文装饰眉标或仿 macOS 的窗口装饰。颜色、圆角（三档）、字号（六档）和控件高度来自 `lib/workbench/theme-palette.json` 生成的主题变量与 `app/globals.css` 中的 `--ui-*` 刻度；下拉统一使用 `components/ui/native-select.tsx`。中文操作名优先，协议参数集中到工具内部或高级页。界面按 1100 像素以上的桌面宽度设计，更窄时显示提示；样式断点只有 ≤1099px 与 ≤700px 两档。

## 入口与流程

| 页面 | 功能 |
| --- | --- |
| `/` | 工作台首页：三个工具卡（角色原图、角色动画、交互物编辑）、继续制作（最近 5 条记录）、最近素材，以及导入素材包 |
| `/player` | 重定向到首页；保留路由供旧链接和制作线入口使用 |
| `/tools/reference-art` | 角色原图：输入描述 → 生成像素原图 → 移送为动画参考图 |
| `/tools/sprite-generator` | 角色动画：准备与描述 → 查看制作方案 → 自动制作 → 检查与调整 → 导出与使用；“已有对象”同时列出角色与交互物，交互物状态动画也在此制作；旧版 `?legacy=1` |
| `/tools/interactable-editor` | 交互物编辑：按项目与对象定位恢复 |
| `/assets` | 分页查找持久资产、精确候选详情及下载真实素材 ZIP |
| `/advanced` | 服务连接、制作记录、游戏交付历史和本机数据；不承担 Agent 对话 |

所有页面共用同一个顶栏，结构不随页面变化：左侧是 Forge 标识（返回首页）和主导航“角色原图、角色动画、交互物编辑、资产库”，当前页加粗并在顶栏下沿显示强调色下划线；右侧是“制作记录”和三个图标按钮（帮助、工作台管理、深浅色切换），图标按钮均有悬停提示。“制作记录”角标在有待处理项时显示警示色数字，只有制作中的任务时显示一个脉冲圆点，状态连接中断时显示“!”；悬停提示写明“需要处理 N 项 · 制作中 N 项”。点击导航后，被点的项保持按下状态，顶栏下沿出现进度条，直到新页面开始加载；离开前的保存检查失败时进度条消失并显示错误。当前作品名和“返回来源资产”不在顶栏，而在各工具自己的工具栏：交互物编辑器在项目名输入框之后，角色动画在步骤条行首（作品名由页面通过 `setPageTitle` 提供），角色原图在页面标题右侧。编辑器只在外壳内增加自己的第二行：交互物为工具栏，角色动画为作品名、步骤条与“最近动作”“模型设置”。动作的旧深链保留原身份和参数。

所有跳转使用 `WorkbenchProvider.navigate`；原有链接由 Provider 捕获并经过同一保存与冲突检查。从资产库进入工具时保留 `returnTo`，上下文的“返回来源资产”恢复原筛选、分页和所选素材；该目标仅接受同站 `/assets` 路径。

工具内的视图、图层、生成、预览、导入和导出继续沿用现有操作。“导入 Forge 素材包”表示本地文件入库，“从资产库选用”表示复用已有素材，“打开工程”表示源工程恢复。交互物工具栏只保留一个主按钮“导出 Godot”；“打开”菜单含打开工程与从资产库选用，“保存”菜单在每项下说明去向：保存草稿（当前浏览器 IndexedDB，编辑时也自动保存）、保存到资产库（本机服务 `save-project` 记录，可被其他工具选用，不导出 Godot）、下载源文件（工程 JSON）。交互物独立导出为资源包，安装与游戏脚本接线由后续交付流程完成。

## 新手引导

首页本身就是目标选择：三个工具卡并排，整张卡可点击，预览图取资产库中对应类型最新的一件（角色原图取角色，角色动画取动画，交互物编辑取交互物或物品原图），没有时显示内置示例像素图。下方“继续制作”按需要处理、制作中、编辑中、已保存、已完成的顺序列出最近 5 条记录，“全部记录”打开制作记录；“最近素材”列出资产库最新 6 件，资产库为空时不显示。右上角“导入素材包”进入 `/assets?import=package`。记录名称是生成的任务编号时，显示工具名代替，完整名称保留在悬停提示中。首页不再弹出引导窗口，旧的 `workbench.onboarding.v1` 偏好不再读取。

“帮助”优先显示当前工具说明、可执行的下一步和当前保存状态；并区分浏览器本机草稿、本机服务保存的共享工程与动作任务、资产库素材、Godot 导出快照。保存位置说明收在“数据保存在哪里”折叠项中；首页之外的页面在帮助底部提供“回到首页”。资产库没有素材时只显示一句说明和导入按钮；工具空白状态同时说明可从何处开始。

引导不会创建项目、提交生成或调用收费图片接口。

## 制作记录

记录以具体资产为单位：某个角色动作、一张物品原图、一个交互物。全局浮层称“制作记录”，动作页局部列表称“最近动作”，管理页称“全部制作记录”。顶栏“制作记录”按钮或首页“全部记录”打开浮层，用分段控件切换制作中与已完成，右上角图标按钮刷新，底部链接到“管理本机数据”；提供恢复入口与存在于任务记录中的产物下载；服务断连时浮层内提示并链接到服务状态。记录状态用带底色的标签显示。名称是生成的任务编号时显示工具名；适配器错误（`Adapter returned HTTP …`）显示为中文短句，原文保留在悬停提示中。

| 数据来源 | 标识与恢复方式 |
| --- | --- |
| 交互物本机草稿 | `interactable:<projectId>:<definitionId>`；`?project=&object=` 恢复对应项目并选中对象 |
| 序列帧作业 | `sprite:<jobId>`；`?job=` 交由原生工具打开已有作业 |
| 开放动作作品 | `motion:<openWorkId>`；`?work=` 打开当前作品，精确执行/旧版本链接带 `version`；方案与原生 job 按作品身份合并 |
| 后台执行记录 | 按已知作业或对象身份合并尝试与产物；无法关联本机草稿的记录进入高级任务详情 |

`prepared` 和 `awaiting_configuration` 明确显示尚未执行或等待配置。序列帧 `created` 表示作业保存、`review_required` 表示等待检查、`approved` 表示可导出，只有 `exported` 才表示完成。未知服务状态显示需要处理。服务断连时保留上次读取的状态，并提示连接中断；不会补造进度百分比。

后台记录与原生作业在有任务制作中时每 6 秒刷新，没有进行中的任务时每 30 秒刷新；标签页隐藏时暂停，回到页面立即刷新一次。任务列表请求带上次的 `revision`（`/api/workbench/tasks?since=`），历史未变化时服务只返回 `unchanged`，不重复传输记录；旧版 runtime 忽略该参数并返回完整页。刷新只查询已有作业，不重新发起生成。页面跟随在有待展示步骤时每 1.5 秒、空闲时每 3 秒、隐藏时每 8 秒报告一次（服务端页面有效期 20 秒）。测试 fixture 与诊断作业不进入原生资产列表。

## 保存与恢复

交互物保存到 IndexedDB `workbench-production-v1` 的 `drafts` 与 `items` 两个存储区。草稿内容、制作记录及交互物当前项目指针在同一事务中提交，写入成功才标记保存。不同交互物项目分别保存。

- 交互物约在修改后 700 毫秒自动保存，一个项目中的每个对象对应一条制作记录。旧版 `workbench-interactable-editor` 的当前草稿可以读取并迁移；原旧数据不删除。
- 外层导航先等待保存完成。保存失败时留在当前页并展示错误；交互物正在导入或导出时阻止切换，项目导入也先保存当前工作。
- 交互物工具栏“保存 › 保存草稿”允许手动重试。关闭或刷新存在未保存修改、仍在进行操作的页面时使用浏览器原生离开提示。源文件备份继续使用各工具的原有导出。
- 序列帧作业由 Python 服务保存。网页通过只读汇总接口读取摘要，恢复链接只选择已有作业，不创建或重跑。工具内部尚未提交的表单仍遵循原生工具的行为。

草稿属于当前浏览器与网站地址；更换浏览器、清理网站数据或切换地址不会自动携带草稿。共享任务仍位于 `work/tasks/`，Agent 产物仍位于 `outputs/`。浏览器草稿不伪装成这些磁盘文件。

## 实现位置与扩展

`workbench/manifest.json` 是路线与能力的唯一清单，`productionLines` 定义顶级入口，能力 `ui` 提供路线归属、入口说明和步骤。页面不直接导入完整清单（含全部输入 schema）：`lib/workbench/ui-manifest.json` 只保留品牌、导航、模块与路由，由 `lib/workbench/ui-manifest.mjs` 生成，构建与开发服务启动时自动同步，也可运行 `npm run ui-manifest:sync`，`npm run ui-manifest:check` 与 `test:workbench-shell` 校验其未过期。`lib/workbench/modules.ts` 从中派生前端数据；`lib/workbench/navigation.ts` 组织共享导航分组、当前页和安全来源返回目标。制作工具的 `name`、`shortName` 与 `entryTitle` 使用同一页面名称，操作按钮另用动作文案。

- `components/workbench/`：首页（含内置示例像素图）、常驻外壳、记录、高级工具和样式。
- `app/interaction.css`、`components/ui/`：共享交互状态（过渡、按下、选中、禁用、`aria-busy` 加载、焦点、三级阴影）、复选框与 `ui-switch` 开关、`ui-segmented` 分段控件，以及 `toast.tsx`、`tooltip.tsx`。新控件优先使用这些类与组件，不在模块样式里另写一套状态。
- `components/workbench/shared-navigation.tsx`：唯一顶栏、制作记录角标和供工具栏使用的来源返回链接。
- `components/workbench/workbench-help.tsx`：当前工具帮助。
- `components/workbench/lazy-dialogs.tsx`、`godot-export-host.tsx`、`components/image-edit/lazy-image-edit-workspace.tsx`：素材选择、素材包导入、Godot 导出和局部调整在首次打开时才加载。大型编辑器通过 `useWorkbenchActions()` 只读取稳定回调，不随状态轮询重渲染。
- `lib/workbench/work-items.ts`：状态归一化、稳定资产身份和执行尝试合并。
- `lib/workbench/browser-store.ts`：草稿与制作记录的原子保存。
- `lib/workbench/editor-session.ts`：当前编辑会话、离开检查和保存同步。
- `features/interactable-editor/browser-storage.ts`：交互物多项目保存和旧草稿兼容读取。
- `app/api/workbench/sprite-pipeline/jobs/route.ts`：原生作业摘要白名单，不向浏览器暴露连接器令牌。
- `Tools/SpritePipeline/sprite_pipeline/ui.py`：`workbench_job` 恢复入口与选中作业通知。已运行的 Python UI 需重新启动以加载源代码变化。

公共 Provider 在浏览器宿主支持 `document.modelContext` 时注册 `list_workbench_capabilities` 与 `start_workbench_task`。页面能力不替代仓库级 STDIO MCP；MCP/CLI 继续使用共享运行时，算法留在工具实现、适配器或服务端连接器。

## 本地与托管边界

Web 的同源 API 通过 `WORKBENCH_RUNTIME_URL` 访问默认位于 `127.0.0.1:8790` 的 runtime bridge。托管页面无法自然读取开发者电脑上的回环服务、任务目录或另一 origin 的 IndexedDB。远程使用需要单独部署经过认证和访问控制的 runtime；只发布界面不会让本地能力自动上线。

## 验证

常规验证：`npm run lint`、`npm run typecheck`、`npm run build`。

外壳回归：`npm run test:workbench-shell`，覆盖共享名称与分组、兼容路线、资产来源返回校验、状态真实性、执行尝试去重、本机恢复链接优先、保存失败及繁忙操作的离开保护。`node tests/workbench-shell/navigation-server.mjs` 启动独立浏览器验收页面，复用实际 Provider 和导航组件、模拟所有服务响应，可检查键盘焦点、当前工具帮助、首页入口，以及保存失败、导入中、版本冲突的离开保护。交互物与 MCP 检查使用保留的测试入口。

共享工程回归并入 `test:editor-documents`；结构历史与外观约束回归并入 `test:open-motion`；精确交付查询与分页回归并入 `test:game-export`。浏览器隔离夹具分别由 `tests/editor-documents/library-server.mjs`、`tests/authoring-gaps/web-server.mjs`、`tests/image-assets/dimensions-server.mjs` 和 `tests/game-export/history-server.mjs` 启动，打印可访问地址；使用真实组件与测试响应，不调用付费生成或修改正式素材。

完整测试矩阵见 [使用与操作手册](operations-manual.md)，整体分层见 [系统架构](architecture.md)。

## 对象选择与兼容

开放动作准备页使用“已有对象”，选项显示角色/交互物类型和像素尺寸，类型来自已有预设。角色显示朝向，交互物不添加朝向或持武器的手。上传区叫“上传角色原图”，仍只上传 64×64 / 128×128 角色 PNG，没有交互物上传或自由切换类型入口。128×128 PixelLab 物品图通过[移送入口](prop-art.md#旧-pixellab-流程)成为交互物预设；交互物合同与状态链接续已接通，确认的状态图与过渡可写回切换槽或序列条目。`?object=` 可定位已有对象，旧 `?character=` 和 character_id 草稿保持兼容。工程验收与真实生成效果的边界见[当前进度](论文方向与方法.md#5-进度)。

## 原图与序列帧路线

首页直接进入角色原图或角色动画；旧的 `/player` 总览页已重定向到首页。`/tools/reference-art` 提供描述、朝向、PixelLab Key 设置、真实任务进度与 PNG 预览。Key 与动画共用，生成操作进入 runtime ledger；`?task=` 可恢复原图记录。移送成功后进入动画的 `?character=` 链接并预选角色，尚未创建动画任务。未提交的原图提示词只保留在当前页面；生成后的提示词、名称和朝向随任务保存。
