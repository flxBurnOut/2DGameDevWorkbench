# 交互物动画面板说明

> 路由：`/tools/interactable-motion`（在 `workbench/manifest.json` 登记为 `editorModules` 中的 `interactable-motion`，与角色动画共用 `sprite-generator` 开放动作作品数据）。

本面板面向开关、拉杆、宝箱、指示灯等交互物的状态动画制作、检查、修正与槽位写回；物件的行为、触发、文本、音效与碰撞仍在[交互物编辑器](interactable-editor.md)中配置。

## 1. 界面布局与四阶段流程

`object_type=interactable` 的作品默认在本面板打开（角色动画页的对象下拉只列角色，加 `&layout=studio` 可在角色页查看同一作品）。支持 `?work=<openWorkId>`、`?object=<id>`、`?document=<id>&definition=<definitionId>` 恢复上下文。

- **顶栏工具条**：作品名、版本、“最近作品”“模型设置”，以及四个阶段切换：**定义状态 → 制定方案 → 制作与检查 → 写回**。下方对象条显示对象来源与绑定的交互物工程。
- **左栏（只读状态图）**：展示状态节点（首节点为原图，线性链最多 5 个状态 / 4 段过渡）、帧数与各段状态标签；开始制作前可点“修改”回到状态编辑。
- **中栏（随阶段切换）**：
  - *定义状态*：状态卡片编辑器（各状态名称、外观、可选目标图与整段设置，部件结构折叠在下方）；
  - *制定方案*：分段方案与交互物合同核对；
  - *制作与检查*：待确认段的方形画布播放器与逐帧检查；
  - *过渡画布*：已保存过渡的帧条、原版/备选同步播放、叠加检查层图例与局部调整入口。
- **右栏（四个页签）**：**要求**（合同字段）、**检查**（复核结论、叠加层开关、人工结论）、**工具**（专用帧工具与选帧修改）、**写回**（逐槽映射、场景模拟预览与 Godot 导出）。开始制作前“检查”和“工具”不可用；逐帧工具仅对待确认段或通过技术检查的完整候选开放。
- **底部状态栏**：显示当前缺失项与唯一主操作按钮（完整候选有技术阻断时提示不可采用/导出，但已确认状态图与已接受过渡仍可写回）。

## 2. 端到端使用路径

1. **进入与准备原图**：从交互物编辑器切换/序列物件点 **制作状态动画** 会先保存工程再带上下文进入。缺少 128 px 物品原图时，可直接在面板内生成 PixelLab 物品图、导入 128 px PNG 或经 `PixelProp` 转换大图并移送（见[物品原图导入与转换](prop-art.md#导入与转换为动画原图)）。
2. **定义状态骨架**：切换物件默认带 A → B 两态，序列物件按条目生成节点。铰接与形变动作先在“部件结构”选择已核对结构。
3. **规划与分段检查**：通过 `plan-motion`（带 `motionSpec.interactable_skeleton`）制定方案，本机校验强制段数等于相邻状态对数；每段生成后逐帧检查，可先单独锁定状态帧（`accept_state`）再裁决整段过渡（`accept` / `reject`）。
4. **修正与派生**：在“工具”页签执行确定性修正、生成式选帧修改或创建派生素材。
5. **写回与预览**：在“写回”页签把状态图与过渡映射到切换 A/B 或序列条目，一次事务提交 `import-motion-asset`（支持逐帧相对时长与往返播放），并用内置交互物模拟器预览“触发 → 播放过渡 → 停在新状态”。

## 3. 交互物专用编辑工具（`T1–T10`）

所有工具均遵守以下保护规则：不改动已锁定状态图、接续边界与停留帧；确定性工具不消耗绘图次数；结果先保存为备选或待确认派生，完整播放并写明结论（≥ 4 字）后才正式采用或入库。

| 编号 | 工具 | 用途与做法 | 提交方式 |
| --- | --- | --- | --- |
| T1 | 固定部件回填 | 将原图固定区像素逐帧回填到可编辑帧，自动跳过已核对结构运动部件、手工标记不回填区及通道差 ≥ 64 的运动像素 | 前端精确 PNG 编解码计算，经 `local-frame-edits` 存为备选 |
| T2 | 叠加检查层 | 在画布叠加固定监测区、逐帧变化热区、枢轴点与铰接半径圆、洋葱皮与首尾接缝 | 只读视图 |
| T3 | 对齐校正 | 以固定部件包围盒/质心检测 1–2 px 帧间漂移，执行整数像素平移（跳过会裁切可见边缘像素的位移） | 前端计算，经 `local-frame-edits` 提交 |
| T4 | 批量清理 | 将擦除、Alpha 清理或像素补丁批量应用到选中帧范围 | 前端计算，经 `local-frame-edits` 提交 |
| T5 | 状态色调派生 | 对状态图做色表映射派生新状态（如亮/灭灯），可作段末目标图或直接登记为非生成状态图 | `derived_assets.py`（服务端按色表重算） |
| T6 | 节奏编辑 | 在写回前调整逐帧相对时长（`durations`）与末帧停留，不改原帧和原导出 | 写回参数 `import-motion-asset` |
| T7 | 循环接缝检查 | 对比末帧与首帧差异，支持“往返播放（`ping_pong`）”预览与写回 | 只读 / 写回参数 |
| T8 | 绕轴旋转草稿 | 指定枢轴与运动部件掩码生成最近邻旋转草稿（像素画旋转会有锯齿，仅作起点） | 同帧数走 `local-frame-edits`；新建过渡走 `derived_assets.py`（要求首帧逐像素匹配起始状态） |
| T9 | 反向过渡 | 由已接受的 A → B 过渡倒放派生 B → A，逐帧校验源哈希 | `derived_assets.py` |
| T10 | 上传状态图 | 上传 128 px 透明 PNG 并注明来源与核对依据，作为目标图或静态状态图 | `derived_assets.py` |

- **派生资产归属**：T5/T8/T9/T10 经人工播放并写明结论接受后以 `motion-derived:<work>:<id>` 进入资产目录（资产库标为“派生状态图 / 派生过渡”），与模型生成结果分开统计。派生素材目前只在网页面板创建；Agent 可经 `workbench_get_motion_bindings` 只读查询槽位绑定，并经 `import-motion-asset` 写回已接受的派生资产。

## 4. 关键代码与已知限制

- **前端**：`app/(workbench)/tools/interactable-motion/`、`components/interactable-motion/`、`features/interactable-motion/`（`png-rgba.ts` 无损 PNG 编解码、`frame-tools.ts` 帧工具）；复用了角色动画的检查、调整与模型设置组件。
- **后端**：`Tools/SpritePipeline/sprite_pipeline/collaboration/derived_assets.py`、`local_frame_edits.py`、`state_chain.py`；Bridge 只读路由 `GET /v1/documents/<id>/motion-bindings`（MCP `workbench_get_motion_bindings`）。
- **当前限制**：
  - 状态图为线性链（最多 5 个状态 / 4 段过渡），分支或并行状态需拆成多个作品；
  - 候选级帧工具（T1/T3/T4/T8 同帧数）要求各段均已接受，待确认段可在段内使用 T1/T3/T4；
  - T10 当前仅支持本地上传，暂不支持直接从资产库选已有图片；T5 界面当前作用于整张状态图（后端已支持区域 `spans`）。
