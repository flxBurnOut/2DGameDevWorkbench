# 交互物动画独立面板方案

> 状态：已实施（第 1–6 步），实施记录见[第 8 节](#8-实施记录)。方案核对基准为 `paper-vbyc` 提交 `c501e63`，实施基于 `6b881c1`，2026-11-16（UTC−05:00）；主体实现为 `47db60b`，布局与流程重排见 [8.5](#85-布局与流程重排33e23f2)（`33e23f2`）。第 2–3 节描述的是实施前的界面，保留作对照。
> 范围：为交互物状态动画单独做一个网页面板，并补充适合交互物的编辑工具。先汇总当前界面逻辑和合并后的动画工具，再给出面板设计、工具清单、后端改动和实施顺序。不改变已有作品、检查点、保护规则和付费授权语义。

## 1. 结论

交互物动画的后端已经完整：对象泛化、物品原图移送、交互物合同、状态链、单独确认状态帧、外部 B 图条件和状态写回（N1–N6）都已实现，Agent 可以通过 `sprite-generator` 走完全程。

网页上缺的是入口和工作方式：

- 交互物动画没有自己的页面，混在“角色动画”五阶段工作区里，名称、默认文案和页面结构都按角色设计。
- 交互物的核心是状态图（A → B → C），当前界面却按“一段动作描述”线性推进，状态图只在候选的折叠项“状态图（N）”中出现。
- 生成在角色动画页，绑定到切换状态或序列条目在交互物编辑器里完成，需要在两页之间往返，而且看不到哪些槽已经绑定。
- 可用的编辑工具都是通用的（选帧修改、单帧像素编辑、色表映射），缺少针对“固定部件不动、运动部件绕轴转、开关两态对称”的工具。

建议新建 `/tools/interactable-motion`“交互物动画”面板：以状态图为中心，左侧是状态与过渡，中间是过渡的播放和逐帧画布，右侧是要求、检查、工具和写回。后端继续使用同一个 `sprite-generator` 能力和开放动作作品，面板只是同一份数据的另一种前端；交互物专用工具优先用现有的本地帧编辑接口实现，只有派生过渡和状态骨架需要后端扩展。分六步实施，前两步不改后端。

## 2. 当前界面逻辑

### 2.1 入口

| 位置 | 与交互物动画的关系 |
| --- | --- |
| 顶栏主导航 | 角色原图、角色动画、交互物编辑、资产库。没有“交互物动画”。 |
| 首页工具卡 | “角色动画”卡的说明写“选择角色或交互物”，标题与标签都是“角色”。 |
| 交互物编辑 → 外观 → 获取图片 → 生成物品原图（PixelLab） | 生成 128 px 物品原图后，按钮“移送到物品动画”；移送后变为“打开物品动画”，在新标签打开 `/tools/sprite-generator?object=<id>`。 |
| 角色动画 → 准备与描述 → 已有对象 | 下拉同时列出角色和交互物，交互物显示为“名称 · 交互物 · 128px”。 |
| 资产库 | 已确认的状态图和已接受的过渡作为资产出现，可从交互物编辑器“从资产库选用”。 |

“生成透明物件”（GPT Image 2.6）产出的物品图不能作为动画参考，只有 128 px PixelLab 物品原图可以移送。

### 2.2 从物品原图到写回的完整路径

| 步骤 | 页面与位置 | 后端 / Agent 操作 |
| --- | --- | --- |
| 1. 生成物品原图 | 交互物编辑 → 外观 → 获取图片 → 生成物品原图 | `reference-art` `generate`，`subject=prop` |
| 2. 移送为动画对象 | 同上，“移送到物品动画” | `reference-art` `transfer`；`prop_reference.py` 核验来源、尺寸与哈希，注册 `object_type=interactable` 对象 |
| 3. 描述并制定方案 | 角色动画 → 准备与描述：选对象、写“对象要做什么”“结束时希望保持什么姿势” | `plan-motion`（`motionSpec.object_id / object_type`） |
| 4. 查看方案 | 查看制作方案：交互物额外显示“交互物状态与起始图核对”（初态 → 目标状态、运动 / 固定部件、运动类型、终点与停留、描述与参考差异、视角 / 初态 / 部件归属核对） | `get-motion` |
| 5. 可选：绑定段末状态图 | 方案页“用已有状态图约束本段末帧” | `target-motion-stage` |
| 6. 分段制作与检查 | 自动制作 → 检查与调整：逐段播放，可“只确认第 N 帧，保留过渡待修复”或“确认此段，继续制作” | `generate-motion`、`get-motion-stage`、`review-motion-stage`（`accept_state` / `accept` / `reject`） |
| 7. 修正 | 检查页的“调整部分帧”、当前帧局部调整 | `get-motion-adjustment` / `create-motion-adjustment` / `review-motion-adjustment`；`edit-motion-frames` |
| 8. 查看状态链 | 候选下的“状态图（N）”折叠项 | `get-motion` 返回 `state_chain` |
| 9. 写回交互物 | 交互物编辑 → 选择切换或序列物件 → 左栏“素材”→“导入位置”选某条目的“状态图”或“进入过渡”→“从资产库选用原图 / 动画” | 共享文档命令 `import-motion-asset` |
| 10. 导出 | 交互物编辑“导出 Godot”，或动画页导出 SpriteFrames | `interactable-editor` `export-godot`；`sprite-generator` `export` |

### 2.3 交互物编辑器里与动画相关的界面

- 外观页签 → “帧动画”：导入有序帧图片、从精灵表切帧（帧宽、帧高、帧数）、帧率、循环、“帧顺序与时长”（逐帧相对时长）、待机动画与焦点动画选择。
- 切换（A / B 状态）与序列条目：各自的图片、动画、颜色、显隐和实体碰撞；“使用静态状态图”；使用动画的状态图片槽只读。
- 静态图片槽局部调整（7A–7D）：默认图、切换状态图、序列条目图可进入图片局部调整工作区。
- 预览画布：模拟靠近、离开、按键、点击、外部调用，播放反馈中的动画，但不显示动画工具产出的过渡与状态图之间的关系。

### 2.4 问题

| 编号 | 问题 | 表现 |
| --- | --- | --- |
| P1 | 入口难找 | 名称是“角色动画”；交互物的入口是“获取图片”里一个折叠卡片的次要按钮，并在新标签打开 |
| P2 | 心智模型不对 | 交互物是状态图，界面是一段动作描述加线性五步。用户只能在文字里描述“从关到开”，状态图要到候选折叠项里才能看到 |
| P3 | 两页往返 | 生成在动画页，绑定在交互物编辑器；“导入位置”只对切换和序列物件出现；看不到哪些条目已绑定、来自哪个作品版本 |
| P4 | 角色残留 | 准备页的“上传角色原图”、结构面板、提示文案都按角色写；对象下拉混合两类 |
| P5 | 交互物检查只是文字 | 运动 / 固定部件是文字列表；固定区域像素变化和铰接半径测量藏在“查看部件逐帧测量”里，没有叠加到画面上 |
| P6 | 工具不贴合交互物 | 没有固定部件回填、绕轴旋转、开关反向、状态色调切换、对齐校正等交互物常见需求 |
| P7 | 缺少使用场景预览 | 过渡只在棋盘格上播放，看不到它在交互物运行时里“触发 → 播放过渡 → 停在新状态”的效果 |

### 3.2 已实现的编辑与修正工具

| 工具 | 性质 | 范围与限制 | 网页入口 | Agent 操作 |
| --- | --- | --- | --- | --- |
| 段末锚点截取 | 确定性 | 目标状态提前到达时选择较早的真实帧结束本段，原始尾帧保留 | 检查页“目标姿势提前到达时，选择实际锚点” | `review-motion-stage` 的 `anchorFrame` + `acknowledgeTrim` |
| 单独确认状态帧 | 确定性 | 先锁定状态图，过渡仍待裁决 | 检查页“只确认第 N 帧” | `review-motion-stage`（`accept_state`） |
| 选帧修改：受限外观编辑 | 生成式（PixelLab） | 128 px 一次 2 帧，64 px 2–14 偶数帧；可选逐帧精确区域，本地合成保护区域外 RGBA | 检查页“调整部分帧” | `create-motion-adjustment`（`adjustmentPreserveMotion`、`adjustmentRegions`） |
| 选帧修改：动作过渡重画 | 生成式（PixelLab） | 4–16 偶数帧；可能改变所选帧姿势 | 同上 | 同上 |
| 单帧确定性编辑 | 确定性 | 替色、色表映射、保明暗映射、擦除、填充、平移、像素补丁、Alpha 清理、区域恢复；保存为完整播放备选再采用 | 检查页从播放器进入“局部调整当前帧” | 图片会话 `motion-frame` 目标 + `edit_image_region` |
| 多帧色表映射 | 确定性 | 同一 RGB 色表覆盖一段或完整候选的可编辑帧，跳过锁定帧，不改 Alpha | “选中全部可编辑帧” | `edit-motion-frames` |
| 旧段内修复 | 生成式 | 只为已有记录保留 | 检查页“旧版局部修复记录” | `repair-motion-stage` / `review-motion-repair` |
| 交互物测量 | 只读 | 扣除运动遮挡后的固定区域像素变化、铰接半径；与模型意见冲突时转人工裁决 | “查看部件逐帧测量” | 包含在复核报告中 |
| 结构与时序观察 | 只读（可选一次模型调用） | 铰接与形变需选择已核对结构；观察不授权修改 | 准备页结构面板、播放器时序观察 | `motionSpec.visual_structure` |
| 独立视觉复核 | 模型意见 | `experts_v1` 每段及整段至多五次；不自动通过、重画或采用 | 检查页“检查详情” | 包含在 `get-motion-stage` / `get-motion` |
| 导出 | 确定性 | PNG、预览、配方 / QA、单动作 Godot SpriteFrames 包 | 导出与使用 | `export` |

本地帧编辑接口 `local_frame_edits.py` 接受两种输入：色表映射，或逐帧的完整 PNG 补丁加区域。服务端在作品锁内重读来源、核对帧哈希、拒绝锁定帧，并逐像素验证区域外 RGBA 不变，然后保存为完整播放备选。这意味着任何“逐帧计算出新像素、只改授权区域”的工具都可以在前端计算、经同一接口提交，不需要新的后端操作。

### 3.3 保护规则

- 已锁定的状态图、段首、已确认的段尾和停留帧不能被任何编辑工具修改。
- 创建备选不等于采用；完整候选采用派生新版本，原帧与原导出保留。
- 确定性编辑不消耗绘图试做次数；生成式修改按实际帧计数，每帧最多两次。
- 生成、规划和复核都需要明确的执行与费用授权；GET、刷新和读历史不发起新调用。

## 4. 方案：交互物动画独立面板

### 4.1 定位

- 新路由 `/tools/interactable-motion`，名称“交互物动画”，顶栏主导航为：角色原图 · 角色动画 · 交互物动画 · 交互物编辑 · 资产库。
- 数据层不分家：仍是 `sprite-generator` 能力下的开放动作作品（`?work=<openWorkId>`），同一作品可以被两个页面读取。`object_type=interactable` 的作品默认在新面板打开，角色动画页的对象下拉只列角色。
- 面板负责“状态动画的制作、检查、修正和写回”；行为、触发、文本、音效和碰撞仍在交互物编辑器里配置。

### 4.2 布局

```
┌ 顶栏 ───────────────────────────────────────────────────────────────┐
├ 对象条：[缩略图] 三档拉杆 · 交互物 · 128px │ 绑定：交互物项目 › 三档拉杆（切换） │ 版本 3 │
├──────────────┬──────────────────────────────────┬────────────────────┤
│ 状态图        │ 过渡画布                          │ 要求 │ 检查 │ 工具 │ 写回 │
│              │                                  │                    │
│  ● A 关（原图）│  [原版 | 备选] 同步播放             │ 选中过渡 A→B：     │
│   │ 8 帧 已接受│  ┌────────────────────────┐      │ 初态 / 目标状态     │
│   ▼          │  │   棋盘格 + 枢轴点 + 固定区 │      │ 运动部件 / 固定部件 │
│  ● B 开 ✓     │  │   叠加 + 洋葱皮            │      │ 运动类型 / 停留     │
│   │ 6 帧 待检查│  └────────────────────────┘      │ 复核结论与测量      │
│   ▼          │  帧条：[1][2][3]…[8] 锁定帧带锁标记   │ 可用工具与额度      │
│  ○ C 中档     │  逐帧时长 · FPS · 循环              │ 写回槽位与状态      │
│  + 添加状态   │                                  │                    │
├──────────────┴──────────────────────────────────┴────────────────────┤
│ 状态栏：还需：确认 B 状态帧 │ 预计消耗 … │            [主操作：确认此过渡] │
└─────────────────────────────────────────────────────────────────────┘
```

- **状态图（左）**：节点是状态（原图为首节点），边是过渡（对应方案中的段）。节点显示已确认的状态图、已绑定的目标图或文字描述；边显示帧数和状态（规划中、生成中、待检查、已接受、已拒绝）。选中节点或边决定中间和右侧显示什么。
- **过渡画布（中）**：复用现有播放器与帧条，增加枢轴点、固定区域和逐帧差异的叠加层，以及原版与备选同步播放。
- **右侧四个页签**：要求（合同字段，可编辑的只在规划前）、检查（复核结论、测量叠加开关、人工结论）、工具（第 4.4 节）、写回（第 4.5 节）。
- **状态栏（下）**：说明当前还缺什么，只有一个主操作，沿用第 1 步建立的禁用原因写法。

### 4.3 流程

1. **选对象**：从交互物编辑器某个物件进入时，带上 `document` 与 `definition`，面板显示“绑定到哪个物件”。没有可用的 128 px 参考时，面板内直接提供“生成物品原图”（复用 `reference-art` 的 prop 生成与移送），不再跳去另一页的折叠卡片。
2. **定义状态**：在状态图上添加状态（名称、外观描述、可选目标图）和过渡（起止状态、是否循环、终点停留）。切换物件默认给出 A → B 两个状态，序列物件按条目生成节点。
3. **规划与制作**：沿用 `plan-motion` / `generate-motion`。状态图在规划前序列化为描述和段末目标（`target-motion-stage`）；第 5 步之后改用结构化的状态骨架（B1）。
4. **检查**：按过渡逐段检查，测量结果叠加在帧上；“确认状态帧”和“确认过渡”是两个按钮，对应 `accept_state` 与 `accept`。
5. **修正**：在“工具”页签选择第 4.4 节的工具，结果都是完整播放备选，同步播放后再采用。
6. **写回**：在“写回”页签把状态映射到切换的 A / B 或序列条目，一键提交 `import-motion-asset`，并显示每个槽当前绑定的作品、版本和哈希。
7. **场景预览**：在面板内用交互物运行时预览（复用 `components/interactable-editor/preview.tsx` 与 `features/editor-documents/simulation-replay.mjs`）播放“触发 → 过渡 → 停在新状态”。

### 4.4 交互物专用编辑工具

| 编号 | 工具 | 解决什么 | 做法 | 后端 |
| --- | --- | --- | --- | --- |
| T1 | 固定部件回填 | 底座、外壳等固定部件在生成中轻微抖动或变色 | 在原图上圈定固定区域（或取已核对结构中的固定部件），把原图该区域像素逐帧回填到过渡的所有可编辑帧；被运动部件遮挡的像素按测量的遮挡掩码跳过 | 前端计算，经现有 `local-frame-edits` 逐帧补丁提交 |
| T2 | 叠加检查层 | 测量结果只能读文字 | 在画布叠加固定区域逐帧变化热区、枢轴点与铰接半径圆、上一帧洋葱皮 | 只读，复用复核报告中的测量 |
| T3 | 对齐校正 | 整体在帧间漂移 1–2 px | 以固定部件的包围盒或质心为基准，检测逐帧偏移，提供整数像素平移修正 | 前端计算，经 `local-frame-edits` 提交（区域覆盖移动前后范围） |
| T4 | 批量清理 | 生成后出现零散噪点、半透明边 | 把单帧已有的擦除、Alpha 清理、像素补丁扩展到所选帧范围 | 前端计算，经 `local-frame-edits` 提交 |
| T5 | 状态色调派生 | 指示灯亮 / 灭、屏幕开 / 关这类只改颜色的状态，不必走生成 | 在状态图上选区域并做色表映射，得到新的状态图，作为下一个状态的目标图或直接作为静态状态图写回 | 作为目标图时用现有 `target-motion-stage`；作为状态图写回需 B3 |
| T6 | 节奏编辑 | 开门过渡需要在末尾停一下、灯闪需要不均匀间隔 | 逐帧相对时长与末帧停留，在写回前调整；不改原帧和原导出 | 写回参数，沿用交互物动画片段已有的逐帧 `duration` 字段 |
| T7 | 循环接缝检查 | 待机闪烁等循环动画首尾跳变 | 显示末帧到首帧的差异，提供“往返播放”预览 | 只读；往返作为写回时的播放设置 |
| T8 | 绕轴旋转草稿 | 拉杆、门、开关这类铰接运动生成不稳定 | 指定枢轴和运动部件掩码，按角度生成最近邻旋转的逐帧草稿，作为完整播放备选，需要人工检查后采用 | 帧数与段一致时经 `local-frame-edits` 全帧补丁提交；需要新段时用 B2 |
| T9 | 反向过渡 | A → B 已经做好，B → A 是同一运动倒放 | 由已接受的 A → B 派生 B → A 过渡，记录来源与派生方式 | B2 |
| T10 | 状态图替换 | 已有满意的手绘状态图 | 为某个状态上传或从资产库选择 128 px 透明 PNG，作为目标图或静态状态图 | 目标图用现有接口；静态状态图需 B3 |

所有工具都遵守第 3.3 节的规则：不改锁定帧，结果先成为备选，同步播放后明确采用；确定性工具不消耗绘图次数，T8 的草稿不计为模型通过。

### 4.5 写回

- “写回”页签按物件类型显示目标槽：切换物件显示 A / B 两个状态和“进入 B 的过渡”“回到 A 的过渡”；序列物件按条目显示“状态图”“进入过渡”。
- 每个槽显示当前绑定：资产来源（作品、版本、状态或过渡）、帧数、哈希，以及与面板当前作品是否一致。
- 写回只调用现有的 `import-motion-asset`，继续带 `expectedRevision` 与稳定 `commandId`；冲突时重读并保留未提交选择。
- 交互物编辑器的“导入位置”保留，作为不经过面板的入口；编辑器中切换和序列物件增加“制作状态动画”按钮，带上下文打开面板。

### 4.6 后端与接口改动

- 不自动采用、不自动重画；模型意见和测量只作为证据。
- 不把交互物行为、触发、碰撞配置搬进面板。
