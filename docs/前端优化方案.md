# 前端优化方案

> 状态：四步均已实施，结果与偏差见第 9 节。方案记录于 2026-11-15，核对基准为 `paper-vbyc` 提交 `9819a9b2588a`；实施基于提交 `6e4ad65`。
> 范围：Web 工作台（`app/`、`components/`、`features/` 的前端部分）的加载与运行性能、排版和视觉一致性。不涉及 SpritePipeline 原生界面，不改变任何制作流程或数据合同。

## 1. 结论

前端可以正常构建和使用，没有严重的性能问题。拉低体验的主要是界面不统一和信息层级混乱，因此本方案中排版与视觉的分量比性能重。

实施分四步，前两步风险低、观感改变最大，后两步量大但机械，可以按页面分批。

## 2. 评估方法

| 项目 | 做法 |
| --- | --- |
| 构建 | `npm run build`，统计 `dist/client` 中各 chunk 的原始与 gzip 体积 |
| 运行 | `npm run dev` 启动三个服务，用无头 Chromium 逐页打开七个页面 |
| 视口 | 1440×900 与 390×844 |
| 页面 | `/`、`/player`、`/tools/interactable-editor`、`/tools/reference-art`、`/tools/sprite-generator`、`/assets`、`/advanced` |
| 静态统计 | 对 `components/` 与 `app/` 的样式和组件做计数 |

没有覆盖的部分：

- 深色主题。无头浏览器渲染的是浅色，深色下的对比度和配色没有检查。
- 有真实数据时的表现。评估环境没有作品、任务和素材，资产库网格、帧条、长任务列表在数据量大时的渲染没有测。
- 真实设备上的交互流畅度，如画布拖动、动画播放的帧率。

## 3. 性能

### 3.1 现状

客户端 JS 合计约 1.5 MB（未压缩）。主要 chunk：

| chunk | 原始 | gzip | 说明 |
| --- | --- | --- | --- |
| `work-items` | 307 KB | 91 KB | 所有页面共用 |
| `index` | 203 KB | 55 KB | 所有页面共用 |
| `framework` | 190 KB | 59 KB | React 运行时 |
| `open-motion-studio` | 155 KB | 48 KB | 角色动画页 |
| `image-edit-workspace` | 146 KB | 47 KB | 图片局部调整 |
| `interactable-editor` | 115 KB | 35 KB | 交互物编辑器 |
| `shared-navigation` | 80 KB | 28 KB | 所有页面共用 |

### 3.2 问题与做法

| 编号 | 问题 | 证据 | 做法 | 优先级 |
| --- | --- | --- | --- | --- |
| P1 | 整份能力清单被打进公共包 | `work-items` chunk 中包含完整的 `workbench/manifest.json`（91 KB，含全部输入 schema）、zod 和 jszip。清单由 `lib/workbench/modules.ts`、`lib/workbench/brand.ts`、`components/workbench/agent-follow.tsx` 直接导入 | 构建时生成只含品牌、导航、模块列表和路由的精简清单供页面使用；zod 与 jszip 改为用到时再加载 | 高 |
| P2 | 所有页面持续轮询 | 页面静止时约每秒 1 个请求。`components/workbench/workbench-provider.tsx` 每 6 秒拉取最多 200 条任务记录（带 `refresh=true`）和全部动画作业，标签页不可见时也不停。只有 `agent-follow.tsx` 检查了页面可见性 | 页面不可见时暂停；没有进行中的任务时拉长间隔；任务列表改为只取摘要或增量 | 高 |
| P3 | 重型面板没有按需加载 | `app/` 与 `components/` 中没有任何 `lazy` 或动态导入。Godot 导出对话框（431 行）、图片局部调整工作区（608 行）、模型设置（428 行）都随页面一起加载 | 对话框和次级工作区改为打开时再加载 | 中 |
| P4 | 大组件整体重渲染 | `open-motion-studio.tsx` 1762 行、`interactable-editor.tsx` 1100 行、`motion-structure.tsx` 1158 行，各自带独立定时器。`components/` 中记忆化只有 33 处 | 按步骤或面板拆成子组件，让轮询和播放只刷新自己那一块 | 中 |
| P5 | 图片未延迟解码 | 33 处 `<img>` 中只有 4 处带 `loading` 或 `decoding` | 资产库网格和帧条统一加上 | 低 |

预期：P1 与 P2 完成后，每个页面的首屏下载量减少约三分之一，空闲时的后台请求量降一个量级。这是估计值，以实施后的同口径测量为准。

## 4. 排版与信息层级

| 编号 | 问题 | 表现 | 做法 |
| --- | --- | --- | --- |
| L1 | 顶部栏层数太多 | 交互物编辑器从上到下是全局导航、面包屑、编辑器工具栏，加上底部的"制作中"条，四条横栏约占 230 像素，画布可用高度不到一半 | 面包屑并入全局导航；编辑器工具栏只留主操作，次要操作收进菜单 |
| L2 | 两套页面外壳并存 | 角色动画页使用自己的紧凑顶栏（小图标加"工作区"下拉），其余页面使用完整的全局导航，切换时整个框架变化 | 统一为一套外壳，角色动画页的步骤条作为外壳内的第二行 |
| L3 | 首页被弹窗挡住 | 打开首页先弹"这次想制作什么"，背后的页面本身是同样的入口卡片 | 去掉弹窗，入口卡片直接作为首页主体 |
| L4 | 主操作不突出 | 交互物编辑器工具栏并排五个按钮；"保存到资产库""保存源文件""保存草稿"三种保存语义相近 | 只保留一个主按钮（导出）；保存类合并为一个带下拉的按钮，并在下拉中说明三者的区别 |
| L5 | 属性面板对齐混乱 | 标签居中而输入框左对齐，数字输入宽度不一，"颜色"控件与同行错位 | 标签左对齐，两列等宽栅格 |
| L6 | 空状态信息过载 | 资产库没有素材时仍显示搜索、筛选、分页和三段说明文字 | 空状态只留一句说明和一个导入按钮 |
| L7 | 窄屏下不可用 | 390 宽度时编辑器工具栏折成四行，画布被挤出首屏。样式中有 540、640、700、900、1100 等七种断点写法 | 明确最小支持宽度（建议 1100），低于时给出提示；断点收敛为两档 |

L4 需要先确认三种保存的实际语义再合并，避免把不同的持久化位置混为一谈：草稿在浏览器 IndexedDB，源文件是下载到本机的 JSON，资产库是共享文档。

## 5. 视觉一致性

| 编号 | 问题 | 证据 | 做法 |
| --- | --- | --- | --- |
| V1 | 颜色没有收敛到主题变量 | 样式和组件中有 356 处写死的色值，218 种不同颜色；主题变量只有 86 个 | 归并到一组语义变量：背景、表面、边框、主文字、次文字、强调、状态色。写死的色值按页面逐步替换 |
| V2 | 圆角和字号没有阶梯 | 圆角有 2、4、5、6、7、8、9、10、12 像素九种；字号 22 种 | 圆角定三档，字号定五到六档 |
| V3 | 控件两套并存 | 原生 `<select>` 63 处，封装的 `NativeSelect` 只用了 7 处；原生 `<button>` 208 处，封装的 `Button` 86 处 | 换成 `components/ui/` 中已有的封装组件，按钮高度与下拉样式随之统一 |
| V4 | 英文眉标装饰过多 | 每页都有 `CHARACTER / MOTION · 01`、`FORGE / ASSETS` 这类字距很宽的英文小标题，中文界面中不传达信息 | 删除，或只在首页保留一处 |
| V5 | 背景处理不一致 | 资产库使用网格底纹，其余页面是纯色 | 统一为纯色，网格只用于画布区域 |
| V6 | 内联样式 | `components/` 中有 51 处 `style={{…}}` | 能用类表达的改为类；确实依赖运行时数值的保留 |

V1 至 V3 的替换量大，改动前后应逐页截图对比，深色主题一并检查。

## 6. 遗留文案

资产库页面仍写着"地图工程提供编辑源文件……动画与完整场景保留实际素材"（`components/workbench/asset-library.tsx:420`）。地图与场景模块已在本分支删除，这句话需要改写。

## 7. 实施顺序

| 步骤 | 内容 | 涉及编号 | 说明 |
| --- | --- | --- | --- |
| 1 | 低风险、见效快 | P1、P2、V4、L3、L6、第 6 节 | 不改变页面结构 |
| 2 | 统一外壳 | L1、L2、L4 | 对观感改变最大；L4 先确认保存语义 |
| 3 | 设计变量与控件 | V1、V2、V3、V5、V6、L5、L7 | 量大但机械，按页面分批 |
| 4 | 结构性优化 | P3、P4、P5 | 收益在长时间使用时的流畅度 |

每一步完成后的验收：

- 用第 2 节的同一套页面和视口重新截图，浅色与深色各一遍。
- 重新统计 chunk 体积和空闲请求数，与第 3.1 节对比。
- 运行受影响页面的回归：`test:workbench-shell`、`test:theme`、`test:frontend`、`test:interactable-http`、`test:open-motion`、`test:image-edit`、`test:preview-follow`，以及类型检查和 lint。页面跟随依赖精确的路由和页面标识，改外壳时需要确认 `agent-follow` 的行为不变。

## 8. 不做的事

- 不更换前端框架、构建工具或组件库。
- 不为手机和平板做完整适配。
- 不改动 SpritePipeline 的 Gradio 原生界面。
- 不调整制作流程、任务语义、共享编辑和数据合同。

## 9. 实施记录（2026-11-15）

### 9.1 测量方法

与第 2 节同口径：生产构建（`npm run build`）经 wrangler 提供，runtime 与 SpritePipeline 使用隔离的 `WORKBENCH_TEST_RUN` 数据目录；无头 Chrome 打开七个页面，1440×900 与 390×844 各一遍，浅色与深色各一遍。优化前数据来自同机在临时 worktree 中构建的 `6e4ad65`。28 组截图在两版下均无脚本错误、无横向滚动。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 公共 `work-items` chunk | 300 KB（89 KB gz） | 15 KB（6 KB gz） |
| 首屏 JS 传输：首页 / 角色总览 / 管理 | 268 / 268 / 267 KB | 217 / 216 / 215 KB |
| 首屏 JS 传输：交互物 / 角色原图 / 角色动画 / 资产库 | 356 / 281 / 366 / 325 KB | 282 / 230 / 266 / 227 KB |
| 页面静止 60 秒的后台请求（首页、交互物、资产库相同） | 60（任务 10、序列帧 10、页面跟随 40） | 24（任务 2、序列帧 2、页面跟随 20） |
| 写死色值（出现次数 / 不同颜色） | 247 / 170 | 40 / 29 |
| 圆角取值 / 字号取值 | 20 / 22 | 3 档 / 6 档 |
| 原生 `<select>` / `NativeSelect` | 63 / 2 | 0 / 64 |
| 内联 `style={{…}}` | 51 | 11 |

静态计数用同一脚本统计 `components/` 与 `app/`（不含生成的主题变量），口径与第 3–5 节的人工计数略有差异，前后对比以本表为准。首屏 JS 平均减少约 25%，与“约三分之一”的预估接近。

### 9.2 按编号的落实

- **P1**：页面改读 `lib/workbench/ui-manifest.json`（5.8 KB，由 `ui-manifest.mjs` 从完整清单派生，Vite 构建与开发启动时自动同步；`npm run ui-manifest:check` 与 `test:workbench-shell` 校验）。jszip 在解析 ZIP 时才加载；本机草稿列表只有存在未标记的交互物草稿时才加载 zod 合同。
- **P2**：Provider 轮询在标签页隐藏时暂停，回到页面立即刷新；有制作中任务时 6 秒、空闲时 30 秒。任务列表新增 `since`/`revision`，历史未变时只返回 `unchanged`。页面跟随在有待展示步骤时 1.5 秒、空闲 3 秒、隐藏 8 秒（服务端页面有效期 20 秒）。
- **P3**：Godot 导出对话框、图片局部调整工作区、素材选择、素材包导入、模型设置、旧版序列帧工作区改为首次打开时加载。
- **P4**：角色动画与结构分析的轮询结果未变化时不再触发重渲染，隐藏时跳过；交互物编辑器与角色动画改用只含稳定回调的 `useWorkbenchActions()`，不再随状态轮询重渲染。播放计时器原本已在独立子组件内。
- **P5**：资产网格、素材选择、帧条、历史与目标缩略图加 `loading="lazy"`/`decoding="async"`；主播放器和编辑画布保持即时加载，避免播放闪烁。
- **L1/L2**：所有页面共用一个顶栏，工具页在顶栏显示面包屑（含当前作品名）；去掉第二行上下文栏和底部“制作中”栏，制作记录数量改为顶栏按钮角标。交互物编辑器的顶部从四条横栏约 230 像素降到两条约 120 像素；角色动画不再隐藏全局外壳，步骤条作为外壳内第二行。
- **L3**：首页去掉弹窗，卡片内直接列出各工具及起步说明，并提供“继续上一次制作”和“导入 Forge 素材包”。
- **L4**：已核对三种保存的去向后合并为“保存”菜单：保存草稿（浏览器 IndexedDB）、保存到资产库（本机服务 `save-project` 记录）、下载源文件（工程 JSON），每项下写明区别；“打开”菜单收纳打开工程与从资产库选用；唯一主按钮为“导出 Godot”。
- **L5**：标签居中与颜色控件错位的根因是图片局部调整与交互物编辑器共用 `.ie-workspace`、`.ie-row`、`.ie-center` 类名，前者的全局样式渗入后者。局部调整根元素改为 `.ie-image-edit` 并限定作用域；检查器字段改为左对齐的两列等宽栅格。
- **L6**：资产库无素材时只显示一句说明、导入按钮和回收站入口；分页只在多于一页时出现。
- **L7**：最小支持宽度 1100 像素，更窄时底部提示；全部样式断点收敛为 ≤1099px 与 ≤700px。
- **V1**：近似色直接改用主题变量；深色值属于其他语义的用 `light-dark(var(--theme-light-*), var(--theme-dark-*))` 保持两种模式外观；新增 `cyan-strong` 变量（青色主按钮）并加入对比度测试。交互物编辑器深色模式原用绿色主按钮，统一为全局主色。
- **V2**：`app/globals.css` 定义 `--ui-radius-sm/md/lg`（4/6/8 px）、`--ui-text-xs…xl`（12/13/14/16/20/28 px）和 `--ui-control-height`（34 px）。
- **V4/V5/V6、第 6 节**：英文眉标全部删除；页面背景改为纯色，网格只留在画布与首页预览插图；静态内联样式改为类；资产库遗留的“地图工程”文案已改写。

### 9.3 与方案的偏差和遗留

- **V3 只替换了下拉**。`<button>` 仍有 198 处未换成 `Button`：`Button` 默认是实心主色并带 Tailwind 尺寸类，与四个页面已有的按钮样式冲突，且许多按钮只在有数据时出现、无法逐一截图核对。按钮的高度、内边距和圆角改由 `--ui-control-*` 变量在各页面统一。
- **空闲请求量降了约 60%，未达到“一个量级”**。剩余主要是页面跟随（每 3 秒一次）；继续降低会让 Agent 展示步骤的响应变慢，可按需要把空闲间隔调到 6 秒左右。
- **P4 未拆分大文件**。没有把 1700 行的组件按步骤拆开，而是从源头去掉无效重渲染（轮询去重、稳定回调上下文）。真实设备上的帧率仍未测。
- 有真实数据时的资产网格、帧条与长任务列表仍未在评估环境中覆盖。
- 保留的 40 处色值属于功能色：画布标注描边、颜色选择器默认值、图片编辑的预览底色与选框，不随主题变化。
- 开发模式在自定义 `WORKBENCH_TEST_RUN` Vite 缓存目录下依赖预构建失败（`react-server-dom-webpack` 重复默认导出），与本次修改无关，本次测量改用生产构建。
