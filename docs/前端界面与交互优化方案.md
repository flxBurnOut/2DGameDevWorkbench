# 前端界面与交互优化方案

> 状态：四步均已实施，记录与偏差见第 10 节。走查于 2026-11-16，基准为 `paper-vbyc` 提交 `ba6b16c`。
> 范围：Web 工作台的首页、全局导航与菜单、图标、按钮与操作反馈，以及各页面的同类问题。上一轮[前端优化方案](前端优化方案.md)已解决性能、外壳统一、设计变量和下拉控件；本方案不重复这些内容，只处理那一轮之后仍然存在的审美与交互问题。不改变制作流程、任务语义和数据合同。

## 1. 结论

上一轮把“乱”收拾成了“统一”，但界面仍然显得粗糙，原因集中在三处：

1. **首页没有内容**。首页是两张占位插图卡片，没有展示用户已经做过的任何东西。本机有 37 条制作记录和 24 件像素素材，首页一件都不显示。
2. **入口重复、当前位置不清**。同一组目的地在顶栏左侧、“工作区”下拉和顶栏右侧出现三次，而资产库、工作台管理页的顶栏按钮没有选中态。
3. **操作没有反馈**。全部样式中没有一处 `:active` 按下态，所有页面上可见的按钮都没有过渡动画。选中态与主按钮共用一个样式，禁用态只降低透明度，大多数异步按钮也没有加载态。

建议分四步实施：先做按钮与反馈的基础组件，再重做首页，然后整理导航，最后逐页清理。第一步改动集中在共享样式，改完后所有页面都能受益。

## 2. 走查方法

| 项目 | 做法 |
| --- | --- |
| 环境 | 本机 `npm run dev`（开发模式），使用真实本机数据：37 条制作记录、24 件资产 |
| 浏览器 | 无头 Chrome，通过 DevTools 协议驱动 |
| 视口 | 1440×900（主）、1280×720（常见笔记本） |
| 页面 | `/`、`/player`、`/tools/reference-art`、`/tools/sprite-generator`、`/tools/interactable-editor`、`/assets`、`/advanced` |
| 交互 | 悬停（首页卡片与工具行、顶栏按钮、资产卡片）、工作区下拉、制作记录弹窗、帮助弹窗、Tab 键焦点顺序、深色模式 |
| 计算样式 | 逐页统计可见按钮的高度、圆角、字号和 `transition`，以及标题字号与字重、原生复选框数量 |

本次没有覆盖：

- 窄于 1100 像素的窗口，上一轮已明确不支持。
- 角色动画第 2–5 步和图片局部调整的内部状态，因为需要进行中的任务。
- 真实设备上的触控板手感与动画帧率。

## 3. 首页

### 3.1 问题

| 编号 | 问题 | 证据 |
| --- | --- | --- |
| H1 | 插图像占位符 | 角色卡用 lucide `PersonStanding`，这个图形就是常见的无障碍标识；交互物卡是三个尺寸不一、互相叠压的线框立方体。底下是网格加径向渐变，浅色模式下显得发灰 |
| H2 | 标题层级倒置 | 卡片标题“角色制作总览”和页面 h1 都是 `--ui-text-xl`（28 px，600），卡片抢了页面标题的层级（`workbench.css:380`） |
| H3 | 左右卡片不对称 | 左卡有两个工具入口，右卡只有一个，右下留出约 100 px 空白；右卡描述折行后末行只剩“件。” |
| H4 | 卡片标题不能点 | 卡片和标题都没有链接，只有下方的工具行可以点。悬停卡片时没有任何变化，`transition: box-shadow` 写了，但从来没有设置阴影 |
| H5 | 不展示已有内容 | 首页不读取制作记录和资产。“继续上一次制作”只是打开弹窗 |
| H6 | 次要操作掉出首屏 | 1280×720 下“继续上一次制作”和“导入 Forge 素材包”已经在首屏以下 |
| H7 | 残留装饰 | 卡片左上角 35×2 px 的色条（`.wb-production-card:before`）看起来像渲染错位；品牌名下面仍是英文 “2D game dev workbench”，上一轮删英文眉标时漏掉了 |
| H8 | 中间页冗余 | “角色制作总览”（`/player`）页只有两张卡，内容和首页卡片里的两个入口完全一样，点进去等于多走一步 |

### 3.2 新布局

首页从“产线介绍”改为“工作起点”，从上到下分三块：

```
┌ 顶栏（见第 4 节）─────────────────────────────────────────────┐
│                                                                  │
│  开始制作                                         导入素材包 ↗   │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐              │
│  │ [真实像素图]  │ │ [帧条预览]    │ │ [物件预览]    │              │
│  │ 角色原图      │ │ 角色动画      │ │ 交互物编辑    │              │
│  │ 描述外观生成… │ │ 选择角色描述… │ │ 配置查看、切… │              │
│  │ 角色 · 第1步  │ │ 角色 · 第2步  │ │ 交互物        │              │
│  └──────────────┘ └──────────────┘ └──────────────┘              │
│                                                                  │
│  继续制作                    需要处理 3 · 制作中 1   全部记录 →  │
│  ┌──────────────────────────────────────────────────────────┐    │
│  │ ▣ 三档拉杆      交互物编辑  ● 需要处理  11/10 17:53  [处理] │    │
│  │ ▣ 角色动画 …    角色动画    ● 制作中    11/10 20:28  [查看] │    │
│  │ …（最多 5 条，需要处理的排在前面）                         │    │
│  └──────────────────────────────────────────────────────────┘    │
│                                                                  │
│  最近素材                                         打开资产库 →   │
│  [▦] [▦] [▦] [▦] [▦] [▦] [▦] [▦]   ← 横向一排缩略图，棋盘格底   │
└──────────────────────────────────────────────────────────────────┘
```

要点：

- **三个工具并排，等宽等高**。产线（角色、交互物）降为卡片底部的小标签和强调色，不再用来分组。H3 的不对称和 H8 的中间页都随之消失。整张卡都是链接，悬停时边框换成强调色、阴影加深一级、预览图上移 2 px。
- **预览图用真实素材**。优先取资产库里该类型最新的一件（角色原图取透明 PNG，角色动画取帧条中的 3 帧，交互物取物品原图），按整数倍 `image-rendering: pixelated` 放大，放在棋盘格底上。没有素材时用仓库内置的示例像素图，不再使用 lucide 图标充当插图。
- **继续制作**直接列出最近 5 条制作记录，复用 `WorkItemRow` 的数据，改为紧凑的单行样式。“需要处理”的条目排在前面并带警示色。没有记录时只显示一句“还没有作品，从上面选一个工具开始”。
- **最近素材**是一排 8 个缩略图，点击进入资产库详情。资产为 0 时整块隐藏。
- 页面标题保持 28 px，三块的区块标题用 16 px 加粗，卡片标题 16 px。按这个层级，H2 不再出现。
- 1280×720 下首屏应能看到三张工具卡和至少两条继续制作记录。工具卡预览高度从 178 px 降到约 120 px。

`/player` 改为重定向到首页。保留路由是因为 Agent 页面跟随和旧链接还会用到它，改之前要确认 `agent-follow` 和 `test:preview-follow` 中对这个页面标识的依赖。

| N3 | 当前位置不高亮 | 在资产库和工作台管理页，顶栏右侧对应按钮虽然设置了 `aria-current`，但 `.wb-header-actions` 没有对应样式，看起来没有选中 |

| N7 | 制作记录数字对不上 | 顶栏角标显示 3（只数“需要处理”，并用警示色），弹窗页签写“制作中 · 4”（需要处理 3 加上生成中 1），用户会觉得数字错了 |

### 4.2 方案

**顶栏在所有页面保持同一结构：**

```
[F] Forge │ 角色原图  角色动画  交互物编辑  资产库 │ ……… │ ● 制作记录 3 │ ? │ ⚙ │ ☾ │
```

- 左侧主导航直接列出三个工具和资产库，当前页用底部 2 px 强调色下划线加深色文字标出（N1、N2、N3）。去掉“工作区”下拉；1100–1280 px 宽度下文字够放，不需要折叠。
- 右侧只留“制作记录”一个带文字的按钮；帮助、工作台管理和主题切换改为 32 px 图标按钮，带 tooltip（N4）。
- 去掉品牌名下的英文 tagline（H7）。
- 工具页的作品名和来源链接从顶栏移到工具自己的工具栏：交互物编辑器已有项目名输入框，角色动画放在步骤条行首，角色原图放在页面标题旁。面包屑随之删除。
- 制作记录角标改为两种：有待处理时显示警示色数字，并在 tooltip 中写明“需要处理 3 项”；只有进行中的任务时显示一个带脉冲的小圆点，不显示数字（N7）。

**制作记录弹窗：**

- 页签改为分段控件“制作中 4 | 已完成 33”，选中项为浅底加深色文字，不再用主按钮样式。刷新改为右上角的图标按钮，转动表示刷新中。“管理本机数据”移到弹窗底部作为文字链接。打开时焦点放在分段控件上（N8）。
- 标题回落规则：作品名为空或只是生成的 ID 时，显示“工具名 · 时间”，完整 ID 放进 tooltip。适配器错误按状态码映射为中文短句，例如“作品已不存在”“服务繁忙，稍后重试”，原文放进可展开的详情（N9）。
- 状态改成带底色的小标签（需要处理、制作中、已完成），不再用 6 px 圆点（N9）。

**帮助弹窗：**首页不显示“回到首页”按钮。保存位置说明折叠为“数据保存在哪里”的可展开项，主体只写当前页面的 2–3 个步骤（N10）。

**页面切换：**保留整页跳转（它承担离开前的保存检查），点击后立刻给出反馈：被点的导航项进入按下态，顶栏底边出现一条 2 px 的不确定进度条，直到新页面开始渲染（N11）。

## 5. 图标

| 编号 | 问题 | 做法 |
| --- | --- | --- |
| I1 | 图标不表达功能 | `ModuleIcon` 的映射是：角色原图用 `Paintbrush`，角色动画用 `Images`（一叠图片，看不出是动画），交互物编辑用 `Box`（3D 立方体，看不出可交互）。首页插图又用了 `PersonStanding`。建议为三个工具和两条产线画一套 16×16 网格的像素风自有图标，和产品做的东西风格一致。只用 lucide 的话，角色动画可换 `Film` 或 `Clapperboard`，交互物可换 `MousePointerClick` 或 `Hand`，具体图标名以安装的 `lucide-react@1.31.0` 为准 |
| I2 | 尺寸与描边不统一 | 顶栏 16 px，首页工具行和记录行 20 px，下拉菜单 16 px；首页插图描边 1.6 和 1，其余默认 2。定三档尺寸 16（控件内）、20（列表行首）、24（卡片），描边统一为 1.75 |
| I3 | 图标与文字对不齐 | 顶栏按钮的图标和中文基线差约 1 px，菜单项图标没有固定宽度。图标统一放进固定宽度的槽位，按钮使用 `align-items: center` 且行高为 1 |
| I4 | 只有图标的按钮缺说明 | 例如交互物预览区的重置按钮。所有只有图标的按钮都要有 `aria-label` 和 tooltip，tooltip 延迟 400 ms 出现 |

## 6. 按钮与反馈

### 6.1 现状

| 编号 | 问题 | 证据 |
| --- | --- | --- |
| B1 | 没有按下态 | 全部 CSS 中 `:active` 出现 0 次。shadcn 的 `Button` 有 `active:translate-y-px`，但页面基本不用它 |
| B2 | 没有过渡 | 7 个页面所有可见按钮的计算样式中 `transition-duration` 都是 0s，悬停是瞬间跳变 |
| B3 | 悬停规则各写各的 | `.wb-button` 悬停时换描边和底色；`.ie-workspace button`、`.motion-studio button` 各自定义一套；`image-assets.css` 没有悬停态；首页卡片和资产卡片没有悬停反馈 |
| B4 | 选中态和主按钮长得一样 | `.wb-button[aria-pressed='true']` 和 `.wb-primary` 写在同一条规则里（`workbench.css:221`）。资产库因此出现两个主色按钮（“已保存素材”页签和“导入 Forge 素材包”）；交互物检查器的“外观、触发、行为、记忆”页签也是主色实心。工作台管理页的页签却是浅底描边，同一种控件有两套外观 |
| B5 | 禁用态像可点 | 禁用只把透明度降到 0.55，主按钮禁用后成了淡紫色，像一个浅色风格的按钮（角色原图的“生成一张原图”“用于制作序列帧”，角色动画的“制定方案”），而且不说明为什么不能点 |
| B6 | 大多数异步按钮没有加载态 | 只有 4 个组件用了 `LoaderCircle`。刷新、查找、保存、导入等按钮要么只把文字换成“刷新中…”，要么没有任何变化 |
| B7 | 成功和失败没有统一出口 | 项目里没有 toast。保存、复制、导出成功后只在局部改一行文字，或者什么都不显示 |
| B8 | 焦点框被裁切或过重 | 全局焦点框是 2 px 描边、外偏移 4 px。首页工具行在 `overflow: hidden` 的卡片内，只剩上下两条线；弹窗打开时自动聚焦的链接也画出很重的框 |
| B9 | 原生复选框 | 资产库 24 个，交互物编辑器 8 个，角色动画 3 个，都是系统默认样式。资产卡片里的“选择素材”复选框和旁边的按钮不对齐 |
| B10 | 标题字重不一 | 各页 h1 字重分别是 600、400（角色原图）、650（角色动画） |

### 6.2 统一的状态表

在 `app/globals.css` 增加交互变量，在 `components/ui/` 补齐组件。各模块删掉自己的 `button` 通配样式，改用这些组件或类名。

| 状态 | 主按钮 | 次按钮（描边） | 幽灵按钮 / 图标按钮 | 页签 / 分段控件 |
| --- | --- | --- | --- | --- |
| 默认 | 主色底，白字 | 面板底，边框色 | 透明，次文字色 | 透明，次文字色 |
| 悬停 | 底色加深 8% | 底色换成 `--wb-soft`，边框不变 | 底色 `--wb-soft`，文字变主文字色，**不加描边** | 文字变主文字色 |
| 按下 | 底色加深 14%，`translateY(1px)` | 同左 | 底色再深一级 | 同左 |
| 选中 | — | — | 强调色文字加浅底 | 面板底，主文字色，轻阴影（分段控件）或 2 px 下划线（页签） |
| 焦点 | 2 px 焦点环，外偏移 2 px；在会裁切的容器内改为 `inset` 阴影 | 同左 | 同左 | 同左 |
| 禁用 | 中性灰底、灰字，光标 `not-allowed`；需要说明时在 tooltip 或按钮下方写原因 | 灰字，边框变淡 | 灰字 | 灰字 |
| 加载 | 文字前出现 14 px 旋转图标，宽度不变，`aria-busy="true"`，不可重复点击 | 同左 | 图标本身旋转 | — |

- 过渡统一为 `background-color, border-color, color, box-shadow` 120 ms `ease-out`，`transform` 80 ms。在 `prefers-reduced-motion` 下去掉位移和旋转。
- 卡片类可点击区域（首页工具卡、资产卡、记录行）悬停时边框换成强调色，阴影从 `--shadow-sm` 升到 `--shadow-md`；按下时阴影回落。
- 新增 `Checkbox`（16 px，圆角 4，选中为主色）和 `Switch`（用于“需要循环播放”这类开关），替换全部原生复选框（B9）。
- 新增轻量 toast，挂在右下角，与页面跟随浮层（`.wb-agent-follow`，右下 84 px）错开。用于保存成功、复制成功、导出完成和可撤销的删除。错误仍然显示在出错的控件旁边，不用 toast，以免一闪就看不到（B7）。
- 主按钮规则：每个视图最多一个主色按钮。页签、筛选和选中项一律不用主色实心（B4）。

### 6.3 层次与阴影

现在所有容器都是“白底加 1 px 灰边、没有阴影”，页面、卡片、菜单、弹窗看起来处在同一层，这是“像表格”的主要原因。定义三级：

| 层级 | 用途 | 样式 |
| --- | --- | --- |
| 页面 | 背景 | `--theme-bg` |

### 10.3 与方案的偏差

- **复选框和开关没有做成 React 组件**，而是用样式统一原生 `<input type="checkbox">`。涉及 25 处调用，改成组件需要逐个改受控写法；样式方案效果相同，也不影响现有测试的元素选择。
- **没有删除各模块的 `button` 通配样式**。这些规则还承担布局（高度、内边距、图标间距），删除后需要逐页补类名，这部分放到第 4 步逐页清理时做；本步只把它们的状态改成共享变量。
- 次按钮悬停时边框由默认边框色加深为控件边框色，方案原写“边框不变”。只改底色时浅色模式下变化太弱，加深边框后更容易察觉，又不会像选中。
- 制作记录弹窗打开时仍自动聚焦“管理本机数据”链接，标题与错误文案也未改，属于第 3 步 N8、N9。
