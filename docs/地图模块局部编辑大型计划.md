# 地图模块局部编辑大型计划

规划基线为 2026 年 10 月 31 日的本地工作树。目标是让用户在地图源图层或场景物件上框选一处，用自然语言说明想改什么，得到可比较、可修订、可定点采用的静态 PNG 候选。重点是选区内部的材质观感、结构与画风。角色和动画另走各自的制作流程。IntrinsicEdit 已从本计划移除，Godot 实时材质贴图属于独立的引擎功能。

## 已有基础

- **目标与采用。** 已有地图源图层、具备可验证源图映射的场景地图层、场景实例、交互物静态槽位和独立图片任务入口。它们共用版本与哈希检查、不可变基准、候选比较、定点采用和恢复。场景实例采用时派生独立素材。后续扩展沿用各入口现有的写入范围和锁。[图片编辑契约](../lib/workbench/image-edit-contract.mjs) · [采用与恢复说明](image-editing.md)
- **本地编辑与 AI 编辑。** 精确替色、调色板映射、擦除、移动等操作已可本地执行。普通 AI 编辑已能冻结完整尺寸基准图、硬蒙版、描述和参考图。选区外 RGBA 有编码后校验，保留 Alpha 时另核对本步基准的透明度。候选可按摆放尺寸比较。[意图分流](../features/image-edit/edit-intent.mjs) · [图片会话实现](../lib/workbench/image-edits.mjs)
- **规则拼板试验。** 已接通水平暗缝提示、可选本地 SAM 分板、手工补选和减去、平面金属反光预览、本地候选，以及带反光参考的 AI 草稿。一张带标注的合成木箱上，给定提示后的木板覆盖率为 99.15%。测试按标注补选了 45 个美术像素，最终 84,864 个目标源像素完成修改，其他像素及 Alpha 变化均为 0。该次浏览器验收覆盖了本地采用和共享实例隔离，AI 路径验收到草稿准备。[试验说明](image-editing.md#试验规则拼板换金属) · [试验回归](../tests/image-edit/metal-panel.mjs)

## 待实施的功能

| 工作项 | 当前缺口与待交付内容 | 验收示例 |
| --- | --- | --- |
| 1. 通用编辑计划与执行分流 | 当前能识别明确的像素命令，其他外观描述通常交给 AI。需要从描述中提取目标部件、变化类型、可改范围、保护要求、Alpha 策略、执行方式、验收条件和预算，并在提交前显示一条可修改的说明。 | 输入“只让铁门下沿生锈，保留铭牌”，能分别指出锈蚀区、受保护的铭牌及锈蚀分布要求。精确配色仍走本地操作。 |
| 2. 通用部件定位与结构保护 | 将拼板试验的点、框和手工纠正推广到装饰件、文字、曲线接缝、斜面与遮挡。分别表达用户授权范围、目标范围、允许的邻近影响范围。区分“原像素照留”与“保留边线位置、允许边缘重新着色”。 | 铁门换成石门时，铭牌逐像素保留，门板接缝保留走向并可重画倒角，旧拉丝纹理可被替换。无法确定的边界可由用户局部纠正。 |
| 3. AI 局部上下文、裁剪与回贴 | 目前的分割上下文、反光参考和摆放尺寸对照各有用途。待补的是通用生成路径中的局部推理副本、完整图和局部图的配合、材质／形状／风格参考的用途，以及从推理副本回到源图的坐标映射。 | 对缩放、翻转过的场景物件编辑小部件，回贴到正确的源像素。像素画按原网格检查，接缝过渡仅在授权区域内进行。 |
| 4. 更多材质与表面操作 | 平面金属亮带已能调节。待补通用材质替换、已知贴花与纹理叠加、具有方向或位置规律的表面处理，以及各类任务专用的保持条件。 | 同一块木板分别改为石板、拉丝金属，或仅在下沿掉漆。三者能分别检查旧纹理消除、拉丝方向、掉漆位置。 |
| 5. 分析后计算的保形换色 | 在精确配色之外，试验按需估计漫反射颜色 A、彩色明暗 S 和非漫反射残差 R，在正确色彩空间内将颜色变化量加回原图。建立与基准绑定的分析缓存，并在分解不可靠时回到简单颜色映射或普通编辑。 | 木门换色后仍能辨认原有木纹和明暗。与调色板映射、简单颜色映射及同预算生成比较，只有在对应素材上有净收益时才启用该分支。 |
| 6. 素材级独立复核与有限修订 | 当前有像素差分、Alpha 校验、变暗告警及人工对比。场景协作已有独立复核机制，待接到单图局部编辑，按本次计划核对目标、结构、材质、画风、接缝和透明边缘。 | 候选保护区变化为 0，但木板只是变灰、仍有木结时，复核能标出残留位置。审美偏好、明确缺陷与证据不足分别记录，仅在已设预算内针对缺陷修订。[场景复核实现](../lib/workbench/scene-workflows.mjs) |

材质操作还应覆盖三类有不同验收要求的任务。**磨损与覆盖**要能指定锈蚀、积灰、刮痕或掉漆的作用部位和分布。**部件替换**要允许宝石切面、浮雕等内部结构变化，并分别约定外轮廓、锚点和需核对的交互范围。**透明、透光和发光观感**要明确是否改变实际 Alpha，并在明暗底色和场景中检查边缘。交付单位仍是静态图片候选。

## 候选需要补齐的记录

已有候选保存目标版本、基准、区域、执行参数和像素证据。后续把下列信息绑定到同一个候选，便于定位失败原因和从同一基准重新比较。表中的名称表示拟议的记录职责。

| 记录 | 待保存的信息 |
| --- | --- |
| `EditPlan` 编辑计划 | 用户原意、确认的部件和操作类型、硬保护、视觉保持目标、执行方式、预算与验收条件 |
| `ContextBundle` 输入上下文 | 基准版本与哈希、授权蒙版、局部视图、裁剪和缩放映射、各张参考的用途及来源 |
| `AnalysisBundle` 可选分析 | 结构提示或属性图、模型与权重版本、坐标和色彩空间、预处理参数、分解可信度与降级原因 |
| `ReviewReport` 复核结果 | 逐项硬校验、视觉结论、缺陷位置与证据、未确定项、修订原因与结果 |

换基准后重新校验上下文和分析缓存。每次生成与修订继续使用现有请求身份、版本检查和恢复记录。技术处理完成、视觉复核通过、用户采用分别记账。

## 待完成的真实素材评测

1. **诊断集。** 首轮拟选 24 个不同案例，按换色、材质替换、表面加工、磨损覆盖、部件替换、透明或发光观感六类各选 4 个。纳入像素和手绘素材、小目标、曲面与遮挡，标明需要保留和允许变化的位置。已有锁扣换宝石的单例调用可用于复盘蒙版与定位问题。
2. **配对对照。** 新流程冻结后，拟用 40 份素材各做 3 项任务，共 120 例。按素材划分开发与测试集。基线使用现有手工选区、当前提示与同一图片服务，新流程使用辅助定位、材质计划和复核。固定候选数和总预算，并记录服务返回的质量档位。换色子集再比较简单配色与 A/S/R 分支。
3. **评价与采用门槛。** 在实际摆放尺寸和局部放大图上随机顺序盲评。分任务统计单次成功率、同样候选数下的成功率、严重伪影、复核误接受和误拒绝、人工修选与返修时间、每个成功结果的总调用和成本。每步保护区 RGBA 零变化，启用 Alpha 保持时透明度零变化。此前提出的“大幅改善”门槛可在试验前登记为重点任务成功率提高至少 15 个百分点、按素材配对的 95% 置信区间下界大于 0，同时严重伪影不增加、人工修补时间下降。该门槛属于待验证目标。

## 分批交付顺序

| 批次 | 交付与进入下一批的条件 |
| --- | --- |
| 第一批　建立基线 | 固定当前编辑流程、诊断样例和费用口径，能将问题归到定位、生成、合成或复核环节。 |
| 第二批　通用局部编辑 | 接通计划、部件纠正、局部上下文与素材级复核。通过小目标坐标回贴、选区保护、版本冲突及有限修订检查。 |
| 第三批　材质观感 | 优先覆盖同形状材质替换、表面加工和局部磨损。用真实素材对照决定各操作能否成为常规入口。 |
| 第四批　可选分析增强 | 在保形换色子集验证 A/S/R 的画质、耗时和维护成本，据此决定启用范围。 |
