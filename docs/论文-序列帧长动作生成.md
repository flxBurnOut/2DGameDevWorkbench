# 论文：序列帧长动作生成

> 状态：讨论记录（2026-11-08 建立），以本文最新内容为准。目标会议 IEEE CoG。
> 这是以序列帧工具为主体的论文方向。整体背景与其他已放弃方向见《论文方向与方法》。
> 实验规模、费用与统计口径尚未定稿，文中数字只作参考。

## 1. 一句话

**主题**：用现成的黑盒动画模型，生成长的 2D 游戏角色动作序列帧。

**主张**：先验证，再接续。长动作分段生成时，每段只从通过检查的真实末帧继续；检查不过就在段内修正，不把错误传给后面的段。这样生成的长动作错误更少，多花的检查成本可以接受。

暂定英文标题：*Verify Before You Chain: Checkpointed Generation of Long Sprite Animations with Black-Box Models*

## 2. 要解决的问题

- 现成的图生动画模型一次只能画一小段。本项目使用 PixelLab `/v2/animate-with-text-v3`：输入首帧图片、动作文字、可选末帧图片，输出若干帧；单次请求像素预算 524,288（128×128 时约 32 帧）。
- 长动作只能分段，每段从上一段的结尾继续。前面出的错（装备消失、角色变样、姿势不对、接缝不连贯）会被带进后面所有段，越接越错。
- 生成器是闭源黑盒，无法修改模型本身，只能在**怎么编排、怎么验证、怎么修正**上下功夫。论文的贡献全部在这一层。

## 3. 方法：四个步骤

| 步骤 | 做什么 | 当前工具里的做法 | 主要代码（`Tools/SpritePipeline/sprite_pipeline/collaboration/`） |
| --- | --- | --- | --- |
| 1. 拆段并写清目标 | 把动作拆成最多 4 段，写清每段结束时应是什么样子 | **多专家规划**：外观、动作专家先独立观察参考图，策略专家综合，协调者写出最终方案。输出质量合同：关键姿势（3–6 个）、相机与朝向、支撑与发力、轨迹、物品归属、节奏、结束方式。每条要求标注来源（用户原话 / 参考图观察 / 专家建议）。绘图说明每段不超过 1000 字符 | `planning.py`、`planning_budget.py`、`planning_draft.py`、`executable_brief.py`、`contracts.py`、`quality.py`、`generation_conditions.py` |
| 2. 用真实帧检查这一段 | 检查这段的实际画面是否达到本段目标、是否保持角色与装备一致 | **多专家复核**：先做两次基础检查（观察全部帧，再审核）；再由外观、运动两位专家各自独立检查；有分歧时追加至多一次复核。复核结论分为"满足 / 明确缺陷 / 审美偏好 / 证据不足"。独立专家指出的具体矛盾，不能被后续复核一票清除，保留给人工裁决 | `checkpoints.py`、`production_review.py`、`independent_review.py`、`dispute_review.py`、`visibility_review.py`、`visual_review.py` |
| 3. 通过后用真实末帧接下一段 | 下一段的首帧必须是这一段确认过的真实最后一帧 | 人工确认后，本段存为不可变快照并记录哈希；下一段读取时重新校验哈希，不一致就停止。不用想象出的端点替代，不倒放、不补帧。目标姿势提前到达时，可以人工选一个真实帧作为本段终点 | `checkpoints.py`、`execution.py`、`targets.py` |
| 4. 没通过就修，不传下去 | 在段内修正，或重画本段 | **逐帧修改**：只修本段内部的一个窗口，段首段尾不变。两种方式：外观编辑（128 像素一次 2 帧；64 像素 2–14 个偶数帧）、过渡重画（4–16 个偶数帧，用窗口真实首尾引导）。每段最多两次修复。选帧修改可涂选区域，区域外像素逐像素保护；分别判断"目标是否达成"与"未要求内容是否保持" | `repairs.py`、`adjustments.py`、`adjustment_regions.py`、`adjustment_review.py`、`adjustment_comparison.py` |

可选辅助（不在主流程上）：

- **角色结构**（`structures.py`、`structure_parser.py`、`structure_control.py`）：本地 SAM 2.1 分割 + 一次语义模型调用，得到部件、锚点与关系。可用于第 1 步规划。
- **时序追踪**（`tracking*.py`）：在实际帧上追踪部件，可辅助第 2 步复核。
- **近静止提示**（`motion_evidence.py`）：像素变化只提示可能停顿的帧对，不作结论。

## 5. 和已有工作的区别

| 工作 | 做法 | 区别 |
| --- | --- | --- |
| Sprite Sheet Diffusion（2024/2025） | 扩散模型按姿势序列生成精灵图 | 需要事先给出姿势序列；本文只需动作描述，且使用黑盒生成器 |
| Keyframe-Anchored Identity Preservation（2026） | 先生成一串关键帧，再在关键帧之间填充 | 关键帧是想象出来的；本文只从真实生成并通过检查的帧接续 |
| EM-Vid（2026） | 指出关键帧链会漂移，用实体记忆解决 | 说明漂移是公认问题；本文用验证而非记忆 |
| Agent Sprite Forge（开源 Agent 技能） | 每个动作一次图生视频，生成联系表供 Agent 查看 | 最接近的实际竞品；无分段、无检查点、不处理评审分歧 |
| Is Your Video Language Model a Reliable Judge?（ICLR 2025） | 简单聚合多位模型评审不提升可靠性 | 支持"保留矛盾而不是投票" |
| Each Judge Its Own Yardstick（2026） | 把评审分歧当信号 | 方向一致，可引用 |
| VLM 评审失效模式研究 | 模型评审对细节缺陷敏感度低 | 说明为什么人工裁决不能省 |

尚未找到"黑盒首/末帧模型 + 验证后接续 + 保留评审矛盾"用于长精灵动作的工作；正式写作前需在 CoG、FDG、AIIDE、SIGGRAPH Asia 及 arXiv 补查。

## 6. 研究问题

- **RQ1 失败刻画**：黑盒模型分段生成长动作时，会出现哪些失败？分别出现在哪一段、是否随段数累积？
- **RQ2 接续策略**：在相同帧数与预算下，"验证后接续"相比其他接续方式，错误是否更少？
- **RQ3 复核可靠性**：多专家复核与人工判断的一致程度如何？保留矛盾规则拦下多少误判，代价多少人工裁决？
- **RQ4 成本**：验证与修正需要多少额外模型调用和人工时间？什么情况下模型复核就足够，什么情况下必须人工？

## 7. 实验设计（草案）

### 7.1 回顾性分析（对应 RQ1、RQ3；无新增生成费用）

- 数据：用户 Windows 机器上的真实作业，含每段的实际帧、复核记录、人工裁决和修复记录。
- 做法：按失败类型（漂移、装备消失或增生、身份改变、朝向错乱、接缝不连贯、目标姿势提前到达）人工标注，统计各类型出现的段位置；把模型复核结论与人工裁决对比。
- 注意：已有作业经过人工筛选，存在选择偏差，结论只作描述，不作因果比较。

### 7.2 接续策略对比（对应 RQ2、RQ4；核心实验）

同一批动作、相同段数、帧数、FPS、种子与参考图，比较：

| 组别 | 做法 |
| --- | --- |
| 一次生成 | 在单次请求上限内一次画完 |
| 盲目接续 | 自动用上一段真实末帧接续，不检查 |
| 关键帧先行 | 先生成各段末姿势图，再用首/末帧条件填充 |
| 模型验证后接续 | 只由模型复核决定是否继续，不通过则按规则修复 |
| 人工验证后接续（本文完整方法） | 模型复核 + 人工确认 + 修复 |

指标（待定）：动作是否完成（计划的关键姿势是否出现）、装备与身份一致、接缝连贯、盲评可用率；额外调用次数、费用、人工检查时间。

### 7.3 消融（对应方法组成部分）

- 去掉独立专家，只用基础检查。
- 去掉保留矛盾规则（改为以最终复核为准）。
- 去掉逐帧修复（失败只能整段重画）。
- 加 / 不加角色结构辅助。

## 8. 现有证据

均为开发验收，文档已注明不是准确率或泛化证明：

- 2026-10-28：同一角色"向前挥砍"完整走完四位专家规划与本地校验，4 次 Kimi 调用，最终说明 746 字符。
- 三次授权验收累计 14 次 Kimi、10 次 GLM、0 次 PixelLab。
- 可见性校准用三份旧素材：失败的修改中，两位独立专家指出外形问题，最终复核误判为通过；保留矛盾规则把它留给人工，用户拒绝的状态不变。这是"保留矛盾"有用的单一实例。
- 结构追踪：一个 16 帧单样本，首帧人工纠正改进了后续追踪。
- 绘图条件策略 1/2 的对照未证明普遍收益，未设为默认。

本机（macOS）没有作业数据，真实作业在用户的 Windows 机器上。

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| "有人工确认当然更好" | 同时比较无检查、仅模型检查、模型 + 人工三种检查点，说明人工花在哪里、何时可省 |
| 只依赖一个闭源生成器 | 考虑加入一个支持首/末帧条件的开源视频模型作第二生成器（可用性待确认） |
| 生成费用 | 先查 PixelLab 单价，按实验组别估总额，再定规模 |
| 现有证据过少 | 正式结论只来自新实验；开发样本只作动机说明 |
| 模型复核本身会误判 | 这正是 RQ3 的研究对象；人工标注作为真值 |
| 像素风格与小尺寸（64/128 像素）使评审困难 | 盲评时同时提供原尺寸与放大视图 |

## 10. 论文结构草案（8 页）

1. 引言：游戏需要长动作序列帧；黑盒模型分段生成会累积错误；本文主张先验证再接续。
2. 相关工作：精灵与像素动画生成、长视频与关键帧接续、模型评审可靠性、混合主动内容生成。
3. 问题设定：黑盒首/末帧模型、分段上限、失败类型（来自 RQ1）。
4. 方法：四个步骤；合同、检查点、复核与保留矛盾、段内修复。
5. 实验：回顾性分析、接续策略对比、消融。
6. 结果与讨论：错误、成本、人工何时必要。
7. 局限：闭源生成器、像素尺寸、样本范围。
8. 结论。
