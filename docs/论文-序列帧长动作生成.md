## 1. 核心痛点、洞察与故事线

### 1.1 为什么 2D 游戏精灵不是普通短视频

通用图生视频/动画生成容忍轻微的像素抖动、轮廓漂移或道具微变；但 2D 游戏精灵是绑定了**硬性游戏不变量（Hard Game-Readiness Invariants）**的状态机资产——包括锚点（Anchor）、碰撞底座（Collider Footprint）、角色装备持久性以及交互物多状态间的静态外壳对齐。

现成的商用/黑盒动画模型普遍属于**短视界端点条件生成器（Black-Box Short-Horizon Endpoint-Conditioned Generators）**：每次只能生成一小段帧序列，权重与内部状态不可访问、不可微调，且通常缺乏原生空间蒙版或骨骼控制接口。制作长角色动作或交互物多状态链（A→B→C）时只能分段接续。

### 1.2 核心洞察（Key Insight）

全栈开发与先导实测揭示了黑盒 2D 游戏精灵链式生成的三大深层矛盾：

1. **隐性不变量漂移与 VLM 的双向失灵**：黑盒模型分段接续时最致命的不是明显画崩，而是**“视觉上看似合理、但破坏游戏不变量的隐性漂移（Plausible-but-Invalid Drift）”**（如底座漂移数像素、铰接杆身伸缩、手持装备悄悄消失、段间姿态跳变）。单纯引入 VLM 复核会同时触发两类系统性错误（全文统一使用方向明确的表述，避免不同口径对“假阳性”的定义冲突）：
   - **错误拒绝（False Rejects，代码中 `score_reviews` 记作 `false_positive`：真通过却判失败）**：把正常遮挡（occlusion）、透视缩短（foreshortening）或挥砍拖影误判为“武器消失/断裂”，或将规划专家脑补的细节误作用户硬性要求；
   - **错误放行（False Accepts，代码中记作 `false_negative`：真失败却判通过）**：综合复核抹平独立检查发现的局部缺陷，或 VLM 对像素级固定底座变化与刚体杆长伸缩存在系统性盲区（2026-11-11 拉杆真实付费序列中，基础审计三项全通过，外观专家发现固定斜撑缺失且争议复核已将 `fixed_parts` 判为失败，但所有 VLM 角色均一致漏判了 `transition` 维度中的主杆长度伸缩；主评 Agent 从原始像素人工发现并拒绝后，后续归档掩码重放测试中确定性铰接半径探针在第 4–8 帧成功定位该主杆伸缩异常）。
2. **仅靠生成模型无法一刀切覆盖所有游戏资产**：柔性角色动作依赖生成模型表达有机姿态变化，但交互物往往包含强刚体底座、精确绕轴旋转、纯色变指示灯与对称开关过渡——强行把所有维度全交给概率黑盒生成既低效又不可靠；同时，通用大图模型（1024px）与像素动画模型（128px）之间还存在跨分辨率网格断层。
3. **无原生蒙版下的“零渗漏 $\neq$ 接缝连续”**：当黑盒动画生成器不支持原生空间蒙版、只能靠本地后合成保护区域外像素时，域外逐像素零改动并不自动保证选区边界连续或帧间不跳变（2026-10-27 实测证实：区域外 RGBA 零变化下，刀刃投影角度跳变仍导致人工拒稿），因此局部修复必须同时具备**程序强制零渗漏、成本递增分级与前后解耦对比复核**。

### 1.3 全文故事线（痛点 → 洞察 → 方法 → 验证）

- **痛点**：黑盒短视界生成器在分段制作角色长动作与交互物状态链时，隐性不变量漂移跨段累积；直接引入 VLM 自动验证会同时受困于遮挡错误拒绝、几何盲区错误放行与规划器目标漂移，而盲目重绘导致高昂费用与帧间闪烁。
- **洞察**：游戏级可用性不能指望黑盒生成器或 VLM“自觉靠谱”，而必须构建两道支柱：① **程序化认识论守护（Programmatic Epistemic Guardrails）**——用本地确定性逻辑约束规划来源、视觉证据自洽与三层不沉默覆盖，区分绿灯段与告警段的人类审查负担（将“选择性人类注意力”作为待实测假设）；② **生成式与确定性混合管线（Hybrid Generative-Deterministic Pipeline）**——按资产不变量属性分流，用确定性像素化桥梁（`PixelProp`）、零渗漏分级修复与交互物领域原语守住刚体与静态不变量。
- **方法**：提出 **Verify Before You Chain (VBYC)** 混合主动框架，围绕三大核心机制落地：① 防偏见与可编译的状态转移合同；② 程序化认识论守护下的非对称检查点门控；③ 跨分辨率桥接、分级零渗漏修复与交互物混合确定性原语。
- **验证**：以历史真实角色作业的零成本回顾研究建立失败分类学与动机（Section 3.2）；在统一冻结协议下开展角色主实验（评估工作流净效应与**游戏可用率–API 成本–人工耗时**权衡）、六项非对称复核指标与 2×2 离线反事实消融（解耦基线、独立专家保留矛盾与确定性探针的各自效应）、分级修复与 `redraw_only` 消融，以及交互物多状态链与混合确定性原语实测。

## 2. 核心学术贡献（Contributions）

1. **统一问题建模与 2D 游戏精灵链式生成的实证失败分类学**：将角色长动作分段与交互物多状态链（A→B→C）抽象为黑盒短视界端点条件生成器下的带不变量状态转移问题（与具体商用 API 解耦，PixelLab 仅作测试平台实例化）；结合历史真实作业与受控实验，提出针对 2D 像素游戏精灵的实证失败分类学，区分柔性角色漂移与刚体交互物不变量违背，并实证揭示 VLM 几何盲区与黑盒后合成“零渗漏 $\neq$ 接缝连续”等关键边界。
2. **贯穿规划—复核—检查点的程序化认识论守护（Programmatic Epistemic Guardrails）**：
   - **规划上下文隔离与确定性编译**：角色外观首次独立观察隐藏动作文本（满足结构化格式且无追问/裁图时启用 `reference_only=True`，并支持条件匹配下的跨版本零费用复用）、用户要求逐字引证校验与自动来源降级、基于已核对可见部件的 `structure_usage` Schema 白名单与服务端校验、预算保留式延迟质询，以及策略 6 的确定性 12 槽合同编译（剥离协调者自由写 prompt 权限，确定性映射段内帧号并严守上限不截断）。
   - **多尺度取证与双向逻辑门控**：先逐帧客观取证后合同审计（Observe-Before-Audit）、同模型上下文隔离多视角审计、共享全序列联合包围盒的最近邻放大聚焦证据图、最小帧证据门槛与非对称置信阈值（0.80 vs 0.85）、结构化可见性证据一致性守卫（`verified_geometry=False`，双向拦截无依据的缺陷声明与未解决的遮挡放行）、精确界定的三层不沉默覆盖（含依赖本地 PNG 直接解码输入 SAM 2.1 追踪的遮挡扣除固定区/铰接半径 Fail-Closed 探针），以及按作品版本哈希冻结的真实像素检查点与六项非对称复核指标及逐样本防退步门禁。
3. **生成式与确定性混合资产管线（Hybrid Generative-Deterministic Pipeline）及成本–质量权衡分析**：通过纯确定性跨分辨率像素化桥梁（`PixelProp`：默认 24 色加权中位切分、>64 色启用 OKLab 3D KD-Tree 量化与可重算 `pixelSha256` 核验）贯通大图模型与像素动画模型；提出覆盖静态参考图（四层空间集合代数部件属性计划 + 游戏摆放尺度盲评 + 原始返回归因诊断与零新增调用 `recompose-ai` 重合成，定位为系统能力与先导观察）与动画帧（四级分级修复 + 零额外调用前后解耦对比 + 选区全零变动硬判失败）的保不变性修复体系，并结合交互物确定性领域原语（遮挡感知固定区回填、不裁切边缘前景的固定区整数对齐校正、色表/旋转/反向派生）量化混合主动管线的可用率、API 费用与人工耗时权衡。

## 3. 问题抽象、统一表示与资产分流

### 3.1 黑盒短视界端点条件生成器抽象

不以特定 API 的参数定义问题，而是将其形式化为通用黑盒生成器接口 $G(I_{\text{start}}, p, I_{\text{end}}^{\text{opt}}, L, s) \to (F_1, \dots, F_L)$：
- 仅接受首帧真实图像 $I_{\text{start}}$、有长度上限的文本条件 $p$、可选末帧条件 $I_{\text{end}}^{\text{opt}}$、受限段长 $L \le L_{\max}$ 与种子 $s$；
- 内部权重、注意力与隐状态不可访问、不可微调，且无原生空间蒙版或骨骼硬锁定；
- 资产需求由目标状态变化集合 $\Delta$ 与硬性游戏不变量集合 $\mathcal{I}$ 组成，需经 $K$ 段链式接续产出满足引擎碰撞、锚点与状态机语义的序列帧。

测试平台实例化细节（PixelLab `/v2/animate-with-text-v3`：实验使用 64×64 或 128×128 像素画布、适配器单次上限 4–16 偶数帧、最多 4 段、提示词上限 1,000 字符、单次像素预算 524,288，具体作品预算另由任务参数约束；静态参考图使用 GPT Image 2.6 + `PixelProp` 桥接）统一置于实验设置中报告（本文第 7 节 / 投稿 8 页大纲第 5 节）。

### 3.2 角色动作与交互物状态链的统一表示与混合分流

两类对象共用同一套“对象身份、段、状态转移合同（$\Delta, \mathcal{I}$）、哈希检查点”表示，并按不变量刚性特征在生成式与确定性原语间分流：

| 概念 | 角色长动作（主实验：柔性有机运动） | 交互物多状态链（压力测试 + 混合确定性管线） |
| --- | --- | --- |
| 首帧参考 | 角色原图（64/128px；移送前含视角/朝向核对） | 128px 物品图（支持 PixelLab 生成、本地导入，或经 `PixelProp` 从 1024px GPT Image 确定性转换并重算核验 `pixelSha256`） |
| 一段（Segment） | 长动作中的一个动作阶段 | 一次状态过渡（A→B），可由显式状态骨架 `InteractableSkeleton` 硬校验分段数与状态名唯一性，并在规划提示中约束状态名顺序 |
| 检查点（Checkpoint） | 本段确认过的真实末帧 | 确认过的真实末帧，同时登记为具名 B 状态图；支持 `accept_state` 先锁定状态图（但后续生成接续仍要求前段过渡整体 `accepted`） |
| 多段接续 | 最多 4 段，逐段从真实末帧继续 | 状态链 A→B→C，逐个状态从真实状态图继续；末尾停留由 `hold_frames` 播放期重复末帧实现（仍受总计 64 帧上限约束，零生成消耗） |
| 可选末帧条件 | 外部目标姿势图 | 用户已有或色调派生的 B 状态图（启动授权绑定 `target_set_sha256`） |
| 动态目标 $\Delta$ | 关键姿势、支撑与发力、运动轨迹、节奏 | 目标终态外观、运动部件及其轨迹、终点停留 |
| 硬性不变量 $\mathcal{I}$ | 角色身份、装备归属、画布尺度与接缝连贯 | 固定部件/底座像素位置、锚点、轮廓外沿、刚体铰接半径（截图可观察不变量、程序硬校验与引擎行为分列验收） |
| 确定性兜底与派生 | L1 色表/像素补丁、后置 `frame_checks.py` 技术 QA | `T1` 固定区回填（遮挡保护来自人工框、可选参考结构掩码或 $\ge 64$ 通道差启发式）、`T3` 固定区评分+整帧不裁切整数对齐；另支持显式标注来源、与模型生成通过率严格分列的 `T5` 色表状态图 / `T8` 客户端枢轴旋转草稿 / `T9` 已确认播放帧反向过渡派生 |
| 产物去向 | Godot SpriteFrames 包 | 交互物编辑器切换槽、序列条目、过渡动画与 Godot 交互物资源包 |

**口径区分**：生成链检查点协议严格禁止自动倒放或伪造锚点以接续后续生成；交互物独立面板提供的确定性派生状态图与过渡（`derived_assets.py`）须独立记录来源哈希、经人工完整播放确认后才进入资产目录，且在论文实验中与模型生成样本严格区分统计。循环待机动画（如旗帜、火把）属另一类首尾闭环拓扑约束，不纳入本篇实验范围。

## 4. 方法：VBYC 三大核心机制

方法章节按三个与源码严格对应的核心机制组织，避免按操作步骤平铺流水账。

### 4.1 防偏见、来源可追溯与可编译的状态转移合同

- **首轮上下文隔离、角色外观隐藏动作文本与条件零费用复用**（`planning.py`、`planning_observations.py`）：外观专家与运动专家首轮相互隔离；对角色任务，当采用当前结构化规划格式、首次独立观察且无未决问题或裁图请求时，外观专家启用 `reference_only=True` **隐藏用户动作文本**，仅观察参考图本身（运动专家仍可见任务描述）。当用户修订动作描述且原图、对象快照、视觉结构、模型配置与策略版本均未变化时，零付费复用合格的外观观察。
- **逐字引证检查与程序强制来源降级**（`contracts.py` `bind_original_requirements`）：合同将每条约束标注为 `user / reference / expert`。程序将所有用户原文（描述、结束要求与状态骨架）拼成真值语料；凡 LLM 标为 `source="user"` 但 `evidence` 不是原文**精确子串**的条款，程序强制降级为 `source="expert"`，并将逐字原文显式注入合同（该检查核对引语出处而非语义蕴含，防止模型将臆测包装为用户明示要求）。
- **结构引用本地白名单与参考前提核对**（`structure_control.py`、`contracts.py`）：若附带已核对视觉结构，`bind_planning_schema()` 按该图**可见**的部件、锚点与关系 ID 重写 `structure_usage` 的 JSON Schema `enum` 并在服务端二次校验（部分兼容端点以 `json_object` 加提示传递 Schema，因此以服务端白名单校验为最终门禁）；在附带已确认结构快照时，交互物强制所有可见部件互斥完备地归入 `moving_parts` 或 `fixed_parts`，核对视角、初态与部件归属并对描述/参考差异分级，同时在规划前按账户余额与每段独立计费预检可行帧数。
- **有界主动观察与预算保留式延迟质询**（`planning_budget.py`）：专家可按需调用 `inspect_reference`（4× 最近邻局部裁图）或 `consult` 质询同伴；当剩余调用数不足以保障后续必选的 `strategy` 与 `coordinator` 时，`defer()` 自动延后可选质询并将其转交协调者处理，最终回合通过 `FinalStructuredCoordinatorTurn` 强制收敛。
- **策略 6 确定性 12 槽合同编译**（`planning_draft.py`、`structured_brief.py`）：策略专家先在放宽至 4,000 字符的分析草稿中推演全局方案；协调者定稿时，Schema 通过 `SkipJsonSchema` 禁止手写 `stage.prompt`，只填写结构化段目标、全局 `quality.key_poses`、运动约束与三态边界（`pass_through / settle / intentional_hold`，程序硬禁止 `pass_through` 的**声明停留范围**覆盖段末）。服务端确定性地把全局关键帧映射为段内局部帧号并编译为 12 行标准绘图简报，校验总长 $\le 1,000$ 字符，超限时返回逐行字符数并在剩余预算允许时由同角色单次自修正，绝不静默截断；且全局 `event_contract` 不作为独立字段下发单段绘图（实际画面是否提前抢演仍由分段复核检查）。

### 4.2 程序化认识论守护下的非对称检查点门控

不信任任何单次 VLM 口头结论，而是在每段均设显式 `awaiting_review` 人工检查点的基础上，用本地确定性逻辑构建**多尺度取证 + 结构化证据自洽校验 + 三层不沉默覆盖**的非对称门控（并将“绿灯段与告警段实际人工耗时分化”作为实验待测假设）：

1. **Observe-Before-Audit 两步基线 + 同模型上下文隔离多视角审计**（`visual_review.py`、`independent_review.py`、`production_review.py`）：
   - 基线 Call 1（`observe`）在不给质量合同的前提下，强制按 `[1..N]` 逐帧记录 `pose / equipment / change`（缺帧、越界或乱序即报错废）；Call 2（`audit`）才结合联系表、逐帧观察、合同与像素提示（`motion_evidence.py`）打分。
   - 采用专家协议时，随后由**同一配置 `reviewer` 模型**在隔离上下文下分别扮演外观专家与运动专家给出独立三态意见（`pass / fail / uncertain`；明确表述为 *Context-Isolated Multi-Perspective VLM Auditing*，非多模型集成）。无分歧时合计 4 次调用；存在分歧、低置信度或共同 `uncertain` 时追加至多 1 次争议复核（合计最多 5 次，输出四分类：`satisfied / material_defect / preference / insufficient_evidence`）。
2. **共享源坐标最近邻放大聚焦证据图**（`dispute_review.py`）：争议复核先以轮询策略覆盖各争议维度并补入首尾与 $\pm 1$ 邻帧（$\le 12$ 帧），再计算整段所有帧的非透明联合包围盒（Union BBox $\pm 3\text{px}$），以**完全相同的源坐标裁切盒与最近邻缩放**拼成每块 320×320、每页最多 6 帧的放大图板（合成至显示底色，显式标注非原始透明背景）——在不丢失跨帧绝对位移基准的前提下让 VLM 细查像素级漂移与断裂。
3. **程序化双向认识论守护**：
   - **最小帧证据门槛与非对称置信阈值**（`visual_review.py`、`checkpoints.py`）：统一核验所有引用帧满足 $1 \le f \le N$；`completeness` 引用不同帧 $< \min(N, 3)$、时序维度（`rhythm / transition / fixed_parts`）引用 $< 2$ 帧时，程序强制降级为 `uncertain`；汇总判定中 `fail` 置信门槛为 0.80、`pass` 门槛为 0.85（低于门槛的原始逐维状态仍完整留存，但汇总绝不直接放行）。
   - **结构化可见性证据一致性守卫**（`visibility_review.py` v4）：作用于 `equipment`（角色）与 `fixed_parts`（交互物）维度，强制专家与争议调用返回 `VisibilityFinding`（`observation / explanation / expected_visibility / finding / contradiction_frames / before_frames / after_frames`），并在追踪记录中显式标记 `verified_geometry=False`（说明其检验的是模型自报证据的内部自洽性，而非真实 3D 几何重建）。本地 `guard()` 双向核验——**拦错误拒绝**：判 `fail` 却缺少合法可见矛盾帧或合理解释排除则降为 `uncertain`；**拦错误放行**：判 `pass` 但证据含未解决不可见项（且 `not_visible` 须提供观察区间之外的真实前后上下文帧，禁止仅重复观察帧凑数）或可见矛盾则降为 `uncertain`。
   - **三层精确界定的不沉默覆盖（No-Silent-Override）**：
     - *基线全维度保护*（`dispute_review.py`）：争议复核试图将基线非 `pass` 维度改为 `pass` 时，保留原提案但强制降为 `uncertain` 交人工裁决；
     - *独立专家可见矛盾与空复核保护*（`visibility_review.py` v4）：在 `equipment` / `fixed_parts` 维度，若独立专家以 $\ge 0.8$ 置信度提出有结构化可见证据支撑的 `fail`，后续争议复核单方面“翻案通过”无法清除；此外，若独立专家提出可见性疑点而争议复核仅提交空 `items=[]` 试图判 `satisfied`，程序同样截留交人工裁决；
     - *遮挡扣除确定性探针 Fail-Closed 保护*（`prop_measurements.py`）：对绑定了已核对结构与探针策略的交互物，使用本地 SAM 2.1（经绕过 JPEG 中转的 PNG 直接解码输入，`Tools/VisualStructure/tracking.py`，仍含灰底合成、RGB 转换与缩放）逐帧追踪运动部件掩码，先从原图/当前帧像素差（最大 RGBA 通道差 $\ge 64$）中**扣除可见运动部件遮挡区**再统计固定部件变动像素（阈值 $\max(4, \lceil 10\% A_{\text{ref}}\rceil)$），并对铰接运动计算固定参考枢轴到端点部件投影质心的半径偏差（容差 $\max(2\text{px}, 22\% R)$）。若模型判 `pass` 而探针报警、或追踪不可用（Fail-Closed），均强制降级交人工裁决（若报告已有 `fail` 则保留 `fail`）。
   - *旁路扩展与评测守卫*：带时序结构的旁路评测分支还内置**逐字用户原话引证守卫**（`structure_judgment.py`，非精确子串的 `explicit_user_requirement` 缺陷直接拦截）；离线评测工具内置**六项非对称复核指标**（同时支持角色与交互物两套三维度，并区分准则级计数与报告级 `failed_reports`）与冻结语料上的逐样本防退步门禁（`review_evaluation.py` `comparison_gate`，泛化性须由独立保留集验证）。
4. **按作品版本哈希冻结的真实像素检查点与帧归一化**（`checkpoints.py`、`drawing_frames.py`、`state_chain.py`）：按 `input_pose_v1` 校验多余回传首帧（仅在恰好多返回 1 帧且首帧与输入图 Alpha 包围盒一致、黑底可见像素按 Alpha 并集面积归一化的 RGBA 均值差 $\le 0.006$ 时剥离输入上下文帧）；人工确认后复制真实播放帧为该作品版本下的不可变快照并记录 PNG SHA-256（启动授权另绑定 `target_set_sha256`），下一段启动前重验前段确认帧与当前所需目标图（整片编辑采用时另建新版本并重绑新版本内部帧与 token）。目标姿势提前到达时支持显式人工截尾锚点（`anchorFrame`），交互物支持 `accept_state` 先锁状态图、后修过渡。

### 4.3 混合确定性管线与分级保不变性修复协议

将静态参考图制作、跨分辨率桥接与动画段内/整段修复收束于同一套**不可变来源、分层空间保护、解耦评估**契约之下：

- **跨分辨率确定性桥梁 `PixelProp`**（`Tools/PixelProp/`）：面向 GPT Image 1024px 静态物品图与 128px 像素动画接口之间的网格断层，默认采用预乘 Alpha `BOX` 缩放（另提供 `dominant` 众数与 `nearest` 替代配方）与无随机数 24 色加权中位切分（调色板 **$> 64$ 色**时启用 OKLab 3D KD-Tree 加速，小表走精确线性最近邻，`colors=0` 且无显式调色板时跳过量化），并按 Alpha 包围盒裁切、重新对齐与二值化 Alpha（重建网格与锚点）；移送前按规范化配方哈希 `recipeSha256` 重算并核对**解码像素哈希 `pixelSha256`**（可重算核验，像素不一致即拦截），辅以人工视角/初态/完整性确认进入状态链流程。
- **静态参考图阶段——系统能力与先导观察**（`image-part-planner.mjs`、`attribute-plan.mjs`、`image-edit-critic.mjs`）：
  - 以三视图（整图、依赖 `localContext` 与槽位余量的洁净局部裁图、绿色授权区）定位部件并生成五维属性提示策略（`shape / texture / albedo / lighting / reflection` $\times$ `preserve / edit / recompute`），以集合代数 $\text{mask} = \text{allowed} \cap (\text{target} \cup \text{influence}) \setminus \bigcup \text{protect}$ 生成精确可写蒙版（空间硬约束来自蒙版）；
  - 编码后重新解码 RGBA8 核验域外四通道逐字节一致（开启 `preserveAlpha` 时自动禁用低 Alpha 清理以防黑边）；
  - 独立 Critic 先用 6 视图（含按已保存摆放尺寸或默认 64px 渲染的 placement 对照图，图块上限 320px）盲评四维指标与原图坐标缺陷；若未通过，可单独发起 Phase 2 归因诊断，对比归档的 `provider-response.png` 与有效/最大授权蒙版，统计原授权内、有效写区外、原图非透明像素的 RGB 差异（`excludedVisibleChanges`）——在同会话同基准且前后锁 Alpha 条件下，区分“模型画对但被过窄蒙版切掉 → 零新增生成调用 **`recompose-ai`** 本地重合成”与“模型本身画错 → 修改计划”。（静态图编辑与 `PixelProp` 在 8 页主文中作输入来源与系统能力交代，完整实现细节与先导观察可放补充材料。）
- **动画帧四级保不变性修复协议**（`local_frame_edits.py`、`adjustments.py`、`adjustment_regions.py`、`adjustment_comparison.py`、`frame-tools.ts`、`experiment_policy.py`）：

| 级别 | 修正手段 | 是否调用模型 | 空间保护与约束分层 |
| --- | --- | --- | --- |
| L1 确定性像素与交互物领域原语 | 单帧/跨段精确替色与色表映射（≤64 对）、擦除/填充/补丁/区域恢复（拒绝零像素空改动）；交互物专用 `T1` 固定区回填（遮挡保护来自人工框/参考结构掩码/$\ge 64$ 启发式）、`T3` 固定区评分+整帧不裁切整数对齐校正、`T4` 批量清理（另提供显式标注来源的 `T5/T8/T9` 零生成派生） | 否 | 0 API 费用、不占每帧绘图次数、跳过锁定边界、提交后服务端逐帧核验提交授权区外 RGBA 零改动 |
| L2 区域锁定受限生成 | PixelLab 外观编辑（128px 一次 2 可编辑帧、64px 2–14 偶数帧，另含 2 张上下文帧计入调用）+ 显式绑定 `FrameEditRegion` 且 `preserve_motion=true` 时的本地二值后合成 | 是 | **诚实边界**：PixelLab 无原生空间蒙版，靠文本坐标框 + 本地二值后合成保证授权区外 RGBA 零渗漏；2026-10-27 实测证实“零渗漏 $\neq$ 接缝连续”，必须叠加解耦对比评审与人工播放 |
| L3 段内窗口重绘 | 过渡重画（4–16 偶数帧），保持窗口外帧不变，以窗口端点图作为生成条件引导 | 是 | 传统 `LocalRepairs` 限每段 2 次、独立修改限每帧 2 次；禁止静默把外观请求改路由为动作重画 |
| L4 整段重画 | 覆盖当前段最大合法偶数可编辑窗口的过渡重画（首尾都锁时为 $N-2$ 帧；仅锁首帧时为头/尾对齐 $N-2$ 帧；存在内部 `state_checkpoint` 时取其前序可播放区间的最大合法偶数窗，均需 $\ge 4$ 帧） | 是 | 作为兜底范围（按实际请求槽位计费，不先验断言必然最贵）；消融副本 `--repair-policy redraw_only` 限定只允许此级 |

- **复用现有调用上限的前后解耦对比与零改动硬拦截**（`adjustment_comparison.py`）：动画备选复用既有 2/5 次复核预算（若对比发现分歧可触发第 5 次争议复核），同步拼入原版对照与青色授权区叠加图，分开输出 `change`（目标达成）与 `preservation`（未要求内容保持）；目标改善不能抵消退化，且一旦本地统计发现**所有记录选区**的 `changed_inside_pixels == 0`，无论 VLM 如何评价一律硬判 `change=fail`（`no_pixel_change`；当前采用端在无技术硬失败时允许人工写明依据显式确认告警，实验中须预先规定采用规则）。

## 6. 研究问题（Research Questions）

- **RQ1（失败分类学与跨段传播机理）**：黑盒短视界生成器在分段生成 2D 游戏精灵时会出现哪些破坏游戏可用性的失败？隐性不变量漂移如何随段数累积（同时报告到达各段的样本数与退出率）？柔性角色与刚体交互物的失败谱系有何差异？
- **RQ2（工作流对比与人类注意力权衡）**：在相同冻结方案、种子与预算下，各接续工作流在**游戏可用率（Game-Readiness）**与**API 费用 / 人工检查耗时**上的权衡如何（同时区分全任务覆盖率与各组共同可行的配对子集）？程序化认识论门控是否将人类时间主要集中在高风险/告警段？
- **RQ3（VLM 双向失灵与程序化认识论守护收益）**：纯 VLM（含多视角汇总）在哪些场景产生错误拒绝（如遮挡当消失）与错误放行（如刚体漂移/杆长伸缩漏检）？按**六项非对称复核指标**（错误拒绝、错误放行、漏检缺陷、不必要拦截、争议过早定论、报告失败率）与 2×2 离线反事实消融，“独立专家”“保留矛盾规则”“双向可见性守卫”与“确定性探针”各自贡献多少段级纠错收益与弃权代价？
- **RQ4（混合确定性原语与分级修复的性价比）**：相比仅允许整段重画（`redraw_only`），四级保不变性修复对角色动作的修复成功率与 API 费用有何影响？在交互物场景中，引入 `T1/T3` 确定性原语与 `PixelProp` / 派生路径能在多大程度上突破纯黑盒生成器的刚体瓶颈？

### 7.1 动机回顾性研究（前置至 Section 3.2；对应 RQ1、部分 RQ3；零新增生成费用）

- **数据**：Windows 机器历史真实角色作业（待按 `PAPER-01` 执行 `EXP inventory` 清点 `full` / `legacy` 数量与分段复核记录；注意 `legacy` 仅支持整片标注，`reviewed_stages` 仅反映是否存在报告或历史，导出时按实际完成状态筛查）。
- **方法**：标注失败类型（身份改变、装备消失/增生、朝向错乱、接缝断裂、锚点偏移、姿势提前到达），统计各段位分布并交叉比对模型复核与人工裁决；明确声明因存在筛选偏差，仅作描述性动机研究与失败分类学来源，不作因果比较。

### 7.2 角色主实验：工作流对比与帕累托权衡（对应 RQ2、RQ4）

在同一冻结方案（提示词、段数、帧数、FPS、种子、参考图与预算上限）下比较 5 组，主结论明确定位为**完整工作流的净效应**（待按 `PAPER-07` 统一跨组绘图预算账本，并可选追加同权限裁决者对照以单独归因“验证”效应）：

| 组别 | 代码标识 | 做法与公平性设计 |
| --- | --- | --- |
| 一次生成 | `single` | 单次画完；对策略 6 的 12 行结构化简报执行确定性共享头去重与姿势路标帧号平移（绝不截断；`End`/`Boundary` 取末段，无法接收中间段绑定末图），超 1,000 字符或合计超 16 帧按 `blocked_preflight` 计入全任务分母（`PAPER-04` 已修复）。同时在**各组共同可行的配对子集**上单独比较 |
| 盲目接续 | `blind` | 自动用上一段真实末帧接续，无复核、无修复（保留固定段位的可比漂移轨迹） |
| 从 A 图生成的未验证端点提案 | `keyframe_first`（待 `PAPER-02` 拍板命名及小样本静态关键帧对照） | 每段（未绑定外部末图时）均从**原始 A 图**出发执行 4 帧终态提案（超 1,000 字符的 12 行简报确定性提取终态核心行，`PAPER-04` 已修复）冻结其末帧，再首末图填充；按有无外部末图分层统计 |
| 仅模型验证后接续 | `model_only` | 在真实流程内仅按固定规则由模型复核自动裁决（程序已禁止人工通过 API/Checkpoints 介入解锁），未通过时执行至多一次段内偶数窗口重绘（`repairs.py`，要求段长 $\ge 6$ 帧）；跨组预算对齐与整片 QA 结局判定跟进 `PAPER-07` |
| 认识论门控 + 人工确认（完整方法） | `human_verified` | 完整 VBYC 门控 + 四级保不变性修复工具集 + 人工裁决与计时（`human_seconds` 记决策秒数，正式实验另记规划/选区/排错等主动人时与等待时间） |

- **三重终点与盲评方式**：预注册并分开报告三个终点——① 完整候选生成率、② 生产技术 QA 通过率、③ 独立盲评游戏可用率，公开各环节失败流转。通过 `blind_pack` 生成匿名离线盲评包（1× 原尺寸 + 适配容器宽度的整数倍最近邻放大双视图、棋盘格/深浅背景切换、非循环动作默认播完即停与单帧步进；已校验帧尺寸一致、拒绝重复目录并纳入无 Job 的 `model_only` 预检拦截）；正式付费实验前按 `PAPER-09` 补齐预注册 `run_id` 对账清单并在盲评页展示任务需求与参考图。仅在多个冻结预算/人力运行点上主张帕累托前沿，单运行点表述为“观察到的非支配结果”。

### 7.3 交互物实验：刚体不变量压力测试与混合确定性管线（对应 RQ1、RQ2、RQ3、RQ4；小规模）

- **对象**：若干多状态交互物（覆盖色变/发光、铰接转动、形变与带遮挡刚体平移，按 PixelLab 原图与 `PixelProp` 转换图分桶描述；若主张桥接提升画质，须以同物同初态配对参考对照），构建 2–3 状态链（A→B→C）。
- **两层对比与三类通过率**：
  1. **纯生成接续压力测试**：对比 `blind` / `model_only` / `human_verified`（带 SAM 2.1 追踪 + `prop_measurements` 确定性探针），**分别报告状态图通过率、单条过渡通过率与整条状态链（A→B→C）通过率**（`hold_frames` 播放层规则在五组间统一跟进 `PAPER-08`，并另报生成器自身末段稳定性），衡量固定部件偏移、铰接半径稳定性与探针拦截错误放行命中率；
  2. **混合确定性原语增益观察**：在同一批失败源片段上做 `T1` 固定区回填与 `T3` 固定区对齐的配对修复测试（分别评估固定区改善、运动区副作用、人工标注时间与可处理比例），并预注册 `T5/T8/T9` 的适用对象与人工端点验收标准，将其成本与可用率与纯模型生成结果严格分列报告。

### 7.4 消融实验（对应三大机制与六项非对称复核指标）

`counterfactual_verdicts` 现已输出完整的 **2×2 离线反事实矩阵**及逐维 `checks_by_condition`（可直接接入支持角色与交互物双口径的 `score_reviews` 评分），且在存在 `adjustment_comparison` 失败时保留独立门禁、对争议提议重新执行 `grounded_audit` 最小帧门槛校验；注意离线重算度量的是**段级决策敏感性**，不等同于在线换锚后的后续段展开：

| 消融项 | 对照做法 | 新增付费生成 | 回答的问题 |
| --- | --- | --- | --- |
| 去独立专家与探针 | 离线重算 `review_ablation.baseline_only` | 否 | 相对 Observe-Before-Audit 基线的六项非对称指标增益（同时移除专家、争议与末端探针） |
| 2×2 消融：去末端探针守卫（保留矛盾开） | 离线重算 `review_ablation.without_probes` 与 `probe_overrides` | 否 | 撤回 `guard_measurements` 末端降级后的差异（注：基础/专家上下文仍可能见过 `tracked_parts` 线索；完全隔离探针上下文需独立重跑） |
| 2×2 消融：去保留矛盾规则（探针开） | 离线重算 `review_ablation.without_retention` 与 `retained_contradictions` | 否 | 仅移除 No-Silent-Override、保持探针开启时，争议翻案放行多少缺陷及对应弃权降幅 |
| 2×2 消融：同去保留矛盾与探针 | 离线重算 `review_ablation.final_review_wins` | 否 | 同时移除矛盾保留与末端探针后的联合敏感性 |
| 仅允许整段重画 | `EXP clone ... --repair-policy redraw_only`（`PAPER-05` 及内部 `state_checkpoint` 区间切分已修复）对比完整四级工具集 | 是 | 分级修复省下多少调用次数、费用及 L1–L4 工具选用与采用分布 |
| 可选结构观察器 | 规划时加 / 不加已核对视觉结构与结构白名单 | 是 | 结构辅助对规划与跨段稳定性的边际影响 |

## 9. 现状、已有真实证据与剩余缺口

截至 2026-11-20，核心架构、实验脚手架、跨平台回归门禁及本轮 Codex 三路深度审查定位的实验与管线高危边界均已完成代码修复并补充单元测试回归（包括 2×2 反事实矩阵与比较结论保真、角色/交互物双口径 `score_reviews`、v2 历史回放提示词保真、内部 `state_checkpoint` 下 `redraw_only` 区间切分、`model_only` 防人工越权拦截、v4 空争议可见性保护、视觉不完整响应回执保留、派生资产原子发布与哈希校验、零像素空编辑拦截及 `T3` 不裁切边缘保护）。

**已有真实模型与先导观察证据**：
- **规划稳定性（2026-10-28）**：角色“向前挥砍”走完四位专家与本机校验，4 次 Kimi 调用，定稿 746 字符；策略 6 经双模型首次定稿实测复验。
- **双向可见性守护实测（2026-10-28）**：三份旧素材校准中，认可主段武器遮挡由“确定丢失”纠偏为“遮挡/投影不明”（拦错误拒绝）；失败修改样本中两位独立专家识别出外形缺陷而综合复核误判通过，v4 矛盾保留规则将其截留给人工（拦错误放行）。
- **动画局部编辑实测（2026-10-27）**：三轮独立授权实测直接揭示“静默跨方法路由会破坏原动作”与“本地后合成虽达成域外 RGBA 零改动，但刀刃投影角度跳变仍需解耦对比与人工否决”。

- **静态图局部编辑开发期对照**：十项开发对照中，模型评审认为普通流程 2 张、带部件属性计划与洁净局部参考流程 7 张可用；全部 20 张域外像素零变化（属开发期模型意见，尚无独立人工盲评；保留进论文时须附完整配对记录）。
- **交互物两轮小测**：首轮直调 8 条仅指示灯 1 条合格，暴露带遮挡刚体平移（栅门）穿模倾斜；第二轮完整流程实际绘制 1 条拉杆（`examples/n2-pilot-round2-20261111/lever-2202/`），基础审计三项通过，外观专家与争议复核将 `fixed_parts`（缺斜撑）判为失败，但所有 VLM 角色均漏判了 `transition` 中的主杆伸缩；主评 Agent 人工拒绝该段后，后续归档掩码重放测试（`test_prop_planning_limits.py`）中确定性铰接半径探针在第 4–8 帧命中该主杆伸缩异常。

**正式付费实验前待闭环清单（已全部登记至 `docs/问题清单/`）**：
1. `PAPER-01`：在 Windows 机器执行 `EXP inventory` 清点并导出历史真实角色作业（零新增生成费用），产出 Section 3.2 失败分类学数据。

| “多专家听起来像多模型集成，实际是否同一模型？” | 正文明确界定为 **Context-Isolated Multi-Perspective VLM Auditing**（同配置 `reviewer` 模型、隔离上下文与独立视角镜头），绝不夸大为多模型集成 |
| “`single` / `keyframe_first` 基线被拼 prompt 规则冤杀或不够公平” | 已落地 12 行结构化简报确定性共享头去重与终态字段提取（`PAPER-04`），绝不截断、零模型调用；实验同时报告全任务覆盖率与**各组共同可行的配对子集**，并按 `PAPER-02` 准确重定性端点提案基线 |
| “交互物纯生成通过率太低，统一性是否失败？” | 交互物定位为**刚体不变量压力测试 + 混合确定性管线展示**，分列报告状态图、单条过渡、整条链三类通过率；纯生成暴露的刚体/遮挡缺陷成为 RQ1/RQ3 实证，同时以配对失败样本评估 `T1/T3` 确定性原语的挽救收益与副作用 |
| “确定性探针到底算不算无模型？” | 透明声明遮挡扣除与铰接半径探针依赖参考结构确认与本地 SAM 2.1（绕过 JPEG 中转的 PNG 直接解码输入，不调用外部付费 API），追踪不可用时采取 Fail-Closed 保护，并如实报告其阈值标定范围 |
| “无原生蒙版的区域编辑会不会有接缝？” | 主动把 2026-10-27 实测中“后合成零渗漏 $\neq$ 接缝连续”写成领域洞见，论证为何必须叠加 `comparison_protocol=1` 前后解耦评审与人工播放 |
| “像素小图盲评看不清细节或非循环动作产生假断缝” | `blind_pack` 已落地 1× 原尺寸 + 容器自适应整数倍最近邻放大双视图、棋盘格/深浅背景切换、非循环动作默认播完即停与单帧步进（`PAPER-06`），正式实验前按 `PAPER-09` 补齐 `run_id` 对账与任务参考展示 |
