## 1. 核心痛点、洞察与故事线

### 1.1 为什么 2D 游戏精灵不是普通短视频

通用图生视频/动画生成容忍轻微的轮廓抖动、像素偏移或道具微变；但 2D 游戏精灵是绑定了**硬性游戏不变量（Hard Game-Readiness Invariants）**的状态机资产——包括锚点（Anchor）、碰撞底座（Collider Footprint）、角色装备持久性以及多状态间的静态轮廓对齐。

现成的商用/黑盒图生动画模型普遍属于**短视界端点条件生成器（Black-Box Short-Horizon Endpoint-Conditioned Generators）**：每次只能生成一小段帧序列，无法微调模型权重。制作长角色动作或交互物多状态链（A→B→C）时只能分段接续。

### 1.2 核心洞察（Key Insight）

黑盒链式生成在 2D 游戏精灵上最致命的失效模式，不是肉眼一眼就能看穿的彻底画崩，而是**“视觉上看似合理、但破坏了游戏不变量的隐性漂移（Plausible-but-Invalid Drift）”**（如底座漂移数像素、铰接杆件伸缩、手持装备悄悄消失、段间姿态错位）。

开发实践与先导实测暴露出两重根本矛盾：
1. **自动复核存在系统性盲区**：单纯依赖视觉语言模型（VLM）复核时，综合裁决容易抹平独立检查发现的局部矛盾，且 VLM 对像素级固定底座偏移、刚体杆长伸缩存在系统性漏检（假阳性）。
2. **全人工盯盘与无约束重绘代价过高**：若每段全靠人工复查或缺陷即整段重画，人力和调用成本迅速失控；而直接对单帧做无约束生成式局部修改，又会引入跨帧闪烁与域外像素污染。

### 1.3 全文故事线（痛点 → 洞察 → 方法 → 验证）

- **痛点**：黑盒短视界生成器在分段生成角色长动作与交互物状态链时，隐性不变量漂移随段数不可逆地累积，直接破坏游戏碰撞与状态机可用性。
- **洞察**：单靠 VLM 无法可靠拦截游戏几何/像素不变量违背，必须将“分歧与确定性测量冲突”作为定向触发人工裁决的信号，并在拦截后采用成本递增的零渗漏局部修复。
- **方法**：提出 **Verify Before You Chain (VBYC)** 混合主动框架，围绕三大机制构建：① 来源可追溯的状态转移合同；② 非对称、保分歧的选择性检查点门控（独立 VLM 评审 + 确定性探针 + No-Silent-Override 升级规则 + 哈希锁定真实像素检查点）；③ 分级保不变性修复协议。
- **验证**：先以历史真实角色作业的零成本回顾研究建立失败分类学与动机；再在冻结方案与种子的受控实验中，量化各接续策略的**游戏可用率–API 成本–人工耗时帕累托权衡**，离线拆解 VLM 盲区与保分歧/确定性探针的纠错收益，检验分级修复的成本优势，并以交互物多状态链作为刚体不变量压力测试划定当前黑盒生成器的物理边界。

## 2. 核心学术贡献（Contributions）

1. **统一问题建模与游戏精灵链式生成的实证失败分类学**：将角色长动作分段与交互物多状态链（A→B→C）抽象为黑盒短视界端点条件生成器下的带不变量状态转移问题（与具体商用 API 解耦，PixelLab 仅作测试平台实例化）；结合历史生产作业与受控实验，提出 2D 游戏精灵链式生成的实证失败分类学，区分柔性角色漂移与刚体交互物不变量违背，并刻画 VLM 评审在游戏几何不变量上的系统性盲区。
2. **非对称、保分歧的选择性检查点门控协议**：提出来源可追溯的质量合同（显式分离*允许变化的动态目标*与*禁止变化的硬性不变量*），结合多视角独立 VLM 专家与确定性像素/几何探针。核心规则为**不沉默覆盖（No-Silent-Override）**——独立专家发现的具体矛盾或确定性探针冲突不得被下游汇总复核抹平，而是作为高价值信号定向升级给人工裁决；确认通过的真实帧以哈希冻结为不可变检查点，杜绝想象端点传播。
3. **分级保不变性修复协议与成本–质量帕累托实证分析**：针对像素精灵修复易引发跨帧闪烁和域外退化的问题，提出四级成本/风险递增修复协议（确定性像素操作 → 区域锁定受限生成 → 段内窗口重绘 → 整段重绘），强制执行**程序校验的域外零像素变动**与**目标达成/内容保持解耦评审**；在冻结协议下量化接续策略与修复层级的可用率、API 费用与人工检查时间权衡。

## 3. 问题抽象与统一表示

### 3.1 黑盒短视界端点条件生成器抽象

不以特定 API 的配额或参数定义问题，而是将其形式化为通用黑盒生成器接口 $G(I_{\text{start}}, p, I_{\text{end}}^{\text{opt}}, L, s) \to (F_1, \dots, F_L)$：
- 仅接受首帧真实图像 $I_{\text{start}}$、文本动作/过渡描述 $p$、可选末帧条件 $I_{\text{end}}^{\text{opt}}$、受限段长 $L \le L_{\max}$ 与随机种子 $s$；
- 内部权重与中间隐状态不可访问、不可微调；
- 资产需求由目标状态变化集合 $\Delta$ 与硬性游戏不变量集合 $\mathcal{I}$ 组成，需经 $K$ 段链式接续满足整条序列的游戏可用性。

具体测试平台（PixelLab `/v2/animate-with-text-v3`：64×64 或 128×128 像素、单段 4–16 帧、最多 4 段、提示词上限 1,000 字符、单次像素预算 524,288）下沉至实验实现细节章节说明。

### 3.2 角色动作与交互物状态链的统一表示

两类对象用同一套“段、合同（$\Delta, \mathcal{I}$）、检查点”表示，工具只在合同字段与不变量探针上按对象类型实例化：

| 概念 | 角色长动作（主实验领域） | 交互物多状态链（刚体不变量压力测试领域） |
| --- | --- | --- |
| 首帧参考 | 角色原图 | 交互物的 A 状态图（PixelLab 128px 物品图） |
| 一段（Segment） | 长动作中的一个动作阶段 | 一次状态过渡（A→B） |
| 检查点（Checkpoint） | 本段确认过的真实末帧 | 确认过的真实末帧，同时登记为具名 B 状态图 |
| 多段接续 | 最多 4 段，逐段从真实末帧继续 | 状态链 A→B→C，逐个状态从真实状态图继续 |
| 可选末帧条件 | 外部目标姿势图 | 用户已有的 B 状态图（可选） |
| 动态目标 $\Delta$ | 关键姿势、支撑与发力、运动轨迹、节奏 | 目标状态终态外观、运动部件及其轨迹、终点停留 |
| 硬性不变量 $\mathcal{I}$ | 角色身份、装备归属、画布尺度与接缝连贯 | 固定部件/底座像素位置、锚点、轮廓外沿、刚体铰接半径 |
| 产物去向 | Godot SpriteFrames | 交互物编辑器切换槽、序列条目与过渡动画 |

B 状态图来自真实生成并通过验证的末帧，不用局部编辑去“凭空造图”。循环待机动画（如旗帜、火把）要求首尾拓扑闭环，属于另一类约束，不纳入本篇。

### 3.3 交互物的战略定位：压力测试与边界探测

交互物在论文中不硬包装为“与角色成功率相当的第二成功领域”，而是明确定位为**刚体与锚点不变量压力测试领域（Stress-Test Domain / Boundary Probe）**：
- 若补足额度后完整流程提升了状态链可用率，则作为跨资产类型的泛化证据；
- 若黑盒生成器在带遮挡刚体平移、刚体铰接等运动上持续暴露底层缺陷，则作为 **RQ1（失败分类学对比）** 与 **RQ3（确定性探针弥补 VLM 盲区）** 的强实证证据，诚实划定黑盒模型边界并证明框架成功阻止劣质状态图污染游戏碰撞盒与后续状态。

## 4. 方法：VBYC 三大核心机制

放弃按操作顺序平铺的“步骤 1/2/3/4”写法，方法章节围绕三个紧扣学术问题的机制组织。

### 4.1 来源可追溯的状态转移合同（Provenance-Tracked State-Transition Contracts）

- **目标**：把模糊的自然语言动作或状态链请求，编译为可核验的段级目标 $\Delta_k$、硬性不变量 $\mathcal{I}_k$ 与可执行绘图说明。
- **机制**：采用多专家规划（外观专家与运动专家先各自独立观察参考图，策略专家综合拆段，协调者输出最终方案）。规划前核对参考图前提（视角、朝向、初态及部件覆盖，记录描述与参考图差异），并按余额预检总帧数上限。
- **来源标注（Provenance）**：合同中每条约束标明来源（用户原话 / 参考图观察 / 专家推断），避免后续复核把专家脑补的细节误当成硬性用户需求。
- **主要代码**：`Tools/SpritePipeline/sprite_pipeline/collaboration/` 下的 `planning.py`、`planning_budget.py`、`planning_draft.py`、`executable_brief.py`、`contracts.py`、`quality.py`、`generation_conditions.py`。

### 4.2 非对称验证与保分歧检查点门控（Asymmetric Verification & Disagreement-Preserving Gating）

- **目标**：以最小人类注意力代价截断假阳性错误传播，避免纯 VLM 汇总复核漏检与全人工逐帧盯盘两个极端。
- **三层异构观察器**：
  1. **基础复核**：两次基础视觉检查，筛查显性缺陷。
  2. **独立视角 VLM 专家**：外观专家与运动专家各自独立审片，将结论细分为四类——`满足 / 明确缺陷 / 审美偏好 / 证据不足`；分歧时追加至多一次争议复核。交互物分项对状态终态、过渡与固定内容分别给结论。
  3. **确定性不变量探针（Deterministic Probes）**：针对 VLM 存在系统性盲区的几何/像素约束（如交互物固定部件像素变化、铰接转动半径波动）进行确定性测量（`prop_measurements.py`）。
- **核心门控规则——不沉默覆盖（No-Silent-Override）**：
  - 独立专家指出的具体矛盾，不得被后续争议复核一票清除；
  - 模型判“通过”但与确定性探针测量结果冲突时（`guard_measurements`），强制降级为待定并定向升级给人工实际画面裁决。
- **不可变真实像素检查点**：只有通过验证（或经人工显式确认）的段才冻结为不可变快照并记录 PNG SHA-256 哈希；下一段启动时重验哈希与目标集摘要，不一致立即中止。不用推测或想象出的端点替代真实末帧，不倒放、不补帧；若目标姿势提前到达，允许人工选定真实中间帧截断作为检查点。
- **主要代码**：`checkpoints.py`、`production_review.py`、`independent_review.py`、`dispute_review.py`、`visibility_review.py`、`visual_review.py`、`prop_measurements.py`、`execution.py`、`targets.py`。

### 4.3 分级保不变性修复协议（Tiered Invariance-Preserving Repair）

当某段未通过检查点验证时，在段内先按成本与风险递增顺序修正，避免缺陷传入后续段或直接触发高成本整段重画。工具多本身不是贡献，学术价值在于所有工具服从统一的**不变性保护契约**。

**四条共同契约**：
1. **明确授权范围**：声明受影响的帧索引与像素级选区/蒙版。
2. **程序强制域外零渗漏（Zero-Leakage Invariance）**：授权范围外逐像素保持不变，由本地程序合成与哈希核验保证，不依赖生成模型自觉。
3. **目标与保持解耦评审（Decoupled Verdict）**：独立复核分开判定“修改目标是否达成”与“非目标内容是否保持”；目标改善不得抵消新出现的退化。
4. **不可变候选与版本核对**：修正产生新候选版本，原帧保留，采用前重验版本与完整播放效果。

**四级修复阶梯（先廉价确定性，后受限生成，最后重绘）**：

| 级别 | 修正手段 | 是否调用模型 | 成本与风险特征 | 现有实现 |
| --- | --- | --- | --- | --- |
| L1 确定性像素工具 | 精确替色、色表映射（≤64 对）、擦除碎片、区域平移、像素补丁、区域恢复 | 否 | 0 API 费用、零随机退化、可跨段一致施加 | `lib/workbench/image-edits.mjs` 等与 `local_frame_edits.py`，单帧与跨段确定性备选，播放后采用 |
| L2 区域锁定受限生成 | 生成前大尺寸参考图：GPT Image 蒙版编辑+部件计划；动画帧：PixelLab 外观编辑 + 本地逐像素区域外保护 | 是 | 中等成本，局部改动受像素边界锁死 | 静态图 `image-edit-critic.mjs`；动画帧区域模式已接入 |
| L3 段内窗口重绘 | 过渡重画，锁定窗口真实首尾帧做条件引导 | 是 | 仅重画局部问题窗口，保留段首段尾不破接缝 | 序列帧工具 `repairs.py`（每段至多两次修复） |
| L4 整段重画 | 对本段全部可编辑帧生成新候选，保留锁定边界与原帧 | 是 | 成本最高，作为兜底；实验中可设 `redraw_only` 消融对照 | 序列帧工具与实验副本策略 |

**帧适用边界（防跨帧闪烁规则）**：
- 允许用于生成前的参考图/状态图、接续前的段末帧/状态检查点帧，以及可整段统一施加的确定性操作（如全序列色表映射）。
- **禁止**对序列中间单帧做生成式编辑（极易引发跨帧闪烁），中间帧运动缺陷统一走 L3 段内窗口重绘或 L4 整段重画。

## 5. 与已有工作的区别

| 工作 | 做法 | 与本文的区别 |
| --- | --- | --- |
| Sprite Sheet Diffusion（2024/2025） | 扩散模型按显式姿势序列生成精灵图 | 需要事先提供完整姿势序列并训练/控制白盒模型；本文仅需文本+首帧，面向不可微调的黑盒生成器 |
| Keyframe-Anchored Identity Preservation（2026） | 先生成一串关键帧，再在关键帧之间填充 | 关键帧是未经动态验证的推测端点；本文只从真实生成并通过不变量验证的帧接续 |
| EM-Vid（2026） | 指出关键帧链会漂移，通过实体记忆机制缓解 | 佐证漂移是公认难题；记忆机制需改写模型架构，本文在黑盒外部以验证与受限修复截断漂移 |
| Agent Sprite Forge（开源 Agent 技能） | 单动作图生视频并拼联系表供 Agent 浏览 | 最接近的实际工程竞品；无分段接续、无硬不变量探针、不保留评审分歧、无分级零渗漏修复、不覆盖交互物状态链 |
| Is Your Video Language Model a Reliable Judge?（ICLR 2025） | 证明简单聚合多位 VLM 评审不能提升可靠性 | 直接支撑本文放弃简单投票、采用“保留分歧 + 确定性探针升级”的理论动机 |
| Each Judge Its Own Yardstick（2026） | 将多评审分歧视为有效信号而非噪声 | 方向一致，本文进一步落地为混合主动游戏管线的选择性人工门控协议 |
| GIE-Bench（2025） | 图像编辑评测将“目标正确”与“内容保持”解耦 | 本文分级修复协议的验收口径与之对齐，并在像素精灵中引入程序强制域外零渗漏 |

## 6. 研究问题（Research Questions）

重塑为四个紧扣机理与量化权衡的问题，避免“人工比不看更好”的同义反复：

- **RQ1（失败分类学与跨段传播机理）**：黑盒短视界生成器在分段生成 2D 游戏精灵时会出现哪些游戏不可用失败？隐性不变量漂移如何随段数累积？柔性角色与刚体交互物的失败谱系有何差异？
- **RQ2（接续策略与人类注意力帕累托权衡）**：在相同冻结方案、种子与帧预算下，不同接续策略在**游戏可用率（Game-Readiness）**与**API 费用 / 人工检查耗时**上的帕累托前沿如何？选择性门控把人类注意力集中在了哪些风险段？
- **RQ3（VLM 盲区与非对称门控收益）**：纯 VLM（含多专家汇总）在哪些游戏不变量上会系统性漏检？“保留矛盾规则”与“确定性探针”分别拦下了多少隐性假阳性，付出了多少额外人工裁决率？
- **RQ4（分级修复的性价比与工具选用）**：相比不通过即整段重画（`redraw_only`），四级保不变性修复对修复成功率、API 调用次数和总成本有何影响？实际返工中确定性与受限局部工具吃掉了多大比例的修复需求？

## 7. 实验设计（草案，规模与费用待定）

实验支撑命令、冻结协议 v3、成本与人工秒数口径及盲评打包机制见《[序列帧实验支撑](motion-experiments.md)》。

### 7.1 动机回顾性研究（前置至论文 Section 3.2；对应 RQ1、部分 RQ3；零新增生成费用）

- **数据**：Windows 机器上积累的真实角色历史作业（含分段原始帧、复核历史、人工裁决与修复记录）。需先按 `PAPER-01` 执行 `EXP inventory` 清点可用开放动作作业与旧版整段作业数量。
- **方法**：人工标注每段失败类型（身份改变、装备消失/增生、朝向错乱、接缝断裂、锚点偏移、目标姿势提前到达），统计各类型在不同段位的分布，并交叉对比模型复核结论与人工裁决。
- **边界声明**：历史作业存在人工筛选与过程偏差，明确仅作为**描述性动机与失败分类学来源**，不用于组间因果比较。

### 7.2 角色主实验：接续策略与帕累托对比（对应 RQ2、RQ4）

在同一批角色动作、相同冻结方案（提示词、段数、帧数、FPS、种子、参考图与预算上限）下比较 5 组：

| 组别 | 代码标识 | 做法与公平性说明 |
| --- | --- | --- |
| 一次生成 | `single` | 单次调用画完（超 16 帧按协议记为预检拦截，纳入分母） |
| 盲目接续 | `blind` | 自动使用上一段真实末帧接续，无复核、无修复 |
| 未验证推测端点接续 | `keyframe_first`（论文拟重定性，见 `PAPER-02`） | 先由同生成器短程 4 帧提案冻结各段末帧，再首末图填充（保持同模型像素网格与画风分布，避免跨模型域偏移；或按 `PAPER-02` 裁决补充静态关键帧小样本对照） |
| 仅模型验证后接续 | `model_only` | 在真实流程内仅依据固定规则由模型复核自动裁决并执行至多一次段内窗口重绘，无人介入 |
| 非对称门控 + 人工确认（完整方法） | `human_verified` | 模型多专家复核 + 确定性探针 + 保分歧定向升级人工裁决 + 四级修复工具集 |

- **核心指标**：盲评游戏可用率（关键姿势达成、装备/身份一致、接缝连贯；分母包含预检拦截、技术中断与审查叫停的不可用运行）、API 调用次数与原生费用、实际人工检查耗时（`human_seconds`），绘制 **游戏可用率 vs 人工耗时 / API 费用帕累托前沿**。

### 7.3 交互物压力测试：刚体与锚点不变量边界探测（对应 RQ1、RQ2、RQ3；小规模）

- **对象**：若干多状态交互物（如宝箱、拉杆、闸门、指示灯等，清单待定），覆盖发光/色变、铰接转动、带遮挡刚体平移等不同运动类型，构建 2–3 状态链（A→B→C）。
- **组别**：取 `blind`、`model_only`、`human_verified` 子集。
- **核心指标**：终态达成、固定部件/底座像素偏移、铰接半径稳定性、状态图直接写回交互物编辑器的可用率、确定性探针拦截 VLM 误判的命中率与人工耗时。

### 7.4 消融实验（对应方法三大机制）

| 消融项 | 对照做法 | 是否需新增付费生成 | 回答的问题 |
| --- | --- | --- | --- |
| 去独立专家 | 离线重算 `review_ablation.baseline_only` | 否 | 多视角独立 VLM 相对基础复核的增益 |
| 去保留矛盾规则 | 离线重算 `review_ablation.final_review_wins` | 否 | No-Silent-Override 拦下多少误通过、增加多少人工裁决 |
| 去确定性探针 | 离线解耦 `without_probes` 与 `probe_overrides`（待按 `PAPER-03` 补齐导出） | 否 | 确定性像素/几何探针弥补了多少 VLM 系统性盲区 |
| 仅允许整段重画 | `EXP clone ... --repair-policy redraw_only` 对比完整四级修复 | 是 | 分级零渗漏修复省下多少调用次数、费用与返工退化 |
| 可选结构观察器 | 规划时加 / 不加 SAM 2.1 视觉结构辅助 | 是 | 可选结构观察器对规划与追踪的边际影响 |

## 8. 论文 8 页闭环大纲（IEEE CoG 双栏标准）

每节写明建议篇幅、核心论证目标与必须落地的证据/图表：

1. **Introduction（~1.0 页）**
   - *核心论证目标*：建立“2D 游戏精灵 ≠ 普通视频”的认知差；提出隐性不变量漂移痛点、VLM 盲区洞察与 3 条学术贡献。
   - *关键图表*：首页 Teaser 图——同一资产在 `blind` 漂移崩坏、`model_only` 漏检放行、本方法经保分歧/确定性探针精准拦截并局部零渗漏修复后的三方对比。
2. **Related Work（~0.75 页）**
   - *核心论证目标*：精准卡位 CoG 社区——① 精灵/游戏资产生成（对比姿态条件白盒法）；② 长视频接续与漂移缓解（对比不可用于闭源黑盒的架构改写）；③ VLM-as-a-Judge 不可靠性与混合主动 PCG（为选择性人工门控奠基）。
3. **Problem Formulation & Motivating Empirical Study（~1.25 页）**
   - *核心论证目标*：完成 API 脱敏建模，并用零成本历史数据立住全文动机。
   - **3.1 Abstracting Black-Box Chained Sprite Generation**：形式化短视界端点条件黑盒生成器与角色/交互物统一状态转移表示（$\Delta, \mathcal{I}$）。
   - **3.2 Motivating Retrospective Study（RQ1）**：分析 Windows 真实历史角色作业，给出 2D 精灵链式生成的 **Failure Taxonomy** 与随段数变化的分布特征，展示纯 VLM 漏检实例（依赖 `PAPER-01`）。
4. **The Verify-Before-You-Chain Framework（~2.0 页）**
   - *核心论证目标*：清晰呈现三大可迁移机制，杜绝操作手册式流水账。
   - **4.1 Provenance-Tracked State-Transition Contracts**：多专家规划与约束来源标注。
   - **4.2 Asymmetric Verification & Disagreement-Preserving Checkpoints**：三层观察器（基础检查 + 独立视角 VLM + 确定性探针）、No-Silent-Override 升级规则、哈希锁定不可变真实像素检查点。
   - **4.3 Tiered Invariance-Preserving Repair**：四级成本递增修复阶梯、程序强制域外零渗漏、目标/保持解耦评审与中间单帧禁生成规则。
   - *关键图表*：重构后的系统方法架构图（取代 `outputs/paper-figures/` 中第 1 版旧图）。
5. **Experimental Setup（~0.75 页）**
   - *核心论证目标*：确立公平、可复现的受控实验协议。说明测试平台实例化（PixelLab 参数与视觉模型）、冻结协议 v3、5 组角色对照与基线定性（`PAPER-02`）、交互物压力测试设置、离线与在线消融、匿名盲评包与全分母可用率口径、成本与 `human_seconds` 计量方式。
6. **Results & Analysis（~1.5 页）**
   - *核心论证目标*：用定量拆解与权衡曲线回应 RQ2–RQ4。
   - **6.1 Chaining Strategies & Pareto Trade-off（RQ2）**：角色主实验结果与 **“游戏可用率 vs 人工耗时 / API 费用”帕累托图**。
   - **6.2 Verification Reliability & VLM Blind Spots（RQ3）**：VLM 与人类真值一致性，以及 `baseline_only` / `final_review_wins` / `without_probes` 三重离线消融数据 + “VLM 判通过但探针/分歧拦下”配对视觉案例图（依赖 `PAPER-03`）。
   - **6.3 Tiered Repair Efficacy（RQ4）**：`redraw_only` vs 完整修正工具集的修复成功率、费用节省与 L1–L4 工具选用分布图。
   - **6.4 Stress-Test Domain: Multi-State Interactables（RQ1/RQ2 延伸）**：刚体与锚点不变量实测结果，展示状态链漂移拦截与黑盒生成器在带遮挡刚体平移上的能力边界。
7. **Discussion, Limitations & Threats to Validity（~0.5 页）**
   - *核心论证目标*：主动化解审稿人挑刺——单一闭源生成器依赖及向开源首尾帧视频模型迁移的接口要求、刚体遮挡物理边界、循环待机动画的拓扑差异、回顾性样本选择偏差、像素小图盲评双视图控制。
8. **Conclusion（~0.25 页）**
   - *核心论证目标*：收束到核心观点——在不可微调的黑盒生成时代，游戏级可用性来自可验证的不变量契约、保分歧的选择性人机门控与零渗漏分级修复。

## 9. 现状、已有证据与现实缺口

截至 2026-11-20（`paper-vbyc` 基准 `dce5a94041c2`），工程底座与实验支撑已具备并在隔离环境与跨平台门禁下验收通过，详见《[论文分支执行计划](论文分支执行计划.md)》与[工程问题清单](问题清单/README.md)。

**已有真实生成与先导观察证据**：
- **规划实测（2026-10-28）**：角色“向前挥砍”走完四位专家规划与本地校验，4 次 Kimi 调用，定稿 746 字符。
- **保留矛盾规则单实例**：可见性校准旧素材中，一次失败修改被两位独立专家指出外形缺陷，但综合复核误判为通过；保留矛盾规则将其截留给人工裁决。
- **结构追踪单实例**：16 帧角色单样本中，首帧人工纠正改善了后续追踪。
- **静态图局部编辑对照**：十项开发对照中，模型评审认为普通流程 2 张、带部件计划与局部参考流程 7 张可用；全部 20 张域外像素零变化（尚无人工盲评）。
- **交互物首轮直调小测**：4 种物品 × 2 种子直接调用生成器，8 条原始序列仅指示灯 1 条同时满足终态、过渡与固定内容要求；带遮挡刚体平移（栅门）出现倾斜与穿出石梁。
- **交互物第二轮完整流程小测**：预定 6 样本仅实际绘制 1 条拉杆动画；**专家 VLM 复核对过渡中杆身伸缩一致误判为通过，最终由确定性像素测量（`guard_measurements`）拦下拒绝**；其余因额度耗尽或规划阻断未生成，采用 0 条。

**尚未验证与实验前缺口**：
- 尚无真实付费生成的跨段状态链成功样本与正式对照组实验数据（PixelLab 余额归零）。
- 确定性探针阈值仅在两条归档序列上标定，跨物品误报率未知；形变类运动尚无通用确定性探针。
- 正式付费实验前必须完成三项现实修补（已登记为 `PAPER-01`、`PAPER-02`、`PAPER-03`，见[问题记录](问题清单/2026-11-20-论文大纲重构与实验修补/README.md)）：
  1. `PAPER-01`：盘点并导出 Windows 历史真实角色作业，落地 Section 3.2 零成本动机研究。
  2. `PAPER-02`：拍板 `keyframe_first` 基线的重定性命名或静态关键帧小样本补充，消除 Strawman Baseline 风险。
  3. `PAPER-03`：在 `counterfactual_verdicts` 与回顾导出中解耦确定性探针拦截与专家分歧拦截，并形成核心对比案例集。

## 10. 风险与 CoG 审稿攻防预案

| 审稿人高频质疑 | 预先防守与应对 |
| --- | --- |
| “先验证再接续只是常识包装 / 人工更好是同义反复” | 不把“人工 > 盲接”当结论；核心展示**可用率–人工秒数帕累托前沿**、VLM 盲区实证、保分歧门控省下多少人工复查以及零渗漏分级修复省下多少 API 调用 |
| “强绑定 PixelLab 单一闭源商用 API，缺乏泛化性” | Section 3 形式化为通用短视界端点条件黑盒生成器；PixelLab 接口参数全部下沉至实验实现细节；讨论中给出向开源首尾帧视频模型迁移的接口映射，审稿要求时可补第二生成器 |
| “`keyframe_first` 用 4 帧动画末帧做关键帧不公平” | 按 `PAPER-02` 明确重定性为“未验证推测端点接续”并说明同像素网格公平性理由，或补测静态关键帧对照 |
| “交互物通过率太低，说明统一方法失效” | 交互物定位为**刚体不变量压力测试与边界探测**；无论通过率高低，均服务于失败分类学（RQ1）与确定性探针纠错（RQ3），诚实界定生成器在带遮挡刚体平移上的底层局限 |
| “三块内容拼盘，8 页塞不下” | 角色为主实验，交互物为小规模压力测试（0.4 页），修复工具集收敛为分级保不变性协议并只占一组消融 |
| “历史回顾数据有选择偏差” | 前置至 Section 3.2 仅作描述性动机与失败分类学，明确不作因果推断 |
| “像素风小尺寸盲评难以看清细节” | 匿名盲评包同时提供原尺寸与整数倍放大视图，并以全运行集（含失败与拦截）为可用率分母 |
