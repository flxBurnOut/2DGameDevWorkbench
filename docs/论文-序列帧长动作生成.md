# 论文：先验证，再接续

> 状态：论文主文档（2026-11-10 按新方向重写），以本文最新内容为准。目标会议 IEEE CoG 2027，8 页，截稿日期待查。
> 方向的来龙去脉、已定决策和进度见《[论文方向与方法](论文方向与方法.md)》。
> 样本数量、费用上限和统计口径尚未讨论，文中一律标"待定"。

暂定标题：*Verify Before You Chain: Checkpointed Sprite Animation for Characters and Interactables with Black-Box Generators*

## 1. 一句话

**主题**：用现成的黑盒动画模型，在同一个工具里生成 2D 游戏的角色动作和交互物状态动画。

**主张**：先验证，再接续。生成只从已验证的真实像素继续，未要求改变的内容必须保住。一段没通过检查，就在这一段里用范围受限的工具修正，不把错误传给后面的段或后面的状态。

## 2. 要解决的问题

- 现成的图生动画模型一次只能画一小段。本项目使用 PixelLab `/v2/animate-with-text-v3`：输入首帧图片、动作文字、可选末帧图片；每段 4–16 帧，最多 4 段、64 帧；单次请求像素预算 524,288（128×128 时约 32 帧）。
- 角色的长动作只能分段，每段从上一段的结尾继续。前面出的错（装备消失、角色变样、姿势不对、接缝不连贯）会被带进后面所有段。
- 交互物有同样的结构。一个宝箱有关闭、打开、取空三个状态，每次状态过渡是一段动画，下一段从上一个状态的画面开始。前一个状态画错（箱体变形、锁扣位置漂移、底座移位），后面的状态全部跟着错，而且游戏里状态图和碰撞、交互范围绑定，漂移会直接变成可见的跳变。
- 生成器是闭源黑盒，不能修改模型，只能在**怎么编排、怎么验证、怎么修正**上下功夫。论文的贡献全部在这一层。

## 3. 角色与交互物的统一

两类对象用同一套"段、检查点、合同"表示，工具只在合同内容上区分它们。

| 概念 | 角色动作 | 交互物状态动画 |
| --- | --- | --- |
| 首帧参考 | 角色原图 | 交互物的 A 状态图 |
| 一段 | 长动作中的一个阶段 | 一次状态过渡（A→B） |
| 检查点 | 本段确认过的真实末帧 | 确认过的真实末帧，同时成为 B 状态图 |
| 多段接续 | 最多 4 段，逐段从真实末帧继续 | 状态链 A→B→C，逐个状态从真实状态图继续 |
| 可选末帧条件 | 外部目标姿势图 | 用户已有的 B 状态图 |
| 合同的重点 | 关键姿势、支撑与发力、轨迹、物品归属、节奏 | 状态的最终样子、不动的部分（底座、锚点、轮廓外沿）、运动部件及其轨迹、画布内位置 |
| 产物去向 | Godot SpriteFrames | 交互物编辑器的切换状态槽、序列条目和过渡动画 |

B 状态图由生成得到并经过验证，不用局部编辑去"造"。循环待机动画（旗帜、火把）要求首尾相同，是另一类约束，不放进这篇论文。

## 4. 方法：四个步骤

| 步骤 | 做什么 | 当前工具里的做法 | 主要代码（`Tools/SpritePipeline/sprite_pipeline/collaboration/`） |
| --- | --- | --- | --- |
| 1. 拆段并写清目标 | 把动作或状态链拆成最多 4 段，写清每段结束时应是什么样子 | **多专家规划**：外观、动作专家先独立观察参考图，策略专家综合，协调者写出最终方案。输出质量合同，每条要求标注来源（用户原话 / 参考图观察 / 专家建议）。绘图说明每段不超过 1000 字符 | `planning.py`、`planning_budget.py`、`planning_draft.py`、`executable_brief.py`、`contracts.py`、`quality.py`、`generation_conditions.py` |
| 2. 用真实帧检查这一段 | 检查这段的实际画面是否达到本段目标、是否保住未要求改变的内容 | **多专家复核**：两次基础检查，再由外观、运动两位专家各自独立检查，有分歧时追加至多一次复核。结论分为"满足 / 明确缺陷 / 审美偏好 / 证据不足"。独立专家指出的具体矛盾不能被后续复核一票清除，保留给人工裁决 | `checkpoints.py`、`production_review.py`、`independent_review.py`、`dispute_review.py`、`visibility_review.py`、`visual_review.py` |
| 3. 通过后用真实末帧接下一段 | 下一段的首帧必须是这一段确认过的真实最后一帧 | 人工确认后，本段存为不可变快照并记录哈希；下一段读取时重新校验哈希，不一致就停止。不用想象出的端点替代，不倒放、不补帧。目标提前到达时，可以人工选一个真实帧作为本段终点 | `checkpoints.py`、`execution.py`、`targets.py` |
| 4. 没通过就修，不传下去 | 在段内修正；修不好再重画本段 | **段内修复**：只修本段内部的一个窗口，段首段尾不变。两种方式：外观编辑（128 像素一次 2 帧；64 像素 2–14 个偶数帧）、过渡重画（4–16 个偶数帧，用窗口真实首尾引导）。每段最多两次修复。新方向在这一步加入修正工具集，见第 5 节 | `repairs.py`、`adjustments.py`、`adjustment_regions.py`、`adjustment_review.py`、`adjustment_comparison.py` |

可选辅助，不在主流程上：角色结构解析（本地 SAM 2.1 加一次语义调用）、时序追踪、近静止提示。它们是可替换的观察器，不算贡献。

## 5. 修正工具集

第 4 步里，Agent 和用户可以从一组修正工具中选择。工具多本身不是贡献；贡献在于所有工具遵守同一套约定，因此可以放心地先用便宜的工具。

**共同约定**

1. 每次修正有明确的授权范围：哪些帧、帧内哪一块区域。
2. 范围外的像素逐像素不变，由程序核验，不靠模型自觉。
3. 修完由独立复核分开判断两件事：修改目标是否达成、其他内容是否保持。目标改善不能抵消新出现的退化。
4. 修正结果是新候选，原帧保留；采用前重新核对版本。

**工具分级**（先试上面的，不行再往下）

| 级别 | 工具 | 是否调用模型 | 现有实现 |
| --- | --- | --- | --- |
| 确定性 | 精确替色、色表映射（至多 64 对）、擦除碎片、区域平移、像素补丁、区域恢复 | 否 | 场景与交互物的图片局部调整已有（`lib/workbench/image-edits.mjs` 等），目前只作用于静态图 |
| 受限生成 | 带蒙版的局部生成编辑，配部件与属性计划、干净局部参考 | 是 | 同上，已接网页与 MCP；候选可请求独立复核（`lib/workbench/image-edit-critic.mjs`） |
| 段内重画 | 外观编辑、过渡重画 | 是 | 序列帧工具已有，区域模式下区域外逐像素保护 |
| 整段重画 | 丢弃本段候选，从上一个检查点重新生成 | 是 | 序列帧工具已有 |

**用在哪些帧上**

- 生成之前的参考图和状态图。
- 接续之前的段末帧或状态帧，修完再确认为检查点。
- 能对整段统一施加的确定性编辑，例如全序列色表映射。
- 不对序列中间的单帧做生成式编辑，单帧改动容易造成闪烁；中间帧的问题走段内重画。

## 7. 和已有工作的区别

| 工作 | 做法 | 区别 |
| --- | --- | --- |
| Sprite Sheet Diffusion（2024/2025） | 扩散模型按姿势序列生成精灵图 | 需要事先给出姿势序列；本文只需动作描述，且使用黑盒生成器 |
| Keyframe-Anchored Identity Preservation（2026） | 先生成一串关键帧，再在关键帧之间填充 | 关键帧是想象出来的；本文只从真实生成并通过检查的帧接续 |
| EM-Vid（2026） | 指出关键帧链会漂移，用实体记忆解决 | 说明漂移是公认问题；本文用验证而非记忆 |
| Agent Sprite Forge（开源 Agent 技能） | 每个动作一次图生视频，生成联系表供 Agent 查看 | 最接近的实际竞品；无分段、无检查点、不处理评审分歧、不覆盖交互物状态 |
| Is Your Video Language Model a Reliable Judge?（ICLR 2025） | 简单聚合多位模型评审不提升可靠性 | 支持"保留矛盾而不是投票" |
| Each Judge Its Own Yardstick（2026） | 把评审分歧当信号 | 方向一致，可引用 |
| GIE-Bench | 图像编辑评测分开"目标正确"与"内容保持" | 修正工具集的验收口径与之一致 |

尚未找到"黑盒首/末帧模型 + 验证后接续 + 保留评审矛盾"用于精灵动画的工作，也未找到把交互物状态链当作接续问题处理的工作。正式写作前需在 CoG、FDG、AIIDE、SIGGRAPH Asia 及 arXiv 补查，交互物与道具动画生成方向尚未查过。

## 8. 研究问题

- **RQ1 失败刻画**：黑盒模型分段生成时会出现哪些失败？出现在哪一段、是否随段数累积？角色与交互物的失败类型有何不同？
- **RQ2 接续策略**：相同帧数与预算下，"验证后接续"相比其他接续方式，错误是否更少？这个结论在交互物状态链上是否仍然成立？
- **RQ3 复核可靠性**：多专家复核与人工判断的一致程度如何？保留矛盾规则拦下多少误判，代价多少人工裁决？
- **RQ4 修正与成本**：有修正工具集时，相比只能整段重画，修复成功率、调用次数和费用如何变化？Agent 实际选用了哪些工具？验证与修正总共需要多少额外调用和人工时间？

## 9. 实验设计（草案，规模待定）

### 9.1 回顾性分析（对应 RQ1、RQ3；无新增生成费用）

- 数据：Windows 机器上的真实角色作业，含每段的实际帧、复核记录、人工裁决和修复记录。数量待清点。
- 做法：按失败类型（漂移、装备消失或增生、身份改变、朝向错乱、接缝不连贯、目标姿势提前到达）人工标注，统计各类型出现的段位置；把模型复核结论与人工裁决对比。
- 已有作业经过人工筛选，存在选择偏差，结论只作描述，不作因果比较。交互物没有历史作业，其失败类型来自 9.3 的新数据。

### 9.2 接续策略对比：角色（对应 RQ2、RQ4；主实验）

同一批动作、相同段数、帧数、FPS、种子与参考图，比较：

| 组别 | 做法 |
| --- | --- |
| 一次生成 | 在单次请求上限内一次画完 |
| 盲目接续 | 自动用上一段真实末帧接续，不检查 |
| 关键帧先行 | 先生成各段末姿势图，再用首/末帧条件填充 |
| 模型验证后接续 | 只由模型复核决定是否继续，不通过则按规则修复 |
| 人工验证后接续（完整方法） | 模型复核 + 人工确认 + 修复 |

指标：计划的关键姿势是否出现、装备与身份是否一致、接缝是否连贯、盲评可用率；额外调用次数、费用、人工检查时间。

### 9.3 接续策略对比：交互物（对应 RQ1、RQ2；第二领域，小规模）

- 对象：若干多状态交互物（箱、门、拉杆等），每个做两到三个状态的状态链。清单待定。
- 组别取 9.2 的子集：盲目接续、模型验证后接续、人工验证后接续。
- 指标：每个状态是否达到描述、不动的部分是否保持（底座与锚点的像素偏移）、状态间过渡是否连贯、状态图能否直接用于交互物编辑器；调用次数与人工时间。
- 目的：说明方法不限于角色，不追求与角色实验同等的规模。

### 9.4 消融（对应方法组成部分）

- 去掉独立专家，只用基础检查。
- 去掉保留矛盾规则，以最终复核为准。
- 修复环节只允许整段重画，对比可用完整修正工具集。记录工具选用分布。
- 加 / 不加角色结构辅助。

## 10. 现状与缺口

**已有实现**

- 角色的开放动作全流程：多专家规划、分段、真实末帧检查点、多专家复核、段内修复、选帧修改（含区域保护）。
- 静态图的局部调整：确定性工具、带蒙版的生成编辑、部件与属性计划、候选独立复核，已接网页与 MCP。
- 交互物编辑器可从资产库导入动画作为默认动画，切换和序列状态可分别配置图片与动画。

**需要新开发**

1. 序列帧工具接受物品图作为参考。目前只接受角色参考，物品原图不能移送为动画参考。
2. 交互物的合同模板：状态描述、不动部分、运动部件。
3. 状态链的产物写回：验证过的末帧写入切换状态槽或序列条目，过渡动画绑定到对应状态。目前导入只支持默认动画。
4. 修正工具集作用于动画帧：现有局部调整只接受地图源图、交互物静态槽和独立图片，交互物的动画状态槽是只读的。

**现有证据**（均为开发验收，不是准确率或泛化证明）

- 2026-10-28：同一角色"向前挥砍"走完四位专家规划与本地校验，4 次 Kimi 调用，最终说明 746 字符。
- 可见性校准用三份旧素材：一次失败的修改中，两位独立专家指出外形问题，最终复核误判为通过；保留矛盾规则把它留给人工。这是"保留矛盾"有用的单一实例。
- 结构追踪：一个 16 帧单样本，首帧人工纠正改进了后续追踪。
- 静态图局部编辑的十项开发对照：模型评审认为普通流程 2 张、带计划与局部参考的流程 7 张可直接用；全部 20 张的范围外像素零变化。没有人工盲评。详见《[地图模块局部编辑大型计划](地图模块局部编辑大型计划.md)》第十二节。
- PixelLab 动画接口对非角色物件的效果：**没有任何证据**。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 动画接口对交互物效果差 | 开发前先做可行性小测（3–5 个交互物的状态过渡）；不可用时交互物降为讨论或换生成器 |
| "有人工确认当然更好" | 同时比较无检查、仅模型检查、模型加人工三种检查点，说明人工花在哪里、何时可省 |
| 只依赖一个闭源生成器 | 首次投稿只用 PixelLab，写入局限；审稿要求时再接入开源首/末帧视频模型 |
| 三块内容挤不进 8 页 | 角色是主实验，交互物是小规模第二领域，修正工具集只占一组消融 |
| 生成费用 | 先查 PixelLab 单价，按组别估总额，再定规模 |
| 模型复核本身会误判 | 这是 RQ3 的研究对象；人工标注作为真值 |
| 像素风格与小尺寸使评审困难 | 盲评同时提供原尺寸与放大视图 |

## 12. 论文结构草案（8 页）

1. 引言：游戏需要角色动作和交互物状态动画；黑盒模型分段生成会累积错误；本文主张先验证再接续。
2. 相关工作：精灵与像素动画生成、长视频与关键帧接续、模型评审可靠性、受限图像编辑、混合主动内容生成。
3. 问题设定：黑盒首/末帧模型、分段上限、角色动作与交互物状态链的统一表示、失败类型。
4. 方法：四个步骤；合同、检查点、复核与保留矛盾、修正工具集及其约定。
5. 实验：回顾性分析、角色接续策略对比、交互物状态链、消融。
6. 结果与讨论：错误、成本、人工何时必要、工具选用。
7. 局限：闭源生成器、像素尺寸、样本范围、不含循环动画。
8. 结论。
