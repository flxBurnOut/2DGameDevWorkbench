## 1. 扫描发现的关键事实

### 1.1 物品图进不了动画生成器（影响最大）

| 事实 | 位置 |
| --- | --- |
| 序列帧的画布只允许 64×64 或 128×128 的正方形 | `Tools/SpritePipeline/sprite_pipeline/models.py:67` |
| 默认的物品原图由 GPT Image 生成，尺寸 1024×1024 | `lib/workbench/adapters/image-assets.mjs:94` |
| 旧的 PixelLab 物品流程是 128×128，但物品不能移送为动画参考 | `lib/workbench/adapters/reference-art.mjs:16`、`:212` |
| 带蒙版的生成式局部编辑同样走 GPT Image，面向大图 | `lib/workbench/adapters/openai-image-provider.mjs` |

含义：交互物的 A 状态图若来自默认流程，要先缩到 128 像素才能交给 PixelLab；反过来，对 64 或 128 像素的动画帧做生成式局部编辑，要先放大再缩回。两个方向都会损失像素画的网格。这直接影响"交互物可行性小测"怎么做，也影响修正工具集里"受限生成"一级能否用于动画帧。裁决见 6.1。

### 1.2 序列帧工具处处假设对象是角色

| 假设 | 位置 |
| --- | --- |
| 任务以 `character_id` 标识对象 | `collaboration/contracts.py:27` |
| 预设含朝向、持武器的手 | `models.py:45–46`（`CharacterPreset`） |
| 质量维度固定为"完整、装备、节奏" | `contracts.py:74` |
| 运动约束含支撑、发力 | `contracts.py:124–125` |
| 规划与复核提示中的角色措辞 | `workspace.py`、`structures.py`、`api.py`、`generation_conditions.py`、`adjustments.py`、`planning.py` 等 15 个文件，共约 150 处 |

### 1.3 两套"局部修改"各自独立

| 能力 | 序列帧一侧 | 图片局部调整一侧 |
| --- | --- | --- |
| 区域表示 | `FrameEditRegion`（`adjustment_regions.py`） | 矩形、多边形、连通色、Alpha 选区、蒙版游程（`image-edit-contract.mjs`） |
| 确定性工具 | 无 | 替色、色表映射、擦除、填充、平移、像素补丁、区域恢复、清理 Alpha |
| 生成式修改 | PixelLab 外观编辑、过渡重画（`repairs.py`） | GPT Image 蒙版编辑（`ai-edit`、`recompose-ai`） |
| 修改前计划 | 需求理解（`adjustments.py`） | 部件与属性计划（`image-part-planner.mjs`、`features/image-edit/attribute-plan.mjs`） |
| 修改后复核 | 目标达成与其他内容保持分判（`adjustment_review.py`） | 单候选独立复核（`image-edit-critic.mjs`） |
| 视觉模型配置 | `collaboration/model_config.py` | `scene-workflow-models.mjs` |
| 可修改的目标 | 作业候选中的帧窗口 | 地图层、场景实例、场景分层部件、交互物静态槽、独立图片任务（`image-edit-targets.mjs:199–203`） |

图片局部调整目前不能以动画帧为目标；交互物正在使用动画的状态槽对它是只读的。

### 1.4 交互物接收动画的入口只有一个

资产库动画只能导入为物件的**默认动画**（`components/interactable-editor/interactable-editor.tsx:477` 附近）。没有"把某一帧写成切换状态图""把一段动画绑定为 A→B 过渡"的入口。

## 4. 执行顺序

每个阶段一个或几个独立提交，阶段结束时跑该阶段列出的检查，全部通过再进入下一阶段。

### 阶段 0：开分支与基线

1. 从 `new-arch` 的 `8e1edac` 开 `paper-vbyc`，只推送该分支，不开 PR。
2. 在新分支上跑一遍保留模块的测试并记录结果，作为后续对照：`test:open-motion`、`test:interactable`、`test:image-edit`、`test:image-attribute-plan`、`test:image-assets`、`test:editor-documents`、`test:assets`、`test:mcp`、`test:http`、`typecheck`、`lint`、`build`，以及序列帧的 Python 测试。
3. 本云端环境没有 Godot，也没有真实素材和作业数据；这两类验证只能在你的机器上做。

检查：四种对照模式在模拟提供方下各跑通一个作业；成本汇总与预算账本一致；盲评包不泄露组别。

## 5. 风险

| 风险 | 应对 |
| --- | --- |
| 尺寸不匹配使交互物或帧上的生成编辑不可用（1.1） | 阶段 3 之前先做可行性小测；不可用时交互物限定为 128 像素的 PixelLab 物品，帧上的"受限生成"一级只用 PixelLab 的外观编辑 |
| 解耦比预期深，尤其是共享文档系统（C4） | 阶段 1 单独成段，不改行为，有全部现有测试兜底；发现过深时改为保留场景的数据模型、只删界面与协作 |
| 删除后丢失黑客松参赛功能 | `new-arch` 原样保留；新分支的 `README.md` 开头写明这是论文分支，完整工作台见 `new-arch` |
