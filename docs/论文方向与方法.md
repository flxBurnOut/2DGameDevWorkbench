## 1. 当前方向（2026-11-23 v8 精简封版确定）

严格拆分**“8 页顶会论文单一主线”**与**“工作台全栈工程总账”**：工作台现有全部功能（含 `PixelProp`、静态图编辑、`recompose-ai`、交互物 `T5/T8/T9` 派生）在产品代码中完整保留；8 页论文只聚焦 **Verify Before You Chain (VBYC)** 的核心学术闭环——**守卫检查点 + 有界保不变性分级修复**：

1. **守卫检查点（Guarded Checkpoints：选择性弃权守卫 + 统一确定性探针）**：将面向短视界端点条件黑盒生成器 $G(I_{\text{start}}, p, I_{\text{end}}^{\text{opt}}, L, s)$ 的分段验收建模为**风险–覆盖率（Risk–Coverage）选择性预测**问题——在防偏见可编译状态转移合同与上下文隔离多视角 VLM 审计（不全为高置信通过时触发带共享源坐标聚焦图的争议核实，含三方同判 `fail` 时的 `verify_claimed_defect`）之上，叠加双向可见性一致性守卫、多级不沉默覆盖，以及覆盖**角色侧**（地面基线、面积变化、质心跳变、调色板偏离）与**交互物侧**（遮挡扣除固定区变化、平面内铰接半径守恒）的 Fail-Closed 确定性探针，并在冻结语料上对比**等调用次数（5 次）无守卫 VLM 基线**。
2. **有界保不变性分级修复（Bounded Tiered Repair）**：在检查点拦下缺陷后，提供从 L1 零生成费像素/交互物固定区原语（`T1` 回填与 `T3` 不裁切整数对齐）、L2 区域锁定外观编辑（本地二值后合成保证域外零渗漏 + 修改前后解耦复核防范“零渗漏 $\neq$ 接缝连续”）到 L3 局部窗口重绘与 L4 整段重画的四级修复协议，并在统一冻结协议下量化盲评可用率、API 成本与检查点人工升级率（Escalation Rate）权衡。

| 内容 | 在当前工作台与论文中的位置 |
| --- | --- |
| 角色长动作（主实验） + 守卫检查点与 L1–L4 分级修复 | **8 页论文唯一主线与主实验**。先以按版本分层的历史真实作业做客观段级漂移与失败分类分析（Section 3.2），再做冻结语料等成本离线复核评测（RQ2），最后做受控冻结协议下的五组工作流对比与 `redraw_only` 修复消融（RQ3–RQ4） |

## 3. 方向演变

| 版本 | 方向 | 放弃或调整的原因 |
| --- | --- | --- |
| 1 | 可验证的 Agent 场景共创系统（协议 + 系统） | 创新点多为工程保障；“Agent + 引擎测试”在 2026 年已拥挤 |
| 2 | 画面与碰撞一致性：推断 + 引擎验证 + 修复闭环 | 范围过宽，五件事挤在 8 页 |
| 3 | 收窄为“一致性问题的定义、度量与检测” | 只覆盖场景，体现不了整个项目 |
| 4 | 统一框架（合同、观察器、裁决）+ 序列帧与场景两个实例 | 两个实例没有共用的实验，框架容易写成功能罗列 |
| 5 | 序列帧长动作生成：先验证，再接续 | 只覆盖角色，缺少交互物刚体压力测试与局部修复对照 |
| 6 | 第 5 版扩展到交互物状态动画，局部编辑作为修正工具集 | 偏工程流水账，易被质疑为 API 包装/同义反复 |
| 7 | 全量源码审计后升级为双支柱大纲（认识论守护 + 混合管线） | 审计后塞入过多旁支子系统（`PixelProp`、静态 Critic/`recompose-ai`、`T5/T8/T9` 派生）与底层文件名/常量，反而导致 8 页主线发散；且角色主域尚缺探针接线与等成本 VLM 对照 |
| 8（当前封版） | **剥离静态参考图编辑、`PixelProp` 细节与零生成派生，收敛为“守卫检查点（弃权守卫 + 统一确定性探针）+ 有界保不变性分级修复”单一闭环**；零生成费补齐角色侧探针接线、等调用次数（5 次）VLM 投票基线与 Risk–Coverage 评估（产品代码本身保持不变） | — |

### 6.1 场景的画面与碰撞一致性

- **问题**：画面上看起来能站的地方没有碰撞（假地面），或有碰撞但画面看不出能站（幽灵地面）。
- **定义**：感知可站面 H 以玩家标注为真值；物理可站面 Γ 是碰撞体上表面中上方有至少一个玩家身高空间的部分。两者按 x 方向每 4 像素采样，同列高度差不超过 τ（暂定 6 像素）视为对上；按长度加权，可达性只用于加权。
- **画面候选**：优先用分层地图和场景地图分层的结构，SAM 只作备选；物件能否站立的语义标签尚缺。
- **归档原型**（只读，保留在 `new-arch`）：[可站面检测](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/affordance.mjs)、[可达性](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/reachability.mjs)、[报告实现](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/lib/workbench/affordance-report.mjs)及[命令入口](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/scripts/affordance-report.mjs)。归档版本的原型测试通过，只在构造的测试场景上运行过；论文分支不提供此能力。
- **缺口**：未区分地表层与物件层；物件无语义标签；观察器不可插拔；可达性未经引擎验证。
- **相关工作**：[Investigating Human Priors for Playing Video Games](https://arxiv.org/pdf/1802.10217) · [Legible Ledges](https://bvbvf1.bib-bvb.de/vufind/PrimoRecord/cdi_uu_diva_oai_DiVA_org_uu_448883) · [Exploring Level Blending across Platformers via Paths and Affordances](https://arxiv.org/pdf/2009.06356) · [A Framework for Analysis of 2D Platformer Levels](https://eis.ucsc.edu/papers/smith-sandbox-08.pdf) · [Rhythm-based level generation](https://dl.acm.org/doi/10.1145/1536513.1536548) · [From Unstable to Playable (AIIDE-25)](https://arxiv.org/abs/2509.23787) · [Level Repair via MILP](https://ojs.aaai.org/index.php/AIIDE/article/view/7424) · [Image-to-Level](https://ojs.aaai.org/index.php/AIIDE/article/download/7429/7302/10897)

### 6.2 统一框架

第 4 版的三层说法（合同、观察器、裁决与绑定）仍可描述整个项目，适合两个以上模块都有硬实验结果后的系统长文（如 IEEE Transactions on Games）。当前论文已将其中核心规则（硬不变量一票否决、“未知”不算通过也不算失败、三层不沉默覆盖、生成只从已确认真实产物继续、人工采用不放行技术检查失败结果）收敛进 VBYC 的程序化认识论守护机制。

以下能力均已在 `paper-vbyc` 产品代码中完整实现并保留，按 v8 封版决定从本篇 8 页 CoG 论文主线剥离，留作独立静态图像/资产管线论文或系统长文使用：
