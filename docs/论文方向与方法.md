## 3. 方向演变

| 版本 | 方向 | 调整原因 |
| --- | --- | --- |
| 1 | 可验证的 Agent 场景共创系统 | 偏工程保障，“Agent + 引擎测试”方向在 2026 年已拥挤 |
| 2 | 画面与碰撞一致性：推断 + 引擎验证 + 修复闭环 | 范围过宽，五件事挤在 8 页 |
| 3 | 收窄为“一致性问题的定义、度量与检测” | 只覆盖场景，代表不了整个项目 |
| 4 | 统一框架（合同、观察器、裁决）+ 序列帧与场景双实例 | 双实例缺少共用实验，容易写成功能罗列 |
| 5 | 序列帧长动作生成：先验证，再接续 | 只覆盖角色，缺少刚体压力测试与局部修复对照 |
| 6 | 扩展到交互物状态动画 + 局部编辑修正工具集 | 偏工程流水账，易被质疑为 API 包装 |
| 7 | 源码审计后升级为双支柱大纲 | 塞入过多旁支子系统与代码细节导致 8 页发散，且角色侧缺探针接线与等成本对照 |
| 8（现行） | 剥离旁支模块，收敛为“守卫检查点 + 有界分级修复”单主线，补齐角色探针与等成本 Risk–Coverage 评测 | — |

## 6. 留作后续论文的素材

### 6.1 场景画面与碰撞一致性

- **问题**：看起来能站的地方没碰撞（假地面），或有碰撞但画面看不出能站（幽灵地面）。
- **定义**：感知可站面 $H$ 以玩家标注为真值，物理可站面 $\Gamma$ 为碰撞体上方具至少一身高空间的表面；按 x 轴每 4 像素采样、高度差 $\le 6$ 像素视为匹配，按长度与可达性加权。
- **归档原型**（只读，位于 `new-arch`）：[可站面检测](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/affordance.mjs)、[可达性](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/reachability.mjs)、[报告](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/lib/workbench/affordance-report.mjs)及[命令入口](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/scripts/affordance-report.mjs)。目前仅在构造场景验证，缺物件可站语义标签与引擎实测。
- **相关工作**：[Investigating Human Priors](https://arxiv.org/pdf/1802.10217) · [Legible Ledges](https://bvbvf1.bib-bvb.de/vufind/PrimoRecord/cdi_uu_diva_oai_DiVA_org_uu_448883) · [Level Blending via Paths and Affordances](https://arxiv.org/pdf/2009.26356) · [Framework for 2D Platformer Levels](https://eis.ucsc.edu/papers/smith-sandbox-08.pdf) · [Rhythm-based Level Generation](https://dl.acm.org/doi/10.1145/1536513.1536548) · [From Unstable to Playable (AIIDE-25)](https://arxiv.org/abs/2509.23787) · [Level Repair via MILP](https://ojs.aaai.org/index.php/AIIDE/article/view/7424) · [Image-to-Level](https://ojs.aaai.org/index.php/AIIDE/article/download/7429/7302/10897)
