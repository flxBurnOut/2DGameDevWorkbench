## 1. 当前方向（2026-11-10 确定，2026-11-20 学术升维）

以序列帧工具为基础，把角色动作与交互物状态链统一抽象为**黑盒短视界端点条件生成器下的带不变量状态转移问题**，并把图片局部编辑收敛为**分级保不变性修复协议**。

核心不再停留在表层的“先验证，再接续”工作流口号，而是聚焦 2D 游戏精灵特有的**隐性不变量漂移（Plausible-but-Invalid Drift）**与 **VLM 评审系统性盲区**，由三项学术机制构成 **Verify Before You Chain (VBYC)** 框架：
1. **来源可追溯的状态转移合同**（显式区分动态目标 $\Delta$ 与硬性不变量 $\mathcal{I}$）；
2. **非对称、保分歧的选择性检查点门控**（多视角独立 VLM + 确定性像素/几何探针 + 不沉默覆盖升级规则 + 哈希锁定真实像素检查点）；
3. **分级保不变性修复协议**（成本递增四级阶梯 + 程序强制域外零渗漏 + 目标/保持解耦评审）。

| 内容 | 在论文中的位置 |
| --- | --- |
| 角色长动作 | **主实验领域**。先以历史真实作业做零成本动机回顾与失败分类学（Section 3.2），再在冻结协议下对比接续策略的可用率–成本–人工耗时帕累托前沿 |
| 交互物状态动画 | **刚体与锚点不变量压力测试领域（Stress-Test Domain / Boundary Probe）**。A 状态图作首帧生成过渡，验证过的真实末帧成为 B 状态图（A→B→C）；无论最终生成通过率高低，均服务于失败分类学与确定性探针纠错验证 |
| 图片局部编辑 | **分级保不变性修复协议**（确定性 → 区域锁定受限生成 → 段内窗口重绘 → 整段重画），占一组消融实验并分析工具选用分布 |

| 版本 | 方向 | 放弃或调整的原因 |

| 1 | 可验证的 Agent 场景共创系统（协议 + 系统） | 创新点多为工程保障；“Agent + 引擎测试”在 2026 年已拥挤 |

### 6.1 场景的画面与碰撞一致性

- **问题**：画面上看起来能站的地方没有碰撞（假地面），或有碰撞但画面看不出能站（幽灵地面）。
- **定义**：感知可站面 H 以玩家标注为真值；物理可站面 Γ 是碰撞体上表面中上方有至少一个玩家身高空间的部分。两者按 x 方向每 4 像素采样，同列高度差不超过 τ（暂定 6 像素）视为对上；按长度加权，可达性只用于加权。
- **画面候选**：优先用分层地图和场景地图分层的结构，SAM 只作备选；物件能否站立的语义标签尚缺。
- **归档原型**（只读，保留在 `new-arch`）：[可站面检测](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/affordance.mjs)、[可达性](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/reachability.mjs)、[报告实现](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/lib/workbench/affordance-report.mjs)及[命令入口](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/scripts/affordance-report.mjs)。归档版本的原型测试通过，只在构造的测试场景上运行过；论文分支不提供此能力。
- **缺口**：未区分地表层与物件层；物件无语义标签；观察器不可插拔；可达性未经引擎验证。

### 6.2 统一框架

第 4 版的三层说法（合同、观察器、裁决与绑定）仍可描述整个项目，适合两个以上模块都有硬实验结果后的系统长文（如 IEEE Transactions on Games）。当前论文已将其中核心规则（硬不变量一票否决、“未知”不算通过也不算失败、独立专家具体矛盾与确定性探针冲突不被后续复核清除、生成只从已确认真实产物继续、人工采用不放行技术检查失败结果）收敛进 VBYC 的非对称门控机制。
