> 状态：讨论记录，以本文最新内容为准（最后更新 2026-11-08）。目标会议 IEEE CoG。
> 本文取代早先的《论文方法-画面与碰撞一致性》草稿；该草稿中仍有效的内容已并入第 6 节。

## 0. 最新方向（2026-11-08）

序列帧方向已单独成文，详细讨论见《论文-序列帧长动作生成》（`docs/论文-序列帧长动作生成.md`），以该文档为准。本节保留为摘要。第 1–8 节保留为背景，其中场景部分（第 6 节）转为后续论文素材。

**主线：先验证，再接续（Verify Before You Chain）。** 用黑盒的"首帧 + 文字 + 可选末帧"动画模型生成长动作时，误差会逐段累积；在段边界用真实帧证据验证、只从确认过的真实末帧继续，并在复核中保留矛盾，可以用有限的人工成本拦住累积误差。

- 生成器事实：PixelLab `/v2/animate-with-text-v3`，闭源；每段 4–16 帧，最多 4 段、64 帧；单次请求像素预算 524,288（128×128 时约 32 帧）。论文贡献只能在编排与验证，不在生成。
- 贡献候选：
  1. 问题刻画：黑盒首/末帧模型生成长动作时的失败类型（漂移、装备消失、接缝、目标姿势提前到达等），来自真实作业记录。
  2. 方法：合同驱动的分段规划 + 只从已确认真实末帧接续的检查点 + 基于合同的独立复核（保留矛盾）+ 窗口内局部修复。
  3. 评估：接续策略对比（一次生成 / 自动用末帧接续 / 先生成关键帧再插值 / 验证后接续）；复核与人工标注的一致性；人工成本。
- 不进主线：角色视觉结构解析与追踪（依赖 SAM，仅作可选观察器）、MCP 与网页界面、预算账本细节（一句话）、选帧修改（可作扩展）、Godot 导出。
- 最近相关工作：Sprite Sheet Diffusion（需要姿势序列）；Keyframe-Anchored Identity Preservation（2026，先生成关键帧链再填充）；EM-Vid（指出关键帧链会漂移）；Agent Sprite Forge（开源 Agent 技能，每个动作一次图生视频 + 联系表复核）；VLM 评审可靠性研究（"Is Your Video Language Model a Reliable Judge?"：简单聚合多位评审不提升可靠性；"Each Judge Its Own Yardstick"：把评审分歧当信号）。
- 待确认：是否接受此主线；是否加入第二个生成器（开源首/末帧视频模型）证明不依赖 PixelLab；Windows 机器上有多少带人工裁决的真实作业可用于回顾性分析。

## 1. 统一框架方向（已被第 0 节取代，保留作背景）

**一篇讲统一框架的论文，挑两个模块做实证。**

核心主张：图像模型只产出像素，游戏却要求这些像素满足一系列语义约束。Forge 在每个模块里把这些约束写成显式**合同**，用实际像素得到的**证据**去检查，再由**裁决规则**决定能否采用、能否作为下一步生成的输入。

- 实证选两个差异最大的模块：**序列帧**（时间上的一致）和**场景**（空间与物理上的一致）。其余模块在论文中用一张表说明同一框架如何覆盖它们。
- 长期目标：两个模块都有硬实验结果后，再整理成完整的系统论文，投期刊（如 IEEE Transactions on Games）。

## 3. 框架：三层

| 层 | 内容 | 是否为本文贡献 |
| --- | --- | --- |
| **合同** | 游戏语义的显式约束，例如"武器在各帧中持续存在""看起来能站的地方有碰撞""授权区外像素不变"；约束来自用户原话、参考观察或专家建议，并标注来源 | 是 |
| **观察器** | 从像素提取证据：Alpha、哈希、碰撞栅格、图层结构、SAM、视觉语言模型 | 大部分不是。SAM 2.1、视觉语言模型都是现成工具，论文明确注明，不作为贡献 |
| **裁决与绑定** | 证据如何变成决定，决定如何约束后续生成 | 是 |

裁决与绑定层的具体规则（各模块已实现）：

- 硬不变量与软判断分开：哈希、像素保护、版本检查一票否决；模型意见只能提出或保留问题。
- "未知"既不算通过，也不算失败。
- 独立专家指出的具体矛盾，不能被后续复核一票清除，保留待人工裁决。
- 生成只能从已确认的真实产物继续，例如序列帧下一段从上一段确认的真实末帧开始，地图扩图保留模板像素。
- 人工采用是最后一道门，技术检查失败不能人工放行。

关于观察器：

- 写成可插拔：同一合同可接 Alpha、图层结构、SAM 或人工标注。
- 论文中做替换实验，检验结论是否依赖某个观察器。
- 观察器出错时的处理（标未知、人工纠正、复核保留矛盾）属于裁决层设计，可以算作贡献。
- 论点之一：**在生成时就保留结构，比生成后再分割更可靠。** 场景实例可直接对比"分层图层产生候选"与"SAM 产生候选"。

## 5. 实例一：序列帧

现有链路（`Tools/SpritePipeline/sprite_pipeline/collaboration/`）：

- **开放动作**：用户描述任意动作，无预设、无按动作名称的分支。
- **多专家规划**：外观、动作专家先独立观察，策略专家与协调者综合，输出质量合同（关键姿势、支撑与发力、轨迹、物品归属、节奏等），每条要求标注来源。
- **分段制作**：最多 4 段，每段从上一段已确认的真实末帧继续，确认后存为不可变快照。
- **结构观察**：本地 SAM 加一次语义调用解析部件、锚点与关系；在实际帧上追踪，可纠正、可恢复。属于可选观察器。
- **独立复核**：两次基础检查 + 外观与运动两位独立专家 + 至多一次争议复核；矛盾保留规则见第 3 节。
- **选帧修改**：用户原话优先于专家建议；分别判断目标是否达成、未要求内容是否保持。

适合作为论文证据的点（实验设计待定）：

- 有无"真实末帧检查点"时，跨段漂移（装备、身份、朝向）差多少。
- "保留矛盾"规则拦下了多少被最终复核误判的缺陷，代价是多少人工裁决。

现有证据只有单样本或小样本开发验收，文档中已注明不是准确率或泛化证明。这些检查不依赖语义分割。

## 6. 实例二：场景的画面与碰撞一致性

### 6.1 定义

- **感知可站面 H**：玩家看画面认为角色能站上去的表面，以玩家标注为真值。
- **物理可站面 Γ**：碰撞体上表面中，上方有至少一个玩家身高空间的部分。
- 两者都按 x 方向每 4 像素采样；同列、高度差不超过 τ（暂定 6 像素）视为对上。
- **假地面**：画面像能站，实际没有碰撞（H 中对不上 Γ 的部分）。
- **幽灵地面**：有碰撞，画面却看不出能站（Γ 中对不上 H 的部分）。
- 均按长度加权；可达性只用来做加权，统计玩家能到达的区域里的错误。

### 6.2 画面候选从哪来

优先使用 Forge 自己保留的结构，SAM 只作备选观察器：

1. **分层制作的地图**：地图工具支持整体层、独立地表层、透明物件层。地表层即地表、物件层即物件，不需要分割。
2. **场景地图分层的结果**：`surface` 元素标为地表，`object` 元素待标注，`background` 不参与。
3. **只有一张平面图时**：用 SAM 分割（备选）。

候选的语义标签（"物件能不能站"）目前缺失，计划由视觉语言模型对编号候选做分类，模型只分类、不画坐标。

### 6.3 推断规则（已在原型实现）

- 稳健顶线：取一个窗口（5 列 × 6 行）内填充率首次达到 0.6 的位置，避开草叶等细碎像素。
- 只用画在玩家后方（`plane=back`）的美术片；前景片、背景元素不产生可站面；排序在玩家参考层之前的交互物排除。
- 头顶空间：碰撞侧所有实心都挡；画面侧只有已标为地表的部分挡。
- 人工碰撞与 Agent 碰撞使用同一数据结构、同一校验、同一编辑命令、同一锁规则，来源只作记录。

### 6.4 接缝

地图扩图时，相邻卡片被画进新卡片的模板，重叠区像素被逐像素保留，模型只填全透明处。所以**真正的接缝在新卡片内部"保留区与生成区"的分界线上**，这里最容易出现地面线错位。羽化会在内容不同的重叠区叠出半透明的双重地面线。推断直接用最终合成图；可选的接缝诊断沿分界线检查顶线是否连续。

### 6.5 移出主线的内容

- 修复闭环：可达性断开时规划新平台位置、生成物件并摆放、从新画面重新推断碰撞。列为未来工作。
- Godot 无头回放验证可达性：不作为贡献。
- 单向平台、危险区、斜坡、角色比例：第一版不处理。
- 状态相关的可供性（门开关）：作为扩展检查。

## 7. 已定决策汇总

| 议题 | 决定 |
| --- | --- |
| 发表方式 | 一篇统一框架论文，实证选序列帧与场景；完整系统论文作为长期目标 |
| 语义分割 | 不作为贡献；SAM 是可替换的观察器，论文明确注明 |
| 场景画面候选 | 优先用分层地图与场景分层结构，SAM 作备选 |
| 地图拼接 | 网页地图拼接工具的方式作为基准，不要求 Agent 具备拼接能力 |
| 人工与 Agent 碰撞 | 完全同等对待，来源只作记录 |
| 前景遮挡 | 前景片不产生可站面；被前景挡住的可站面单独统计为歧义 |
| 角色比例、坡度 | 不作为研究问题 |
| 状态相关的可供性 | 第一版只做静态地图 |
| 实验与测试设计 | 暂不讨论 |
| 原型实现方式 | 只读：推断、度量、可达性只输出报告，不改文档模型；纯函数模块，网页、MCP、批量脚本共用 |
| 代码位置 | 直接提交在 new-arch（提交 8a676e6），未推送 |

## 8. 原型现状

| 部分 | 位置 | 状态 |
| --- | --- | --- |
| 碰撞栅格化、物理可站面、画面稳健顶线、线段连接、一致性对比 | `features/scene-composer/affordance.mjs` | 已实现 |

| 测试 | `npm run test:affordance` | 通过 |

与当前方向相比的缺口：

- 尚未区分地图工具产出的地表层与物件层（目前透明地图层一律标为未标注）。需要确认这些层进入场景后如何保留身份。
- 物件候选没有语义标签，`all` 口径会把树冠等算作可站。
- 观察器还不是可插拔接口（目前固定为"场景分层或透明图层"）。
- 只在构造的测试场景上运行过；真实素材在用户的 Windows 机器上，届时再处理。
