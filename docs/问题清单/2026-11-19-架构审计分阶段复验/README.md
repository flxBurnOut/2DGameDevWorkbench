## 任务历史基准

以下是 macOS arm64、Node 25.8.1 的独立合成进程。每组用 `limit=20`。重建的 p50 / p95 来自 10 个各自新建数据目录的独立进程，p95 采用最近秩。热查询与 RSS 来自另一独立进程的 20 轮交替查询，期间另安排一次取图与原子替换并发。重建指缺少派生摘要，数据可能位于操作系统页缓存。RSS 为整个进程峰值，含夹具准备。读写字节为逻辑任务正文及摘要写入，不含磁盘元数据、归档名单或文件系统放大。

| 100 × 2 MiB | 0 | 143.6 / 218.2 ms | 0.6 / 0.7 ms | 0.8 ms | 0 B | 307 MiB |
| 1,000 × 128 KiB | 250 | 116.4 / 117.1 ms | 3.7 / 4.4 ms | 4.5 ms | 0 B | 160 MiB |
| 10,000 × 8 KiB | 5,000 | 404.1 / 499.9 ms | 24.1 / 25.1 ms | 24.6 ms | 0 B | 165 MiB |

100 × 2 MiB 的重建读取 209,733,380 B，生成 35,980 B 摘要。改一条再读只重读对应的 2,097,333 B。审计基线在同规格合成载荷的 since 查询中位数为 135.9 ms，两个实验的采样轮数不同。三组热测的事件循环延迟 p95 分别为 1.1、1.3 和 2.1 ms。10,000 条时仍要枚举文件、校验代次和排序。Node 的完整资产详情需要跨来源历史与覆盖信息；原生资产详情和单件预览可按身份定位。分段媒体耗时还包括解析 Job 与小型清单。生产延迟和研发成本没有可靠基线。

复验命令为 `node tests/task-isolation/benchmark.mjs 100 2048 0`、`node tests/task-isolation/benchmark.mjs 1000 128 25` 和 `node tests/task-isolation/benchmark.mjs 10000 8 50`。[基准实现](../../../tests/task-isolation/benchmark.mjs)

## 开发环境验证

从已提交源码在临时目录重新 `npm ci`，安装 495 个依赖，冷开发、生产构建、生产健康检查及首页通过。在独立 Python 3.13 环境执行真实 `--api-only` 安装及 `pip check`，从空数据目录启动 Uvicorn 并读取 `/health`；其 site-packages 约 86 MiB。工作机还执行了 Python 3.11 最低版本的全新安装。完整配置含 Gradio 的功能测试与无 Gradio 配置分开运行。本机最终完整 Python 回归含 PixelProp 和 SpritePipeline，894 项通过、1 项仅 Windows 适用的测试跳过，另有 57 项子测试通过。32 个 npm 测试入口逐组复验。实际引擎验收使用公开夹具和临时工程。外部制作服务以模拟提供方验证请求次数和用量。
