**DATA-06 · 稳定查询跳过摘要清理。** 进程记录最近一次无孤立项的源文件名集合和检查时间。首次读取、源文件名集合变化，或距离上次清点达到 60 秒时，再读取摘要目录。一次清点发现孤立项后，下次查询复查。这样既能及时发现已观察到的源删除，也能在后续查询中清理跨进程迟到的摘要。单条任务写进度会改写其摘要，但成员仍相同，适合沿用上次清点。删除前仍核对源文件缺失、摘要目录为真实目录且 dev/ino 一致。归档任务的摘要和在写临时文件保留。[清理实现](../../../lib/workbench/task-history-index.mjs) · [回归用例](../../../tests/task-isolation/history-index.mjs)

新进程命中有效摘要并清除前一进程的孤立摘要。定向回归对文件系统调用计数，稳定查询与已知任务写入检查点后的查询都对摘要目录执行 0 次 lstat、0 次 readdir，读取任务正文 0 字节，即使源目录的返回顺序发生变化也成立。可控时钟复验证明，另一进程迟到发布的摘要在 59,999 ms 时保留，60,000 ms 时进入清理。首次删除遇到模拟的 `EBUSY`，下一次查询即重试成功。目录链接和枚举后新建的任务也均通过保护用例。

**DATA-07 · 可复跑的跨进程压力测试。** 父进程按轮查询列表和执行归档预检，子进程持续原子替换同一任务。脚本分别记录总替换数、测量区间内的替换数和两类失败次数。覆盖不完整、预检被拒或整个测量区间没有成功替换，都会以非零状态退出。默认命令为 `node tests/task-isolation/history-stress.mjs 128 500 0`。三个参数分别控制载荷 KiB、轮数和目标时长（秒）。此项保留为手动压力测试，常规门禁继续用确定性故障用例验证相同竞争窗口。[压力脚本](../../../tests/task-isolation/history-stress.mjs) · [确定性回归](../../../tests/task-isolation/history-index.mjs) · [运行说明](../../../workbench/guides/development.md)

**EXP-03 · 工程自定义规则与写入失败。** Forge 精确匹配独立一行 `# Forge delivery locks`，能识别 LF、CRLF 和末行无换行。已有标记的文件保持原样。缺标记时原位追加规则，工程原有文件的权限和内容得到保留。无法读取、需要追加但不可写，或路径类型不合要求时，返回 HTTP 409 和 `INSTALL_LOCK_IGNORE_UNAVAILABLE`，同时给出具体原因、权限检查及“仅下载 ZIP”提示。此时停止交付并释放 SQLite 写锁，避免在忽略规则尚未确认时发布安装锁。已有标记且可读的只读文件可以正常使用。如果存储设备在写入标题后才报错，重试也会尊重已留下的标记，排障时应核对规则内容。21 项锁回归通过，包括原有 17 项以及新增的自定义规则、追加幂等、权限故障和非常规路径四组用例。真实 HTTP 与 MCP 入口均收到了错误码与提示。[锁实现](../../../lib/workbench/game-export.mjs) · [锁回归](../../../tests/game-export/install-lock.mjs) · [入口回归](../../../tests/game-export/run.mjs) · [交付契约](../../godot-delivery.md)

### DATA-06 同机耗时对照

同一台 macOS arm64，使用同一个 Node 25.8.1 可执行文件、同一份依赖和逐字节相同的基准脚本。执行 `node tests/task-isolation/benchmark.mjs 10000 8 50`，共 10,000 条、每条载荷 8 KiB，其中 5,000 条已归档，页大小 20。A 是干净的 `aeb9d38cda02`，B 是本次复核开始时的未提交修复，C 是最终工作区。三种版本在六轮中采用全部六种运行顺序，串行执行，共 18 个独立进程。每次新建临时数据目录并重建摘要，然后测量 20 次稳定轮询。计时期间未并行运行验证套件。[基准脚本](../../../tests/task-isolation/benchmark.mjs)

每格依次为稳定轮询 p50、p95 和首次重建耗时，单位均为毫秒。末行为各列六次结果的中位数。

| 轮次 | 运行顺序 | A · HEAD | B · 首版修复 | C · 复核后 |
| --- | --- | ---: | ---: | ---: |
| 1 | A → B → C | 24.0 / 25.1 / 405.9 | 26.5 / 27.6 / 408.6 | 23.9 / 24.3 / 401.4 |
| 2 | A → C → B | 24.0 / 24.5 / 403.2 | 26.5 / 27.2 / 416.8 | 24.1 / 24.3 / 402.0 |
| 3 | B → A → C | 24.0 / 24.4 / 403.5 | 26.2 / 27.0 / 402.3 | 23.8 / 24.0 / 411.6 |
| 4 | B → C → A | 24.0 / 24.9 / 400.3 | 26.4 / 26.9 / 403.0 | 23.8 / 24.5 / 404.5 |
| 5 | C → A → B | 23.9 / 24.6 / 405.0 | 26.5 / 27.3 / 401.8 | 24.0 / 24.8 / 404.2 |
| 6 | C → B → A | 23.9 / 24.7 / 409.7 | 26.4 / 27.8 / 437.1 | 23.9 / 24.3 / 401.4 |
| **中位数** | | 24.00 / 24.65 / 404.25 | 26.45 / 27.25 / 405.80 | 23.90 / 24.30 / 403.10 |

稳定轮询 p95 的六次中位数从首版的 27.25 ms 回到 24.30 ms，与 HEAD 的 24.65 ms 相差 0.35 ms。HEAD 六次 p95 的范围为 24.4–25.1 ms，最终实现为 24.0–24.8 ms，两组范围重叠。18 次稳定轮询基准均读取 0 字节任务正文，改单条后均只读取 1 个正文。此前记录的 32.5 ms 属于单次历史采样。
