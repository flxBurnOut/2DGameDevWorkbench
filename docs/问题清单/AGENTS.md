# 工程问题归档指引

## 目录结构

- [README.md](README.md) 只做索引：“当前问题”表每条一行，写编号、当前状态、一句话摘要和相关记录目录的链接；“记录索引”表每个记录目录一行，写时间、提交、涉及问题和一句话内容。不在索引中写现象细节、证据或验证过程。
- 每一批记录单独建目录，放在本目录下一层，按记录开始的日期和主题命名：`YYYY-MM-DD-主题/`，例如 `2026-11-17-示例素材生成工具问题/`。一批指同一次发现、审查、实施或复验，通常对应一个工作区基准或一个归档提交。同一天的不同批次分别建目录。
- 目录内的 `README.md` 是这批记录的正文，依次写：
  1. 元信息表：记录时间（带时区）、基准提交、归档提交、登记问题、跟进问题。
  2. 问题条目：本批首次登记的问题，写可观察现象与影响的工具环节、验证方法。
  3. 记录：发现、裁决、修复、复验的过程与证据链接。
  4. 本目录文档：长报告、方案或复盘，与 `README.md` 放在同一目录。
- 目录只收录适合随仓库共享的说明。原始回执、运行产物和私人数据仍按项目约定保存在本机，从正文链接或写明本机位置。

## 新增与更新

- 先在索引中按现象、影响环节和证据查重。同一问题沿用原编号，不重复登记。
- 新问题：新建本批记录目录，在目录 `README.md` 写问题条目，再在索引“当前问题”和“记录索引”各加一行。编号用主题前缀加两位序号，如 `UI-06`、`PLAN-01`；同前缀续号。
- 已有问题的后续裁决、修复或复验：在本次工作对应的记录目录中记录（新批次就新建目录），更新索引中该问题的状态，并在“记录”列追加新目录链接。原登记目录中的条目保留登记时的描述，不改写历史。
- 每次新增、裁决、修复或复验都记下问题编号、带时区的记录时间和 Git 提交编号。用 `git rev-parse --short=12 HEAD` 核对当前基准。涉及未提交工作时，注明“工作区基于该提交”及相关改动；正式提交或验证后，在同一目录追加实际编号与结果，并更新索引中的提交列。回填历史时标明使用的是提交时间，可用 `git show -s --format='%h %cI' <提交>` 核对。

## 内容要求

- 问题条目写清可观察现象、影响的工具环节、证据和验证方法。原因尚待定位时写明待查。
- 涉及生成模型时，记录工具如何处理输入、约束、证据和采用决定。生成器偶发的画面偏差可作为证据；只有它暴露出工具职责上的缺口，才登记工程问题。
- 关闭条目时写清验证了什么行为，附验证结果或证据，并保留最初登记和历次决定。历史报告中的结论保留其当时语境，当前状态以索引为准。

## 链接

- 记录目录比本目录深一层：仓库根目录的文件用 `../../../`，`docs/` 下的文档用 `../../`，另一个记录目录用 `../<目录名>/`。
- 移动或重命名记录目录时，同步更新索引、其他记录目录、`docs/` 中的入链，以及正文中的相对路径和章节锚点。
