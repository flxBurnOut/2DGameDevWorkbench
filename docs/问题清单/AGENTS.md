# 工程问题归档指引

## 目录结构

- **[README.md](README.md) 只做总索引**：分为 **待处理问题**（未完全闭环的活跃项，置顶）、**已关闭问题**（历史闭环项）和 **记录索引** 三张表。索引中只写编号、标准状态、一句话摘要和记录目录链接，不写现象细节或测试流水账。
- **受控状态词表**：总索引状态列统一使用五种值之一：`待处理`、`进行中`、`待实测`、`已关闭`、`暂不修改`。补充背景写在对应批次目录中，不在状态列堆长括号备注。
- **按批次建子目录**：每批记录单独建目录 `YYYY-MM-DD-主题/`（如 `2026-11-17-示例素材生成工具问题/`），对应同一次发现、审查、实施或复验；同一天不同批次分别建目录。
- **批次 `README.md` 最小结构**：
  1. 首行保留返回链接：`> 返回[问题清单索引](../README.md)。`
  2. 元信息表：记录时间（带时区）、基准提交、归档提交、登记问题、跟进问题。
  3. `## 问题条目`（固定 4 列：`编号 | 影响环节 | 登记现象 | 验证方法`；**纯跟进批次省略本节**）。
  4. `## 记录`：发现、裁决、修复与验证结论，附证据或代码链接。
  5. `## 本目录文档`：仅当目录内另有长报告、方案或复盘文件时列出；**无附属文档则省略本节**。
- 目录只收录适合随仓库共享的说明；原始回执、运行产物和私人数据留在本地忽略目录，正文写明路径即可。

## 新增与更新

- **查重与续号**：新增前先按现象和影响环节在索引查重。同一问题沿用原编号；新问题用主题前缀加两位序号（如 `UI-06`、`PLAN-01`、`PAPER-13`），并在索引前缀表补充新领域缩写。
- **保留历史记录**：已有问题的后续裁决、修复或复验记入新批次目录，同步更新总索引状态并追加记录链接；原登记目录中的原始现象描述保持不变，不事后覆盖。
- **时间与提交记录**：
  - 每次登记、修复或复验均记下带时区的时间与 Git 提交编号（`git rev-parse --short=12 HEAD`）。
  - 涉及未提交工作时标明“工作区基于该提交”；正式提交后在同目录补齐归档提交并同步总索引状态。
  - 回填历史记录时注明使用提交时间，可用 `git show -s --format='%h %cI' <提交>` 核对。

## 内容要求

- 问题条目用直白中文写清可观察现象、影响环节和验证方法（原因未定位时注明待查）；摘要统一描述问题本身或待办目标，不与状态列重复。
- 涉及生成模型时，记录工具如何处理输入、约束、证据与采用决定；仅当模型偏差暴露出工具职责缺口时登记为工程问题。
- 关闭条目时写明验证了什么行为及结果，当前状态以总索引为准。

## 链接维护

- 批次目录比本目录深一层：仓库根目录用 `../../../`，`docs/` 顶层文档用 `../../`，其他批次目录用 `../<目录名>/`。
- 移动或重命名批次目录时，同步更新总索引、其他批次、`docs/` 中的入链及章节锚点。
