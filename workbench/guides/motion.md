# 开放动作：从对象到交付

用于新动作、继续分段制作、检查或导出。精确输入以 `sprite-generator` 当前 schema 为准；模型配置、UI 与旧作业排错见[序列帧文档](../../docs/sprite-generator.md)。局部偏好修改转[选帧调整](../../docs/motion-adjustments.md)。

## 开始或继续

读取当前对象库存和已有作品。新动作使用 `plan-motion`，在 `motionSpec.description` 保留用户原话，按请求设置 ending、候选数与预算；需要已有对象 preset，不需要动作 preset。新请求使用 motionSpec.object_id / object_type，类型从库存读取；旧 character_id 保持可读。128 px 物品经[导入、转换或 PixelLab 生成后移送](../../docs/prop-art.md#导入与转换为动画原图)可选。交互物可在 `motionSpec.interactable_skeleton` 按顺序列出状态（首个为原图，最多 5 个）；规划必须每对相邻状态一段，段数不符由本机校验退回，骨架写入冻结方案。交互物合同核对视角、初态与部件归属。遇到带遮挡的刚体平移，只有用户明确选择尝试才在 generate-motion 传 allowUnsupportedMotion。review-motion-stage 的 accept_state 可先锁定真实状态帧，过渡仍待确认。用户授权默认制作时可使用已配置模型和当前默认预算，普通参数无需再次确认。规划本身调用模型；纯讨论只读取信息。

收到方案后处理真正未答的关键问题。`generate-motion` 绑定返回的 revision 与 planSha256；已授权连续制作可使用 autoExecute。追踪原 taskId 和 `?work=<openWorkId>`，换候选时保留精确版本与候选身份。

PixelLab 规划会先读取可用单位。可在 `motionSpec.budget` 设置 `max_frames_per_request` 和 `max_total_frames`，后者含所有候选，播放停留不计绘图帧。余额未知时仍遵守用户上限；就绪方案展示预计单位，提交前再次核对额度。

主评核对交互物时，仅外观描述差异按参考图写入合同，保留原话和处理依据，无需因此阻断或重做原图。影响运动、改变固定部件集合或要求裁决的差异在规划阶段处理。铰接和形变先选择已核对结构，每个部件按 ID 归入运动或固定清单；铰接另选固定部件上的可见轴点和运动端点。检查阶段结合实际帧、扣除运动遮挡后的固定区域像素变化及铰接半径。测量与模型意见冲突时，主评查看对应帧并记录裁决。

模型与预算随任务冻结，修改设置影响新任务。新任务通常使用增强复核：基础观察/审核、外观与运动独立意见，有争议再一次复核；每段及整段最多五次。基础协议最多两次。额度从当前 schema 和方案读取，修复后的复查计入原任务账本。旧任务沿用已保存协议。

涉及结构辅助、时序观察或规划稳定性时，读取[视觉结构协议](../../docs/visual-structures.md)：策略分析草案与可执行方案分开，预留后续专家预算；实际绘图文本不截断。结构确认不是画面采用或修改区域授权。遮挡、透视缩短与外观断裂保留不确定性及具体矛盾，不能凭单次模型意见自动通过、重绘或升级旧任务。

只有 GPT Image 物品图时，先 `reference-art convert-prop`，查看 compare.png，核对视角、初始状态、部件完整和透明背景，再 `transfer` 附 `confirmation.note`。用户已明确委托检查时 Agent 可直接提交实际观察；未委托或保留选择时，用 `workbench_present` 展示对比图等待确认。选参数属于本机可重做的常规选择；多张源图而用户未指定时先确定来源。导入/转换的 PixelLab 动画效果未经真实验证，后续规划与绘图仍需各自费用授权。对象清单与新作品的 character.provenance 保留来源摘要，实验统计按来源筛选。

## 网页入口

需要用户在网页上操作或查看时：交互物动画在“交互物动画”面板 `/tools/interactable-motion` 制作，`object_type=interactable` 的作品默认在此打开（`?work=<openWorkId>`，可带 `&document=<id>&definition=<definitionId>` 指明写回物件）；角色动画页的对象列表只含角色。面板左侧为状态图，中间为过渡画布，右侧“要求 / 检查 / 工具 / 写回”。没有 128 px 物品原图时可在面板内生成、导入或转换并移送；交互物编辑器中切换与序列物件的“制作状态动画”会保存工程并带上下文打开面板。写回页签逐槽显示当前绑定，并只通过 `import-motion-asset` 提交；编辑器“素材 → 导入位置”仍可直接选用。用 `workbench_present` 打开准确页面，`workbench_get_motion_bindings` 只读查询各槽绑定。面板说明见[方案与实施记录](../../docs/交互物动画独立面板方案.md)。

写回可带 `durations`（逐帧相对时长，数量等于过渡帧数）与 `playback: ping_pong`；这只改变交互物动画片段，原帧和导出不变。面板的确定性工具（固定部件回填、对齐、批量清理、同帧数旋转草稿）经 `local-frame-edits` 保存为完整播放备选，仍须对比后采用。倒放、旋转草稿、色调派生和上传的状态图属于派生素材：记录来源与哈希，必须人工播放并写明结论接受后才进入资产库，目前只在网页面板创建。

## 分段与完整检查

出现 pendingCheckpoints 时，用 `get-motion-stage` 读取准确候选和零基 stage 的全序列。以实际 FPS 检查运动、末姿势、装备和接缝，再用原 token/revision 调 `review-motion-stage`，填写接受或拒绝及实际观察依据。用户已委托 Agent 检查时可直接裁决；用户保留选择时展示需要决定的画面。

接受的真实末帧作为下一段输入。拒绝保留当前结果；根据用户目标、可用修复范围和授权决定下一步。模型通过只提供证据，不取代主 Agent 或用户的实际观察。最终仍检查组装后的完整动作。

交互物多状态作业每段对应一次过渡。用 `get-motion` 查看候选的 `state_chain`，首项为参考原图，后续各项记录可见状态、来源段、帧索引和 PNG 哈希。`get-motion-stage` 返回本段的 `transition` 和已确认的 `state_image`；其 `frame` 从零计并排除输入参考，`raw_index` 从零计并包含提供方返回的上下文帧。单独确认状态图后仍须裁决过渡。若随后拒绝，已单独确认的图保留，过渡状态标为 `rejected`，后段停止。直接接受整段也会登记选中帧。网页的候选「状态图」可查看同一来源。

符合目标的姿势若早于越界尾段，可在检查完整源序列后显式选择 anchorFrame 和 acknowledgeTrim，记录原因；省略就保留全段。播放映射记录选中的真实帧，原始字节继续保留。制作前已有合适目标 PNG 时可用 target-motion-stage 绑定，输出端点仍采用真实生成帧。

## 调整与恢复

用户偏好也是有效调整目标。用 get-motion-adjustment 读取当前可编辑范围，按已明确的范围与额度创建备选；不要让专家建议覆盖用户原话。已开始后段依赖的锚点、跨段范围和当前不支持的帧数由接口拒绝。完成后检查原版、备选全序列及两侧衔接，再提交采用或保留原版的决定。完整候选采用产生新版本；片段采用仍要完成该片段确认。

旧 repair-motion-stage 任务继续通过其原 attempt/token 读取和处理。新修改使用统一的备选流程。图像范围、参考、帧序、FPS 和版本绑定保持到采用；改变来源后重新读取上下文。

查询和刷新继续原任务。提交未知或中断先查已有回执和远端 ID；用 recover / attach-provider-job 处理可恢复作业。避免以新请求重复未知付费提交。已知失败则依据原因和现有授权修复；新增费用、范围或候选超出原委托时再询问。

## 采用和导出

实际检查后用 reviewNote 记录结论，并只确认已评估的提醒。技术硬错误需要先处理。获授权的主 Agent 可采用与导出；只有模型报告或文件存在不能据此填写已看图。

采用后导出准确候选。当前包可提供 PNG、预览、配方/QA 和单动作 Godot SpriteFrames 包；历史导出可能没有 Godot 包。需要补包时走已有候选的导出流程，复用已完成的检查。

原始帧和交付映射分别保留，输出 FPS、loop 和实际帧数以最终配方为准。接入游戏读取[工程 Skill](../../.agents/skills/forge-game-engineering/SKILL.md)，保留其他动作及目标控制器行为。
